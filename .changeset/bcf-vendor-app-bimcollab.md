BCF server sign-in: let a deployment sign its users in through its own vendor-registered OAuth app, so BIMcollab users never see a Client ID field (#3900). BIMcollab issues client ids to application developers only — a space administrator cannot obtain one, and its IdentityServer refuses the password and client-credentials grants for such a client — so the previous form, which asked BIMcollab users to "register an OAuth application with the vendor", sent them after something they could never get. The viewer now reads `VITE_BCF_APP_<PRESET>_CLIENT_ID` / `_CLIENT_SECRET` / `_REDIRECT_URI` per preset at build time; with an app configured the BIMcollab preset hides the client-id and secret fields, sends the app's credentials and its registered redirect URI (BIMcollab's playground client is pinned to `http://localhost:5000/Callback`, which the dev server now routes to the callback page) and keeps them for the refresh grant. A redirect URI on another origin is refused before any network work, since the callback page reports back over an origin-scoped BroadcastChannel. Without an app, the form says which vendor issues the ids instead of the generic registration advice.
