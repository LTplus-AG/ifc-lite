Add `ifc-lite schedule <file.ifc> --type <IfcClass> --columns "<Header>=<path>[, ...]" [--where <expr>] [--format csv|json]`: a tabular schedule of one IFC class, one row per entity.

Each column is a `Header=path` pair (a bare `path` is its own header); `path` is a plain attribute name (`Name`, `Tag`, `GlobalId`, …), a `PsetName.PropName`, or a `QtoName.QtyName`. Property/quantity paths resolve through the same shared resolver `export` uses (so schedule columns inherit its type-inheritance / same-named-pset / complex-property behaviour), plain attribute names read from the canonical entity-attribute list, and `--where` reuses the exact filter `query` applies. CSV output routes every cell through the shared RFC-4180 escaper (formula-injection guard included); a missing value is an empty CSV cell / JSON `null`.

Grouping, sorting and subtotals: `--sort "<Header>[:asc|desc][, ...]"` stably sorts rows by column HEADER (numeric when both cells parse as numbers, else string; missing values sort last, original entity order the tiebreaker); `--group-by "<Header>[, ...]"` orders rows so each group is contiguous (group key order ascending, or the `--sort` direction when the group header is also a sort key); `--subtotals "<agg>[, ...]"` with `agg` ∈ `count | sum:<Header> | avg:<Header> | min:<Header> | max:<Header>` emits a subtotal row after each group and a grand-total row (without `--group-by`, just the grand total). The numeric reduction reuses the same `Number.isFinite`-guarded aggregator behind `query`'s `--sum/--avg/--min/--max`, so an `Infinity`/`NaN` value cannot poison a subtotal. In CSV a subtotal row leaves non-aggregated columns blank and labels the group column (e.g. `Subtotal (Fire=REI60)`, suffixed `: <n>` when `count` is requested); in JSON it is an object carrying a `__row: "subtotal" | "total"` marker plus the group and aggregated fields. A `--sort`/`--group-by`/`--subtotals` header that is not among `--columns` is a fatal error listing the valid headers.
