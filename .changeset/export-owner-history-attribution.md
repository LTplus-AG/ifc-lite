Rust only, in `ifc-lite-export`. Export plans attribute changes to the exporting application as buildingSMART describes for IfcChangeActionEnum. Objects a plan adds get an `ADDED` owner history owned by that application. Records it changes get a `MODIFIED` history that keeps the original owner and creation date and names the application as last modifier. What counts as changed is the plan's own scope: every object it patches, every rewritten record that carries an owner history (relationships, property and quantity sets, types), and the set holding a value it edits in place. Other rewritten records (materials, shapes, placements) are not attributed separately. Untouched records stay byte-identical. The STEP header writes `originating_system` in buildingSMART's header-agreement form, `Company - Application - Version`, from the application's fields as given (an application that doesn't fit the form is never refused; the entry points that return findings report it), `ifc-lite <version>` as `preprocessor_version`, and the change time in UTC. For existing callers: a plan that changes attributable records without an application gets a finding (output bytes unchanged), a patch that writes nothing is refused ("patch changes nothing"), and `WriteReport.patched` counts only patches that wrote something.
