Rust only, in `ifc-lite-export`; nothing in the wasm package changes. The export plan's public structs and enums (`plan::NewObject`, `NewType`, `Extrusion`, `Patch`, `PropWrite`, `ExportPlan`, `Disposition`, `Representation`, the material and classification types, `Skeleton` and the rest) are now `#[non_exhaustive]`, so a field or variant added later is not a breaking change. Outside the crate, build a struct with its `new` constructor and finish it with the `with_*` setters or by assigning its public fields (`NewObject::new(id, IfcClass::Wall, NewPlacement::new(plan::IDENTITY)).with_container(storey)`); match the enums with a wildcard arm. The struct-like variants `PropertyValue::Measure` and `ValueUnit::Si` are `#[non_exhaustive]` too: build them with `PropertyValue::measure`, `ValueUnit::si` or `ValueUnit::si_prefixed`, and match their fields with `..`. `PropScope`, `PsetKind` and `GlobalId` are unchanged. `Refusal`, `ValidationFinding` and `DroppedRepresentation` have `new` constructors, so a caller can build the values it compares a report against. Output is byte-identical. This breaks the Rust API, so `rust-major-offset.json` records it as Rust-only break #12 and the crates publish at 22.x; the npm packages change nothing.
