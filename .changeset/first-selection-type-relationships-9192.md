Selecting an element on a large model no longer reads every typing relationship from the source on the way to the Properties panel (#9192). `readCurrentTypeQuantities` now takes them from the parsed relationship graph, and reads a relationship's record only when an edit touched it, the parser recorded no edge for it, an edge of it has the wrong class on its relating side (a record the byte reader misread, or a definition set naming a non-definition), or it names the element or type being read. One more case is read only when it decides the answer: a definition relationship that an edit over-counts (it names a definition the edit removed) is read when that bound would cross the reference budget. Answers are unchanged, with one narrowing: a relationship whose list holds both valid references and unreadable values, and whose every element and definition the parsed graph lists (such as `(#10,'x',#14)`), now refuses only the elements and types it names, rather than every read in the file. A record the byte reader misread (a nested or typed value, as in `((#10),#14)`, shifts the rest of the list into the relating slot) is read up front and refuses the whole model, as before. A refused record found on lookup to name anything the graph does not list also refuses the whole model from that read on. A refusal now holds for the edit revision like an answer does (model-wide, per relationship and per type), instead of being worked out again on every click.
