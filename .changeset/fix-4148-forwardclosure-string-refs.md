Fix `extract-entities` reading an `#`-prefixed number out of a product's or storey's free-text Name/Description as if it were an object reference, when it happens to match a real expressId in the file. This produced two failure modes: `forwardClosure` over-extracted (e.g. `'Chair pairs with #71'` pulled entity 71 and its closure into a selection that never named it); and, for `--storey`, `resolveStoreyPlacement` and `productsUnderPlacement` could pick a silently WRONG subset — a storey Description naming another storey's real placement (`'duplicate of #99'`) made the extraction resolve to that placement instead of the storey's own, and a product Name naming a placement id could seed it into the wrong storey's extraction. All three sites now walk each record with the same string-aware `refsOutsideStrings` `subset-relations.ts` already uses for relation members, so an id mentioned only inside free text is no longer treated as a reference. The voids/fills fixpoint loop's own `REF_RE` scan was reviewed and left as is — it reads only the last N reference slots of a known relation shape, positionally unaffected by an earlier free-text `#id`.
