New package `@ifc-lite/georef-check` says what is wrong with a model's georeferencing and how to fix it. `diagnoseGeoreference(facts, { reprojector?, crsCatalog? })` is a pure function that returns the Levels of Georeferencing found (LoGeoRef 10 to 50, per the published definition) with stricter notions kept as separate `indicators`, and a list of findings. Each finding has a stable code, a severity, a one-sentence explanation, the numbers it is based on, and structured fixes: each change names a real entity instance and EXPRESS attribute, and each fix says how it can be applied (one `bim.georef.update`, one grouped `bim.georef.set` with the values only the user can supply marked, or manual with the reason). It covers the map position applied twice (by the site placement or by the geometry), Scale and unit slips, a UTM zone number in front of the Easting, LV03 numbers in an LV95 model, positions outside the CRS's area, authoring-tool default site locations, site latitude/longitude that contradicts the map conversion (naming which side is suspect), a CRS with no map conversion, a missing or unresolvable CRS, a missing MapUnit or vertical datum, invalid rotations, sources that disagree, and IFC2X3 without the ePSet convention. `collectGeorefFacts(store)` reads the facts from a parsed `IfcDataStore` without meshing, measuring IfcCartesianPoint and point-list coordinates separately and reading each point list through a bounded prefix. The injected `Reprojector` takes metres and returns `[longitude, latitude]`; `crsRequirements(facts)` lists the CRSs to resolve before diagnosing, so an asynchronous resolver can feed it.

`@ifc-lite/parser` adds `extractGeoreferenceCandidates` and `extractGeoreferenceCandidatesOnDemand`. They return every georeferencing source in a file (IFC4 entities, `ePSet_MapConversion`, the IfcSite reference point, every IfcMapConversion with its own TargetCRS) instead of only the one that wins. `extractGeoreferencing` and `extractGeoreferencingOnDemand` are unchanged.
