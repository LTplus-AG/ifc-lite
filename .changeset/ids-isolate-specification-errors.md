One specification that throws no longer ends the whole `validateIDS` run (#7482). Only a rejected `xs:pattern` (`UnsafeRegexPatternError`) used to be caught per specification; any other error rejected the run and discarded every other specification's verdict. Now an error from evaluating a specification fails that specification with `error: "Specification could not be evaluated: <reason>"`, as a rejected pattern always did (a thrown value that cannot be converted to text, such as `Object.create(null)`, is named by its kind, so formatting the reason can never end the run), and the other specifications are reported, as `runRuleSet` in `@ifc-lite/rules` already does. A host's cancellation (anything thrown with the name `AbortError`, including an object or function abort reason from `signal.throwIfAborted()`) and an exception thrown by the host's own `onProgress` callback end the run, so a host callback failure is never reported as a specification verdict. One callback case changes: on the previous release, an `UnsafeRegexPatternError` thrown by the host's own `onProgress` while a specification validated was caught as that specification's evaluation error (the catch tested only the class, not where the error came from), so each specification it reached was reported as failed with the host's message and the run went on; it now ends the run with the original exception, like any other callback exception. A genuinely rejected IDS pattern still fails only its own specification. The applicability property index that the specifications of a run share now marks an entity as indexed only once its property sets are folded in, so an entity whose sets could not be read is not silently left out of a later specification. A specification with `error` set is an evaluation error, not a `fail` verdict: the buildingSMART corpus, preview, writer round-trip and IfcTester parity tests, the conformance and AI-eval scorers, and `ifc-lite delivery` (whose IDS check now reports `error`, with `erroredSpecifications` and the reasons, as its rules check already does) all treat it so.
