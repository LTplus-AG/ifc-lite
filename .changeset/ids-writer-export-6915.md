Export `writeIdsXml`, the IDS 1.0 writer behind `ruleSetToIds`, and extend it (#6915): property `dataType`, `partOf` facets (upper-case XSD relation token, related entity required) and requirement `instructions` are now written. String-length and digit restrictions (`xs:length` / `xs:minLength` / `xs:maxLength` / `xs:totalDigits` / `xs:fractionDigits`) and conjunctive restrictions (a pattern, enumeration and bounds in one `xs:restriction`) are written; bounds on `xs:decimal` and the integer bases are written without an exponent. Constraint parts it has no XML for (unparseable bounds, two patterns or two enumerations that one restriction would OR, siblings with different bases, a bounds restriction without any facet) are refused with an error instead of being written as a weaker check. Line breaks and tabs in attribute values (such as multi-line `instructions`) are written as character references so they read back unchanged, and a control character XML 1.0 cannot carry is refused with the element or attribute it is in. Every pass/fail case of the vendored buildingSMART IDS corpus (all 307) reads back with the same specifications and gives the same verdict.
