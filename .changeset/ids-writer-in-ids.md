Export `writeIdsXml`, the IDS 1.0 writer (moved here from `@ifc-lite/rules`, ADR-005; #6915). It writes property `dataType`, `partOf` facets (upper-case XSD relation token, related entity required), requirement `instructions` and every constraint shape the parser produces: string-length and digit restrictions (`xs:length` / `xs:minLength` / `xs:maxLength` / `xs:totalDigits` / `xs:fractionDigits`) and conjunctive restrictions (a pattern, enumeration and bounds in one `xs:restriction`); bounds on `xs:decimal` and the integer bases are written without an exponent. Constraint parts with no valid IDS 1.0 form (unparseable bounds, two patterns or two enumerations that one restriction would OR, siblings with different bases, a bounds restriction without any facet) are refused with an error instead of being written as a weaker check. Line breaks and tabs in attribute values (such as multi-line `instructions`) are written as character references so they read back unchanged, and a control character XML 1.0 cannot carry is refused with the element or attribute it is in. Every pass/fail case of the vendored buildingSMART IDS corpus (all 307) reads back with the same specifications and gives the same verdict.
