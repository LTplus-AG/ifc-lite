IFCX models are read the way the equivalent IFC is. The window type in `hello-wall.ifcx` (a node of class `IfcWindow` that the windows inherit as `windowType`) becomes an `IfcWindowType` related to its windows by `DefinesByType`, so it is no longer a third window on no storey. The class-less material nodes the wall and the window type inherit as `material` become `IfcMaterial` rows named by their `bsi::ifc::material` code, related by `AssociatesMaterial`. `ComposedNode.inherits` keeps the reference composition used to forget. An occurrence is named by its own `Name`, then by the edge it hangs under, and only then by its type's `TypeName`; the converter's `_001` uniqueness suffix is dropped only when the unsuffixed sibling edge exists. The entity table and the spatial tree now share one name lookup, so a space is named alike in both. A storey's spaces are mapped to the storey in `elementToStorey`, and a storey with no `Elevation` takes the Z of its placement chain, as the STEP builder does. The parse result carries `lengthUnitScale` (new export `IFCX_LENGTH_UNIT_SCALE`, 1: IFCX declares no unit and this reader applies no scale, so metres is an assumption stated in one place) and `derivedEntities` (the rows the reader derived, so the writer emits the file's own class for the window type and nothing for the added materials).
