**diff**: add **lineage** (issue #4955) — the 1:k artifact an external data owner rekeys on when identity is not enough. `lineageFromDiff` derives `{ base[], head[], relation, reason, shares? }` entries from a diff: `identity` from committed content matches and from the aliases the run was given (carried forward so a replayed lineage does not erode), `split`/`merge` from split/merge claims with per-piece volume shares where every piece was measured, and `replaced` from successor claims passed in as ACCEPTED, never from the engine's own suggestions. `rekeyByLineage` answers where each old key's row goes under `copy-to-all`, `largest-share` (orphaning rather than guessing without shares or on a tie) or `orphan-on-split`; `keyAliasesFromLineage` replays the 1:1 entries as `keyAliases`. The `ifc-lite/lineage` sidecar (`createLineageSidecar` / `serializeLineageSidecar` / `parseLineageSidecar` / `validateLineageSidecar` / `lineageSidecarMismatches`) pins both model digests like the identity map does, and refuses a document in which any key appears in two entries on one side. Both sidecars gain an optional `keyProperty` (absent = GlobalId, so existing files stay valid) and their mismatch checks report a key-scheme mismatch like a digest mismatch. `ModelIdentity` moved to a shared module and is re-exported unchanged.
