Add `ifc-lite-mcp --bridge`: a stdio MCP server that forwards tool calls over a loopback WebSocket (`127.0.0.1`, default port 21517, `--bridge-port` to change) to one paired ifc-lite browser tab, so a local agent can work on the model open there. It loads no model of its own. Pairing uses a one-time code shown by the new always-listed `bridge_status` tool and on stderr, with the port and code in the link's URL fragment. The upgrade is refused unless the Origin is allowlisted (`https://ifclite.com`, the `--bridge-viewer-url` origin, and `--allow-origin`) and the Host is loopback. Each tab tool carries a `readOnly` flag: mutating tools are hidden and refused while the tab grants read-only access or the bridge runs `--read-only`, and tools are listed with MCP `annotations` (`readOnlyHint`, `destructiveHint`) and an optional `title`. The transport-neutral frame protocol is exported, browser-safe, as `@ifc-lite/mcp/bridge-protocol`. `MCPServer` takes an optional `instructions` string, `Tool`/`ToolDefinition` take optional `title` and `annotations` (new `ToolAnnotations` type), and `ToolErrorCode` gains `VIEWER_NOT_CONNECTED` and `TIMEOUT`. The browser side ships separately.
