"@ifc-lite/mcp": minor

The MCP HTTP transport now bounds its session table. `initialize` was the only request that created a session and only `DELETE` removed one, so a client that never ended its sessions grew the table, and the server and layer workspace behind each entry, without limit. New `HttpTransportOptions.maxSessions` (default 1000) refuses further `initialize` calls with 503 `session-capacity`. At that cap, only as many sessions as the new one needs are reclaimed: those with no request for `sessionIdleMs` (default 30 minutes), nothing in flight and no open SSE stream, oldest first and sessions with no unpublished layer drafts before sessions that hold some. Reclaiming disposes a session's unpublished layer drafts as `DELETE` does, and logs a warning naming the session. A request that names a session the server no longer holds (ended by `DELETE`, reclaimed, or never issued) now gets the MCP spec's 404 `unknown-session`, with a body saying it may have been ended while idle at the session limit and to send `initialize` again; it used to get 400 `Mcp-Session-Id required` on `POST` and a plain-text 404 on `GET`.
