---
"@ifc-lite/mcp": minor
---

The MCP HTTP transport now bounds its session table. `initialize` was the only request that created a session and only `DELETE` removed one, so a client that never ended its sessions grew the table, and the server and layer workspace behind each entry, without limit. New `HttpTransportOptions.maxSessions` (default 1000) caps live sessions plus sessions still being built. At the cap, one session is ended to make room only if it has been inactive for `sessionIdleMs` (default 30 minutes), holds no unpublished layer drafts, has no request in flight and has no open SSE stream; the idle window restarts when a request settles or a stream closes. A session holding unpublished drafts is never ended for another client, however long it has been inactive. When no session qualifies, `initialize` is refused with 503 and a JSON body `{"error":"session-capacity","message":...}`, and nothing is ended. A request naming a session the server no longer holds (ended by `DELETE`, reclaimed, or never issued) now gets the MCP spec's 404 with a JSON body `{"error":"unknown-session","message":...}` telling the client to send `initialize` again; it used to get 400 `Mcp-Session-Id required` on `POST` and a plain-text 404 on `GET`. A `GET` with no `Mcp-Session-Id` header now gets 400 `Mcp-Session-Id required`, as `POST` does, instead of a plain-text 404.
