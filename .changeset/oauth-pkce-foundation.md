Add `@ifc-lite/oauth-pkce`: browser OAuth 2.0 Authorization Code + PKCE (RFC 7636) for a public client (no client secret). Provides PKCE code_verifier/code_challenge generation via Web Crypto, authorization-URL construction with CSRF `state` validation and redirect-origin validation, authorization-code and refresh-token exchange, and a `TokenManager` that persists tokens behind a caller-supplied storage interface and de-duplicates concurrent refreshes onto a single in-flight request.

This is shared plumbing for upcoming OAuth-based file-source providers (Google Drive, Dropbox, SharePoint/OneDrive); it does not implement or register any provider itself.

`@ifc-lite/oauth-pkce` 0.1.0 was published manually to establish the package and its OIDC trusted publisher, so this release is 0.2.0. Relative to 0.1.0 it:

- Fixes two races in `TokenManager` where `clear()` or `setTokens()` landing while `getValidAccessToken()` was still reading storage was not seen by that call. The session identity a refresh checks itself against is now captured before the storage read rather than after it, so a sign-out or a new sign-in that lands during the read disarms the refresh instead of being adopted by it. Previously, `clear()` during that window left a freshly refreshed token set written back under the key the user had just signed out of (and handed its caller a live access token), and a new sign-in during that window could be overwritten by the previous session's refresh.
- Corrects the `AuthorizationRequestConfig.extraParams` docstring (the extras are applied *first* and then overwritten by the protocol parameters — the previous "Applied last" described the opposite mechanism) **and** closes the one gap in the override protection it promised: `scope` is the only protocol parameter whose write is conditional (`if (config.scope)`), so with `config.scope` unset or empty an `extraParams.scope` was not overwritten and *was* sent. A `scope` entry in `extraParams` is now dropped outright, so the documented "an extra can never decide a protocol parameter" holds without exception.
- Makes `requestToken` validate the optional fields of a token response instead of copying them through untyped. A provider sending a non-string `refresh_token` previously produced a stored entry that `TokenManager`'s own shape guard rejected on read, so a *successful* sign-in read back as "never signed in" with nothing naming the cause; it is now reported as a `TokenExchangeError` at the exchange. Non-string `scope`/`token_type` are dropped rather than failing the sign-in, since nothing reads them.
- Bounds and strips provider-supplied `error`/`error_description` text before interpolating it into an error message, on both the authorization-callback and token-endpoint paths. That text is attacker-reachable with no valid `state` required, and was previously copied verbatim — unbounded length, newlines and terminal escape sequences included — into messages that land in logs and bug reports.
- Makes `TokenManager` validate the shape of a persisted token entry before using it, so a corrupt or truncated entry is reported as "no session" instead of producing an `Authorization: Bearer undefined` request. A whitespace-only access token now also counts as unusable rather than producing `Authorization: Bearer    `.
- Rejects a non-integer `byteLength` in `generateCodeVerifier`. `NaN` passed the previous range check (both comparisons against `NaN` are false) and `new Uint8Array(NaN)` is empty, so it silently produced an empty `code_verifier`.
- Drops `base64UrlEncode` from the public entry point. It is an internal helper behind the PKCE primitives, not part of any OAuth contract, and it is cheaper to remove it before 0.2.0 than to keep it working forever.
