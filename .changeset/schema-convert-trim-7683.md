STEP export with a schema change (`exportStep` with a target schema, `ifc-lite export --format step --schema …`) now trims or pads every entity whose attribute list one schema only appended to, in both directions, reading the attribute lists from the EXPRESS registry instead of a 30-type hand table (#7683). An IFC4 or IFC4X3 model written as IFC2X3 no longer keeps the IFC4-only `Formula` on every `IfcQuantity*`, `Description`/`Category` on `IfcMaterial`, or the IFC4 tails of `IfcMaterialLayer`, `IfcMaterialLayerSet(Usage)`, `IfcTextStyle`, `IfcCurveStyle` and the door/window lining properties, so those records match the IFC2X3 schema the header declares. An IFC2X3 model upgraded to IFC4 drops `ControlElementId` from `IfcDistributionControlElement`, which IFC4 removed. IfcAlignment, IfcReferent, IfcLinearElement, IfcPositioningElement and IfcLinearPositioningElement downgraded below IFC4X3 now become a full 9-attribute `IFCPROXY`, like the other alignment entities, instead of an 8-attribute one carrying the alignment's enum.
