`HeadlessBackendOptions.guidRandom` (also `openModel(bytes, { backend: { guidRandom } })`) seeds every GlobalId a headless session authors, so the same model, edits and seed export the same IFC `DATA` section. `@ifc-lite/create` already took a seeded `SpatialAnchor.guidRandom`, but the SDK never passed one: it now rides on the model resolution (`CostStoreModelResolution.guidRandom`) into every anchor the store backends resolve, into copy, duplicate, array, mirror, split, classification, room create and edit, roof, storey add and storey delete, the structural relationship operations and structural derivation, and into the property sets `export.ifc()` writes. The create operations that resolved their own anchor or wrote GlobalIds without one (`addHostedElementInStore`, `addStoreyInStore`, `applyStoreyDelete`, `reassignElementsToStoreyInStore`, `mirrorElementsInStore`, `copyToStoreysInStore`, `addClassificationInStore`, `assignClassificationInStore`, `createRoomsInStore`, `syncRoomLayoutInStore`, `editFootprintRoofInStore`) take a trailing optional `AuthoringGuidOptions`, `ElementSplitOptions` takes `guidRandom`, `CopyBatchOptions` takes `guidRandom` beside `duplicate`, so a seeded copy, array or storey copy keeps the source Name and only an explicit `duplicate` renames it, and `GroupStoreContext` takes `guidRandom`. Omitting it keeps the platform CSPRNG.
