Orbiting with a large selection is no longer slow (#9835). The highlight of a selection used to be one GPU mesh per selected piece, each with its own uniform write and three draws on every frame, and every frame also rebuilt the selected-id set and looked up each selected entity's pieces. Selecting all 16,916 elements of a 326 MB model took a frame from 4 ms to over 400 ms of renderer time. A selection whose highlight copies would pass the 500-piece pick budget now pools into one merged mesh per colour and model (the per-entity merge of #9192, across entities), and the renderer keeps the selection's highlight meshes between frames, redoing them only when the selection, hide/isolate, the model or item scope, or the scene's geometry changes. The highlight itself is drawn from the same vertices by the same pipeline as before. `RenderOptions.selectedIds` is no longer walked whole on every frame: a new Set, a Set that grew or shrank, and any in-place edit of up to 4,096 ids are seen on the next frame as before, while swapping ids in place at the same count in a larger Set is seen within a few frames, so pass a new Set for a large selection.
