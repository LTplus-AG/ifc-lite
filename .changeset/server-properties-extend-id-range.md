Server properties arriving after geometry now extend the model's published ID range in place, so non-meshed entities above the mesh maximum resolve correctly. Offsets never move and the exported `ModelRange` shape is unchanged. A later reservation clamps source growth to the model's overlay headroom: IDs beyond that bound remain unresolvable, are reported, and block authoring. Properties loading and initial failure also block authoring.

`MutablePropertyView.getCreatedExpressIdBounds(ceiling)` counts only overlay-created IDs: live, created-then-deleted and stashed/undoable creations. Source deletions and source-only allocator floors never block hydration. Pass `.highest` (at or below the requested source maximum) and `.lowest` (across all creations) as the third and fourth arguments to `FederationRegistry.extendModel`. A higher creation cannot hide a lower collision. The registry refuses source growth across creation claims, partly published ranges and published overlay ownership. If retained creations are above the new source maximum, it publishes any preceding gap as reserved-unused ownership in the same notification as source growth. For source max 990 and retained IDs 1001..1005, ownership grows through 1000; creations remain unpublished until requested, then publish contiguously. The ownership bound includes the gap, whose IDs cannot be allocated again. Gap reservation refuses atomically if the first retained ID exceeds overlay headroom or the safe global ID limit.

A refused re-hydration keeps the existing properties and edits. It restores a settled previous run (idle, succeeded or failed) directly in one commit; a cancelled or ownerless running previous run becomes succeeded-equivalent because the existing store is loaded. There is no transient failed or idle run. Only a refusal without an existing store fails the properties run. The activity tray records the refusal and its detail as failed, never completed.

Allocation permissions use the allocator's actual next ID and batch size, allowing earlier unpublished creations without locking editing. Registry publication and preview own validation: oversized contiguous batches throw `OverlayIdSpaceExhaustedError` (`id-space-exhausted`), with contiguity errors first. All reservations cap allocations at overlay headroom and the global safe ID limit. Allocating viewer views, including cold planners, respect source and permanent publication floors; clearing a published overlay never reuses its IDs. Full model clear drops unchanged views and cached editors in one partial state commit, retaining pending edits for reload under the same model ID.

Hydration commits source data, ownership bounds and capacity together, including superseded settlement. Deferred allocator notifications observe complete creation, restoration (including stashed edits and indexes) and transaction rollback; allocator ticks refresh only their model and reentrant capacity changes drain to stability. Read-only facades do not configure allocators. `highestExistingExpressId(store)` reads compact maxima and deferred IDs without scanning compact keys or redundant compact entity columns, while map/indexless stores retain table-only ID coverage.
