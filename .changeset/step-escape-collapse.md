Collapse both ISO 10303-21 string doublings on read: the doubled apostrophe on the Rust attribute path, and the doubled reverse solidus in both decoders.

The standard doubles the apostrophe and the reverse solidus inside a string literal, so `'O''Brien'` holds one apostrophe and `'C:\\temp'` holds one backslash. Two separate halves of that were missing. The apostrophe was un-doubled by the browser parser but not by `AttributeValue::from_token`, which is the funnel behind the CSV, JSON, JSON-LD, IFC5 and Parquet exports and the `ifclite-geom` wheel — the same file therefore read differently depending on which engine produced the output, with the Rust side handing back `O''Brien` for a name, a description, a property value, and a property-set name alike. The reverse solidus was resolved by neither language: it fell into the decoders' "unknown or malformed escapes pass through" branch and no caller of either decoder compensated, so a Windows path or a regular expression in a property value surfaced with every separator doubled. Both are wrong values rather than ugly ones — an IDS check or a downstream join against the authored string simply did not match, and nothing errored.

The apostrophe is un-doubled where the contract already said it should be, at the tokenizer's consumer, and before the backslash decode so that a pair an escape had just produced (`\X\27\X\27`) is not swallowed. The reverse solidus is resolved inside the decoders themselves, where it is unambiguous: the escape arms are disjoint on the character following the backslash, so a directive still consumes its own terminator before the pair is ever tested (`\X2\00FC\X0\` followed by `\\` is three consecutive backslashes and decodes to `ü\`), and fully-doubled text reads as the literal characters it is (`\\X2\\00FC\\X0\\` is `\X2\00FC\X0\`, not `ü`). Both readings are pinned to the shared Rust/TypeScript vectors that already held the two decoders together, which is what stops this from re-diverging.

The writers are the other half of the same contract. The TypeScript escapers were already doubling both; the Rust STEP and merged exporters were doubling only the apostrophe, which would have turned this read fix into a write bug, and now double both. What that makes true is the composition: write then read is the identity for a value containing either escape, and re-exporting a decoded value reproduces the same wire bytes instead of gaining a backslash on every pass. One behaviour change falls outside the pair itself, on malformed input — an empty `\X2\`/`\X4\` payload rejects the directive and the scan resumes one character in, where it now lands on a valid escaped reverse solidus, so `\X2\\X0\` decodes to `\X2\X0\` rather than passing through whole. The header decoder in `@ifc-lite/parser` drops its own hand-rolled span-aware scan for the backslash pair, which existed only because the shared decoder could not do this, and delegates instead.

Correct decoding is not idempotent, which makes "decode once, at the parse boundary" an invariant the display layer has to hold too. Running the decoder twice collapses `\\` a second time, so the authored UNC path `\\server\share` — stored, exported and round-tripped correctly — rendered as `\server\share`. Making the decoder idempotent instead would not work: idempotence requires treating an already-decoded `\` and an authored, still-doubled `\\` alike, which is exactly the ambiguity this change removes. The redundant second decodes are therefore removed: `parsePropertyValue` in `@ifc-lite/encoding` (the display funnel behind the viewer's property table and the Lists engine) now passes its input through, as do the property/quantity card name renders and the annotation-overlay text path, whose Rust producer has decoded at the parse boundary since `AttributeValue::from_token` did. A single-backslash value such as `C:\temp` is a fixed point of the decoder, which is why a redundant decode is easy to add and hard to see; the tests pin the adjacent-backslash case that makes it visible.

Patch rather than minor or major: no export, signature or option changes, and every affected value was previously returned in a form no consumer could have wanted.
