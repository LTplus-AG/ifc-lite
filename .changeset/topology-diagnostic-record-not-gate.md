'@ifc-lite/geometry': minor
---

Step 1 of #3440: every boolean op's accept path validated its kernel output through `ClippingProcessor::validate_mesh`, which checks position/normal finiteness and index bounds and nothing else — a torn result was accepted silently, including on paths whose own comments claim watertightness as part of the contract. `subtract_mesh`, `subtract_mesh_many`, `union_mesh` and `intersection_mesh` now also run the existing directed-edge closure audit (`directed_closed`, already used to gate the analytic prism-cut path) on the mesh each op is about to return, and record a failure carrying a fixed open-topology message through the same `record_failure` channel `NoBoundsOverlap` and the other informational records already use.

This records, it does not gate: `validate_mesh` returns exactly what it returned before, and every one of the four call sites still returns the same mesh it returned before this change. A hard gate here would silently reroute every currently-torn host onto its fallback path across difference, union and intersection at once, and nothing today can say whether those hosts would land better or worse — that measurement is what this diagnostic exists to produce, not something safe to assume in the same PR that adds the check. The follow-up steps are to gate the check behind the existing `debug_geometry`/`csg_capture`/`observability` flags already used for this class of check in `prism_cut.rs` so CI can run zero-tolerance while production still tolerates, and only once the corpus-wide flip set is known, a hard gate.

`subtract_mesh_many` audits the mesh it returns, once, after the last chunk — not each chunk's intermediate. A rejected group returns the host un-cut before the audit runs, so it still records nothing, as its contract says.

The record rides the existing `BoolFailureReason::KernelError` catch-all with a fixed message rather than a new enum variant. `BoolFailureReason` is re-exported from the crate root and is not `#[non_exhaustive]`, so a new variant is a major break for the `ifc-lite-geometry` crate (cargo-semver-checks `enum_variant_added`), which is a heavy price for a counter that changes no geometry. Nothing else in the crate emits `KernelError`, so today every such record is an open-topology accept. Step 2 of #3440, which makes the check gate, is where a dedicated variant earns its major.

The level is `minor`, not `patch`: hosts that previously loaded with no CSG failure recorded can now report one, which moves `totalCsgFailures`, `failuresByReason`, `worstHosts` and `silentNoOps` in the diagnostics this package reports on its `complete` event, and trips its "N CSG failure(s)" console warning. No export is added, removed or renamed, and the geometry handed to callers is unchanged.

`directed_closed` lived as `pub(super)` inside a private `closure_checks` module nested under the void router's prism-cut path, invisible to the CSG module across the crate. It is now `pub(crate)` (as is its parent `voids` module) so `csg/topology_diagnostic.rs` can call the same function the analytic prism-cut path already gates on, rather than writing a fourth definition of "watertight" in this crate — a divergence #3435 already documents between `closed_or_hairline` and the census's own `edge_stats`. Both are crate-internal visibilities, so nothing new is published.

Perf: this adds one O(triangles) hash sweep (`directed_closed`) per accepted boolean-op result. Not measured in this PR — the disk budget available for this change did not allow running `scripts/perf/probe.sh`. `directed_closed` is already run several times per candidate mesh in the hot prism-cut path, which is precedent for its cost being tolerable, but that is context, not a measurement, and this should not be read as claiming one.
