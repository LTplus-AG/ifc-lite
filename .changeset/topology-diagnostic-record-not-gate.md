Step 1 of #3440: every boolean op's accept path validates its kernel output through `ClippingProcessor::validate_mesh`, which checks finiteness and index bounds and nothing else — a torn result was accepted silently, including on paths whose own comments claim watertightness as part of the contract. `subtract_mesh`, `subtract_mesh_many`, `union_mesh` and `intersection_mesh` now also run the existing directed-edge closure audit (`directed_closed`, already used to gate the analytic prism-cut path) on the mesh each op is about to return, and record a new `BoolFailureReason::OpenTopology` through the same `record_failure` channel `NoBoundsOverlap` and the other informational variants already use when it fails.

This records, it does not gate: `validate_mesh` returns exactly what it returned before, and every one of the four call sites still returns the same mesh it returned before this change. A hard gate here would silently reroute every currently-torn host onto its fallback path across difference, union and intersection at once, and nothing today can say whether those hosts would land better or worse — that measurement is what this diagnostic exists to produce, not something safe to assume in the same PR that adds the check. The follow-up steps are to gate the check behind the existing `debug_geometry`/`csg_capture`/`observability` flags already used for this class of check in `prism_cut.rs` so CI can run zero-tolerance while production still tolerates, and only once the corpus-wide flip set is known, a hard gate.

`directed_closed` lived as `pub(super)` inside a private `closure_checks` module nested under the void router's prism-cut path, invisible to the CSG module across the crate. It is now `pub(crate)` (as is its parent `voids` module) so `csg/mod.rs` can call the same function `prism_cut.rs` already gates on at five sites, rather than writing a fourth definition of "watertight" in this crate — a divergence #3435 already documents between `closed_or_hairline` and the census's own `edge_stats`.

Perf: this adds one O(triangles) hash sweep (`directed_closed`) per accepted boolean-op result. Not measured in this PR — the disk budget available for this change did not allow running `scripts/perf/probe.sh`. `directed_closed` is already run several times per candidate mesh in the hot prism-cut path, which is precedent for its cost being tolerable, but that is context, not a measurement, and the PR should not be read as claiming one.
