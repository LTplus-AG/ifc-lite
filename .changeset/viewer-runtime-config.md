A host that deploys the viewer for its users can configure it at start. `mountViewer(container, { config })` takes a `ViewerRuntimeConfig` (version 1: `features` with `default: 'all' | 'none'` plus `disable` / `enable`, and `locale`), and the stock entry fetches one from the same origin when the build sets `VITE_VIEWER_CONFIG_URL`, forwarding the page's `context` query parameter. The request overlaps the download of the viewer's code and times out after 15 seconds. If it fails the viewer shows an error and does not start, so a restricted deployment never falls back to showing everything. Every switchable feature is listed in a catalogue that each build publishes as `features.json` next to `index.html`; this release covers product analytics, the hosting analytics script and the privacy notice. The host's `locale` is the default language; a language chosen in Settings still wins. This is presentation, not protection. With no configuration nothing changes. Analytics now start when the viewer mounts instead of when the module is imported, and the startup locale is negotiated at mount instead of on import. Guide: `docs/guide/viewer-deployment-config.md`.
