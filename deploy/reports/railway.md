## Same-origin route qualification

`vercel.json` forwards only the three viewer entry points (`capabilities`, `session`, `drafts`), canonical UUID report-owner paths and the explicitly supported owner actions (`consent`, `agreement.pdf`, `custom-nda`, `uploads`, `submit`; UUID upload reads and `parts`, `complete`, `abort`) to the dedicated HTTPS API before the SPA fallback. Administrative, unknown and traversal suffixes are excluded. No administrative gateway destination is configured or qualified by this change; maintainer access through an authenticated gateway remains a separate launch requirement. A later issue-target layer adds `resolve-issue` and must independently qualify any routing extension; that future endpoint is excluded here. The separately qualified viewer reporting client must keep relative URLs and same-origin credentials; this main-based routing unit does not add or enable that client. Model bytes go directly to the private S3 endpoint; this rewrite is for control requests and agreement responses. Do not replace the viewer base with the Railway hostname or weaken cookie, Origin or CSRF rules. No Vite proxy or development-origin exception is added.

After the normal viewer deployment, keep public submissions off and verify:

1. Viewer-origin capabilities return `application/json`, `submissionsEnabled:false`, `Cache-Control:no-store` and no session cookie, rather than HTML. Repeat to rule out cached authenticated responses. Do not enable Vercel rewrite caching.
2. Unqualified new sessions/content remain 503. Staff qualification uses a protected operator request, not a token embedded in a browser bundle. The proxy must preserve the exact viewer Origin and backend response status.
3. A qualified session's `__Host-ifclite_report` cookie remains Secure, HttpOnly, SameSite=Strict, Path=/ and without Domain. It belongs to the viewer host. A second cookie jar cannot read or mutate the first owner's report; missing/wrong CSRF and cross-origin mutations fail.
4. Complete a public-fixture upload and deletion through the actual viewer-origin control route, including restart/resume and no-publication checks. Keep all credential-bearing request/response data out of evidence and proxy logs. Confirm routing did not change cloud or Autodesk paths.
5. Qualify client admission across the complete Vercel→Railway chain before enabling users. The current code trusts forwarded addresses only from configured socket peers. Without verified ingress it conservatively shares the proxy-peer quota. Never invent trusted CIDRs or trust all proxies: an unrelated tenant must not forge another client's admission identity. If a verified per-client chain cannot be established, add an authenticated server relay and dedicated server-side ingress proof as separate reviewed work. The static rewrite alone does not establish that proof.

Vercel processes these proxied control requests. Review its logging/observability settings and disclose that processor; do not infer exclusively European handling from the Railway/Scaleway regions. No request body, private filename, NDA/contact data or credential headers should be sent to log drains.

## Backup, privacy and location limits

Railway [documents six-day retention for daily volume backups](https://docs.railway.com/volumes/backups). Native reporting-volume backups are in Amsterdam according to the [provider clarification](https://station.railway.com/questions/data-residency-storage-region-for-volu-f90b5ca6). Application/build/HTTP logs are processed in US West; separate provider-internal disaster-recovery copies are outside that location assurance. The user accepted these disclosed limitations, not an EU-only contractual guarantee.

Application logging is categorical. Hosted PostgreSQL settings disable statement/parameter logging and restrict error statement/detail output; the [logging receipt](../../tests/evidence/model-reports-7495/hosted-database-logging.json) records the checked values. Recheck them after deployment or restore. Ordinary private report details/models expire after 30 days, incomplete uploads after one day; completed-object deletion depends on the application's retention worker. The bucket's MPU lifecycle does not expire completed objects. No separate operator backup of model bytes is configured.

A deleted report may remain in a database snapshot until that snapshot expires. Manual snapshots and detached restore volumes need explicit bounded cleanup; an indefinite locked/manual backup is not covered by the six-day schedule. Do not promise an exact provider-internal backup deletion deadline that has not been verified. The owner approved the exact [LTplus AG v2 agreement](../../legal/model-report-confidentiality-agreement-2026-10-13.v2.txt), version `2026-10-13.v2`, SHA-256 `8977cc03be648645f5b4f568cc9506beddd07f42547e25ace1da530cba37bbbb`, for later automated issuance. Keep NDA signing disabled until complete-source and actual access, provider disclosure, custody, retention, deletion, backup and restore controls qualify the agreed promises. The historical v1 draft and dated logging evidence retain their original bytes and scope.
