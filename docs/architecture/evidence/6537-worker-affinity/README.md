# Worker affinity investigation (#6537)

These are exploratory observations of the actual canonical worker pool, not an A/B performance verdict. Other worktrees were running build and validation graphs during capture. The observer adds timestamps and primitive routing records to existing messages; it preserves message arguments, transfer lists and scheduler policy. No production scheduling code changed.

The production build is `a695734678d5c78206807921b4d173b8977f7162`, whose loading, geometry and renderer paths equal main `e79f27342beb01a6f30d9b63c44795ecd118f4de`. Served WASM SHA-256 is `039415545e2448ce8b1e40b14306524ee60cff29dabd97448080ac0d9e170610`. Fresh owned Windows Chrome contexts load each public fixture first, using the real file input. The native adapter is NVIDIA Blackwell. Metadata, geometry streaming and finalization complete, and an actual GPU color-frame readback is archived for each load. This is not a hash of all GPU upload bytes.

[`summary.json`](summary.json) records input hashes, public download links and worker-local completion clocks for Revit Snowdon Towers, ARCHICAD Holter Tower and ARCHICAD O-S1. Lossless gzip files preserve the complete original traces. All eight processing workers have timestamp coverage for their call boundaries and slice completions. The separate prepass worker injection failed after its context closed in two original runs; those failures remain in the traces and are not represented as processing-worker coverage.

All slices were already posted before the first processing worker finished its final queue on each model. Holter has a larger final idle tail than the other two observations. Job count alone does not predict worker completion: the worker receiving the most jobs finished before workers receiving fewer jobs. The routing-key counts include the initial entity-ID first wave; they are not counts of distinct geometry prototypes. Summed idle-tail worker time is not recoverable wall-clock savings.

The second Holter trace additionally records ordered job keys and express IDs. [`holter-call-boundaries-v2.json`](holter-call-boundaries-v2.json) groups them by actual worker call boundaries. These durations include output flushing and bookkeeping, and multiple keys occur in each call; they do not identify an individual expensive prototype. Its prepass injection succeeded, but it remains an instrumented observation on a busy host.

The next scheduling experiment must retain unstarted groups on the host or otherwise change when they become owned; changing only how new keys are assigned after a worker goes idle cannot move the existing backlog. Sticky ownership of already processed keys, cache reuse, watchdog/retry ownership and exact geometry must remain intact. A candidate earns a performance verdict only through fresh-tab, interleaved end-to-end base/branch controls on an idle host.

`capture.cjs` and `capture-v2.cjs` archive the actual external observer, with only an MPL header added. Their absolute module, CDP and preview paths identify the capture environment; adjust those paths explicitly when reproducing elsewhere. `artifacts.json` records archived byte identities. This evidence does not resolve the O-S1 cache-release A/B result or close any of the four mechanisms in the charter.
