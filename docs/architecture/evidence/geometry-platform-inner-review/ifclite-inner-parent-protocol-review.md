## Concrete findings

**1. Release builds omit Boolean active-path pop.** `program/boolean/protocol.rs`, `BooleanProgram::request_inner`, Frame::ExitPath removes the visited membership but calls `state.active.pop()` only inside `debug_assert_eq!`. Optimized builds omit that entire expression. The active vector therefore retains exited ancestors and completed sibling branches rather than representing the current path. This is the same side-effect-in-debug-assert defect previously corrected in the direct traversal; `boolean/mod.rs::source_frame` already uses the safe separate local pattern.

Move the pop out of the assertion: `let exited = state.active.pop(); debug_assert_eq!(exited, Some(id));`. Keep the numerical/source order otherwise unchanged. This is a real release/debug semantic difference and growing stale bookkeeping; this inspection does not claim a measured geometry mismatch. Add a real Boolean completion/sibling fixture invariant asserting the actual active path is empty after completed exits, and execute it with debug assertions disabled. A normal debug-only test cannot expose the omitted side effect.

**2. A stopped numerical request still performs void-output cleanup first.** `inner_voids.rs::ReadyFinish::execute` calls `self.part.mesh.clean_degenerate()` before its first resource::check_current. The common ReadyOperation::execute dispatcher has no shared entry barrier, and ProductState::execute can execute an already-issued inner numerical request after cancellation becomes sticky. Its lexical owner/scopes do not themselves short-circuit the closure. Thus cancellation between request and execute can still run cleanup and mutate the product's degenerate accounting before returning typed stop. Final output is rejected, so this is extra work/accounting after terminal, not a claim of false successful geometry publication.

Add an entry check before cleanup (or a correctly typed shared entry barrier). Keep the existing post-clean check. A meaningful regression can use a real mesh with degenerate triangles, issue the reached finish operation, make cancellation sticky, execute it and assert unchanged dropped-triangle accounting and typed terminal, with no further part/recovery work. Other ready variants were inspected selectively; this report does not certify every helper's entry barrier.

**3. Exposed diagnostic cancellation bypasses inner router binding.** `GeometryProgram::cancel_with_reports(router)` is public and immediately takes accepted source report cells/continuation reports and records them on the supplied router. It never validates expected_router or the selected emitter/owner first. A low-level caller can execute source admission on router A, then cancel_with_reports(router B), consuming A's evidence into B before any ownership rejection. Actual ProgramRequest execute/accept reject foreign routers, making this diagnostic path inconsistent with that protocol boundary.

Validate the bound router before consuming reports or cleanup, returning rejection without mutation if foreign. This is an exposed low-level API gap: canonical ProductState::finish_stopped correctly reinstalls/validates its actual ProductOwner and scopes before calling cancellation, so no canonical foreign-owner regression is demonstrated here. Preserve legitimate cancellation after a terminal without discarding reached evidence. Test real admitted source refusal reports with foreign cancellation followed by valid cancellation, verifying neither misattribution nor one-time report loss.

## Request/reply ownership and execution review

ProgramRequest is identity only: private program ID, sequence and stage, Copy without a recipe. GeometryProgram owns every actual action/continuation. One pending ticket is issued; request rejects outstanding work. Source/Extension execution marks it consumed before invoking source/selected callback code, preventing copied-ticket replay after unwind. Numerical extraction moves the actual ReadyPayload once and marks pending executed before arithmetic executes. ProgramReply owns its non-Clone output; its fields/payload variants are not public constructors. Validation checks exact request/payload/emitter/router identity and recursively validates nested children before accepting outer side effects. RejectedProgramReply returns the complete original linear reply. No validation-time cleanup/cache publication was found.

Expected decoder identity is checked at subsequent execution, while the inner accept API takes a router only. Canonical ProductState supplies the stronger actual decoder/router lease and source/context validation on both execute and accept. Consequently this inner API is not an independently authenticated detached source/session protocol. The delivered documentation explicitly leaves arbitrary detached worker execution unqualified; do not advertise the public raw inner primitives as a remote source-authority boundary. Initial entity/decoder pairing retains the existing trusted synchronous router calling contract.

Actual selected emitter identity is drawn from the registry processor instance, with nested Boolean recorder binding checked against that selected instance. It is not a family-name inference. Registry/configuration changes alter router identity and are rejected before resuming against a different configuration; trusted same-work callback changes commit through the existing owner mechanism. Pending ProductState rejection preserves its packet before any inner accept. A callback panic leaves ActiveScopes absent/poisoned and inner pending consumed, so a stale outer false/executed marker does not grant replay.

The common processing consumer retains one PendingGeometryAttempt across reached inner requests. Only a fully completed attempt crosses the original Primary/TypeMap/Parts recovery and presentation boundary. GeometryStep replies with sticky stop are still consumed through their numerical/source diagnostic acceptance before cancel_with_reports; coarse outcomes are replaced by Stopped before retries/output. Dormant terminal attempts are kept until finish_stopped reinstalls validated scopes for diagnostic-only cancellation. This preserves the existing canonical owner, source context, triangle-order, exact element/resource state and final diagnostic behavior rather than creating another producer.

## Numerical/source separation and diagnostics

ReadyOperation contains derived numerical enum payloads and nested numerical envelopes, not GeometryProgram, decoder/router/schema or full source traversal callbacks. Child programs stay in executor controls. Inspected item constructors, Boolean plane/prism/solid/group/shell work, cache hashing, mapping geometry, opening metrics/frame/projection operations and void ready operations evaluate owned numeric data. This is stronger than a callback wrapper around an entire original router walk, but it is not proof of complete bounded allocation coverage or every arithmetic branch's equivalence.

Accepted item source reports use a shared once-only cell between executor and detached packet. Numerical reports remain reply-owned; cancellation and unwind consume source evidence once while restoring the caller prefix. Consuming Single and Group completion checks preserve reached records before terminal classification; Group rewinds provisional records only on ordinary numerical deferral. Void Cut acceptance reaches NumericalOutcome::publish even on stop, allowing failure-only publication while rejecting success effects/telemetry. Staged child ownership remains narrower than root evidence. No explicit source/global cache rollback, budget refund or alternate exact kernel was found in the inspected paths.

The public cancellation hole above is separate from ordinary terminal handling. Arbitrarily dropping a dormant GeometryProgram does not publish reports through ambient TLS; explicit scoped cancellation is the documented route. Dropped numerical replies also retain no ambient publication capability, so owning/executing/accepting them remains a caller obligation under the current synchronous protocol.
