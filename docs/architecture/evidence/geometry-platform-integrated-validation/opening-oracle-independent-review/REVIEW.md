# Independent opening oracle contract review

Read-only decision review. No repository edits, builds, SDK runs, fleet submissions, tolerance changes or model changes. Root owns the landing decision.

## Decision

Scoped approval **conditional on the implementation below** for replacing the newly introduced analytic-BRep-versus-display-mesh volume assertion with an independently source-derived analytic-volume assertion, keeping the existing absolute 1e-6 predicate. This is a correction to the new test's oracle contract, not a fix to production numerical code, and it does not make the representation difference or the no-regression release gate disappear. No production behavior/default selection may change as part of this repair.

Blocking release obligations remain: actual identical-consumer pre-migration-base versus branch exact-path mesh/output identity, actual execution of repaired SDK and Worker witnesses, the separate #3641 non-simple source case, and all other platform/appearance/final-product obligations. If the optional retained mode is required to reproduce the old display mesh exactly, the measured differences remain a supported-mode compatibility blocker; this review cannot redefine that requirement.

## Source and independent verification

Inspected the committed fixture and witness transforms directly. Host #26 and cutters #46/#66/#96 are rectangle-profile +Z prisms; their solid 3D placements and product placement chain #29/#49/#69/#99 -> #8 -> #5 have identity orientation and no extra translation. There is no unit assignment in this fixture; the existing fixture interpretation is metre-valued. The profile directions are (1,0), (.8,.6), (.6,-.8), all positive-oriented rectangle frames after constructing Y=(-sin,cos). Canonical normalization in placement/mod.rs has unit binary64 norms for these particular directions. Half-width/height divisions by two are exact. The Reference variant removes only A from admitted cutters. Repeated variant adds two host item occurrences, and opening A occurrences #201/#202 share #200 with identity #205 and +decoded(.2) X #206; its source map origin is identity #5. These details match the script's input model.

The binary script is correctly structured for this narrow fixture: each numeric leaf is converted to binary64 before exact Fraction lifting; polygon corners derive from those individual values; convex clipping uses CCW half-plane tests and exact rational intersections; inclusion-exclusion accounts for both planar and vertical overlap, including the tiny difference between decoded(.3)+decoded(1.2) and decoded(.6)+decoded(.9). It does not replace those expressions with a pre-rounded 1.5 or 1.7. Boundary duplicates in clipping do not alter signed area. Repeated host multiplicity is applied after per-host union removal, not as subtraction of duplicated cutter volumes.

I independently implemented a different union algorithm in /tmp/ifclite-opening-independent-slab.py. It reuses the script's decoded polygons/source records only, not its clip, inclusion-exclusion or remaining-volume functions. It splits Z at every source endpoint, splits X at every polygon vertex and exact pairwise segment intersection, clips each vertical interval to the host, merges cutter intervals and integrates their piecewise-linear union with exact midpoint quadrature. Every prefix of all three cutter sequences equals the script's exact rational result, not merely its rounded decimal. The fixture-only run completed in under one second; this is not an SDK/engine or canonical decoder run.

Final nearest-f64 values are 2.08, 2.20756625, and 4.16. Exact rational outputs are in /tmp/ifclite-opening-independent-slab.json. Agreement of these two algorithms supports the analytic reference, independent of the measured SDK volumes. Source extraction remains shared/manual-verified; Python float parsing and math.sqrt have not been qualified against an executed EntityDecoder/nalgebra capture.

## Minimum repair that is robust enough to land

1. Keep the failed bab3 values, source/job identity and old assertion text archived. Record the SDK/display differences without attributing their cause to one snap or calling the old exact result incorrect. The explicit kernel reconcile grid and existing execute_tests.rs admitted-volume test establish why exact predicates do not imply authored analytic-volume identity, but they do not trace this fixture's full displacement.
2. A committed test helper must derive its analytic expectation from the actual fixture's canonical decoded coefficients and transforms, with explicit guards restricting it to these finite rectangular +Z prism cases, identity product frames/default units and the reached Reference/mapped occurrence set. Resolve the repeated transform from #206/#204 or canonical mapped frame; do not substitute a hardcoded .2 or inferred final centre. Reject unsupported geometry rather than accidentally broaden this independent oracle.
3. Keep an independent geometry calculation (reviewed exact-rational convex clipping plus inclusion-exclusion, or independently derived interval integration). Do not read SDK mesh, SDK volume, process_geometry result, or observed result constants to build the expectation. A fixture hash plus naked constants alone is weaker than the requested actual-source semantic witness. Capture/assert canonical raw coefficient bits and actual frames so Python's correctly-rounded parsing assumption is checked in Rust, not silently treated as proof.
4. Preserve all current operation/occurrence count, source identity, order/Reference eligibility, sealed frame, live receipt, manifold, Empty, presentation/host multiplicity and source-lifetime gates. Assert independent source-derived per-cut volumes as well as final totals where practical. Repeated per-host results must be checked individually; sum equality alone can conceal one host losing material and another gaining it.
5. Preserve the 1e-6 absolute analytic-volume predicate. Do not widen it to the display delta. SDK integration tolerance stays within its existing documented argument range. Do not relabel a test-helper change as a production geometry repair.
6. Add a shape-discriminating actual physical witness before calling these sources geometrically qualified. At least signed plane sections through wall thickness centre y=decoded(.1), at interior Z levels .1 (no cut), .4 (A/B), .7 (A/B/C), and 1.7 (no cut), compared to independently derived union interval endpoints. Include original, Reference and both repeated host occurrences, with section coordinates bound to each sealed object frame. Check source-derived outer bounds as well. For nominal reference only: at z=.4 A+B removes X=[1,7/3], B alone removes [5/3,7/3]; at z=.7 C+B removes [1.4875,7/3]. Actual expected endpoints must use decoded dyadic coefficients, not those rounded explanatory literals. These checks distinguish translation, missing-cut and wrong-profile errors which equal volume/manifold cannot exclude. A centroid alone still admits many incorrect solids.

## Preservation gate stays separate

Execute the same ordinary process_geometry consumer against a pinned pre-migration base and the integrated branch, identical fixtures/options/environment, and compare selected host mesh/triangle counts plus exact position/index bytes or canonical documented identity. Also retain existing order-invariance coverage. Source unchanged production defaults is useful evidence but is not the requested actual execution. Comparing branch analytic BRep to branch display mesh is a representation comparison; comparing pre-migration display mesh to branch display mesh is the no-regression check. Both results must remain visible. No new analytic optional path may silently select itself for the default exact mode.

## Explicit limits

The independent slab algorithm verifies this small fixture's prism-union arithmetic and the binary script; it is not a general IFC parser, source authority mechanism, interval bound on all intermediate engine f64 products, SDK proof, real authoring-tool corpus verdict or performance measurement. New oracle tests remain unexecuted here. #3641 opposite-direction positive-length boundary overlap and its positive SDK/Worker gate remain independent and red/unqualified. No tolerances, kernel guards or source data were changed.
