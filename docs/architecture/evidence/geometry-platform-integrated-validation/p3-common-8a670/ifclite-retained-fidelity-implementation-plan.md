## Decision

Use actual SDK topology ancestry plus constructor-supplied semantic source bindings. Keep result-face identity, source ancestry, occurrence identity and texture parameterization separate. The current operation-level `RetainedLineage` and tessellated local face numbers do not establish persistent face provenance. P4 needs a versioned per-result face-lineage table and per-corner differential/parameter data before canonical presentation can consume retained results without losing appearance.

An opaque result-face key is legitimate only as an object-revision-local handle. It must not be advertised as a persistent IFC face identifier. Split descendants can share source ancestry while having different result-face keys; coincident merges can carry several ancestors. Neither SDK pointers nor enumeration order supplies cross-operation identity.

## Primary mechanisms and their limits

1. `native/smlib-adapter/src/mesh.cpp:15–78` enumerates `SmBrep::GetFaces`, maps `SmPolyFace::GetOriginalFace()` back to that enumeration, and carries the label through polygon triangulation. This is useful exact topology attribution within one live result. It does not connect that result to the input solids. Current output has shared positional vertices, flat triangle-corner cross-product normals, local face numbers, and no UVs.
2. `copy.cpp:39–60` uses the checked `MergeBrep` path preserving raw tolerance metadata, but supplies null copy maps. SDK `SmCopyBrepMap.h` maps copied topology to originals; its own contract says the map becomes obsolete after either BRep changes. Extend the checked-copy helper with an optional immediately consumed mapping result. Transfer source bindings before any transform/Boolean; retain immutable lineage nodes, not this map or deleted input pointers. Preserve current copy checks, process-taint behavior and tolerance restoration.
3. SDK `SmAObject.cpp:118–185` actually dispatches `SM_NO_COPY`, `SM_NO_SPLIT_IN_BREP`, `SM_NO_MERGE_IN_BREP`, `SM_NO_COINCIDENT` and geometry-change events to attached `SmAttribute` callbacks. `SmAttribute.h:673–760` supplies virtual `MakeCopy`, `Copy`, `Split`, `Merge`, `Coincident`. Default propagation only fills missing same-ID attributes; it cannot preserve both ancestors on coincident/merged faces. Implement a dedicated lineage attribute with immutable ancestry sets and union semantics, not a scalar ID using defaults. Its merge callback must read both operands: SDK suppresses a redundant second callback for equal AttributeIDs. Region `IsPropagatedThroughBooleans()` is a separate region rule, not proof that every face lineage path is covered.
4. `adapter.cpp:193–220` copies both inputs then performs destructive Boolean, consuming the right BRep. Capture copy ancestry first and inspect all output faces before publishing. Difference-cut surfaces usually descend from the right cutter; they are not necessarily ancestry-free faces. Store operation/operand role and orientation separately from the inherited source surface. Preserve multiple origins for coincident faces and choose appearance using an explicit canonical policy.
5. `SmTrackTopologyChanges.h` warns about deleted-pointer reuse. Its change map is not stable identity, and the tracker uses the system callback. Do not install it over kernel system callbacks. A scoped user callback can audit missing construction/edit events, restoring the previous callback; event coverage still needs real operation tests. No exception should escape a kernel notification without an established SDK exception contract. Prefer a bounded out-of-band failure flag checked before result publication.
6. Source constructor labels are not implemented. `sweep.cpp:151–158` obtains the final BRep but no semantic face map. SDK `SmPrimitiveCreation.cpp:1150–1483` knows the source-curve iteration, creates the side face around line1362, and creates start/end caps afterwards. That is a real association seam. Add an optional SDK constructor result/provenance hook at those existing creation sites, or an equally evidenced existing relation; do not infer side roles by final face order or match sampled surfaces. The wrapper copies consuming input curves, so any source tag must survive that copy and be linked explicitly to the created face. Use the same builder, not an adapter reimplementation of sweep math. General surfaces, disk sweep joins and other constructors each need analogous genuine associations.

## Concrete owned contracts

Suggested names describe required data, not existing public APIs:

- `SourceSurfaceKey { definition/source revision, authored item or explicit face ID, semantic patch }`. For a sweep, patch is start cap, end cap, or profile loop/segment; include exact source parameter interval/orientation. For imported data use its source-neutral path identity, not invented STEP IDs.
- `ResultFaceKey { captured runtime/object generation, result revision, local face }` with a sealed face table owned alongside the existing managed object lease.
- `FaceOrigin { source_surface, operation path, operand role, orientation, parameter_transport }`; a result face has a bounded ordered set of origins. Generated geometry is explicit `Generated { operation identity, kind, support/cutter binding }`, never a fake authored face.
- `RetainedFaceTable { result identity, faces: [origins, display role, parameter-map status] }`. Missing ancestry/parameter transport is a coverage failure, not an empty successful table.
- `RetainedDisplayMesh { positions_f64, triangles, triangle_result_faces, corner_normals_f64, corner_surface_parameters, face_table }`. Validate all cardinalities/indices, finite values, ownership, completeness, byte/work limits before installing into the common reply ledger. Empty results have an explicit successful empty table.
- `ReadyRetainedAppearance` owns only the reached immutable material/texture/palette resources and numerical mappings plus product/occurrence identity. No decoder, model context, raw source bundle, or mutable SDK face pointer in numerical packets. Keep source lookups as authenticated reached admissions with their existing late order.

Runtime face tables must be produced by actual sealed execution, bound to the same handle/incarnation/generation/frame as the numerical result. Host-created lineage objects cannot authenticate SDK output. Occurrence transformations compose separately so repeated mapped definitions share source ancestry without sharing occurrence identity. Face tables/corner data and provenance set union/copies need captured original resource account charges and typed stops before publication.

## Normals and UVs: concrete output changes

SDK `SmPoly.h` exposes `SmPolyEdge::GetAuxData()`; `SmPolyVertAuxData` contains original-surface normal and UV. The data is per corner, which is necessary at hard edges and texture seams. `SmSurface::EvaluateNormal`/`Evaluate1stDerivatives` are available. `GetOriginalFace` is safe as a temporary label even when back pointers are stale; do not dereference it when `GetOKBackPtrs()` is false. Consume live topology data before disposal. Verify auxiliary data for every original and newly triangulated corner rather than assuming triangulation populates it. Missing or ambiguous UV/normal data requires explicit evaluation/coverage handling, not an unchecked flat-normal fallback.

`SmApiTessellate` calls `ConvertToPolyBrep` with attribute propagation enabled, but the SDK header says attribute propagation requires `SM_INDEXING`. The current adapter's explicit original-face lookup should remain the attribution authority; don't silently depend on a build flag to recover lineage. Auxiliary UV is documented as surface UV **or** texture UV, so it must not be exposed as IFC texture coordinates without proving its parameter convention. Surface orientation/faceuse orientation and reflection parity must be applied exactly once. Transform normals with the actual inverse transpose for nonrigid transforms and normalize; proper rigid placement only rotates them. Preserve corner discontinuities when expanding/welding to canonical per-vertex buffers.

`ResolvedTextureMap` in `processors/texture/mod.rs:95–115` contains IFC face-set vertex UVs and optional per-triangle indices parallel to original `CoordIndex`. Those indices do not apply to a new tessellation. In particular, `TexCoordIndex=None` still binds to original source coordinate indices, not new SDK vertex indices. There is no sound “same number of triangles” shortcut.

For explicit triangular source patches, retain the exact authored triangle/corner-UV relation and interpolate using its source patch coordinates for descendants; this is an authored mapping, not matching sampled mesh faces. Crossing a texture discontinuity must split patches/corners. General analytic surfaces require an actual IFC surface/texture generator mapping, source parameter domains and any reparameterization transport. An arbitrary vertex-index texture map cannot be promoted to a continuous analytic surface texture without an explicit mapping definition. Rational conversion and surface replacement must carry an exact parameter transport certificate, or mark that obligation unresolved. Circle/cylinder periodic seams and trimmed surface domains are mandatory witnesses. Texture source bytes/URL, texture ID, repeatS/repeatT, alpha, and attachment deduplication remain canonical.

## Canonical presentation preservation

`RetainedPresentation` currently stores item/style/map/type identity and pending indexed palette/texture resources. It records obligations; it does not evaluate them. Extend the logical face/source binding, not just append a final mesh's arbitrary local face IDs.

Use `element/presentation_source.rs` and existing `assembly_*`/`element_mesh_build.rs` as the only final assembly policy. Preserve:

- submesh orientation/normal repair before direct/mapped style admission; empty noninstances skip style and material cursor; instance placeholders consume the shared material cursor;
- style lookup, element-material cursor, fallback and inferred material-name order; type-map fallback lookup timing and geometry class;
- texture validity and texture-over-indexed-palette precedence; palette source geometry ID versus material ID; UV-aware source weld and hash timing;
- product metadata, source/material ID distinction, origin and MeshFrame, instance/template eligibility, local bounds/local-to-world, site-local rotation and f64 survey/RTC composition.

Retessellated output needs an explicit source-face palette mapping instead of applying `split_mesh_by_indexed_colour` against unrelated new triangle positions. Source item style alone is insufficient when original faces have different palettes. Resolve coincident ancestry using defined operand/style precedence and preserve ambiguity until that policy exists; averaging colors is not preservation.

Layer display is the host's outer shell partitioned by material bands. `program/layers/slice.rs` deliberately makes no interface caps. A retained closed-solid split can retain caps numerically, but display must exclude only layer-generated internal interface faces, while retaining genuine opening/cutter surfaces from the pre-layer host. Tag the actual plane operation's generated faces and carry host ancestry. Geometric “lies on interface plane” tests can delete legitimate authored faces and are not proof. Keep shared-interface geometry coherent and material IDs distinct from geometry IDs. Coordinate this face role protocol with the active plane owner; don't change their numerical opcodes in parallel.

## Derived rigid occurrence concern

Confirmed at `program/retained.rs:137–150`: a nonidentity proper-rigid frame on an Operation definition is forced through `RetainedOperationKind::Affine`. `worker_dependencies.rs` accepts a frame override for Source/Affine, but Result takes only its stored frame. Opcode18 runs rational eligibility/normalization (`affine.cpp:92–175`) even for a translation. It can refuse classes/knots that a proper-rigid checked copy can preserve. SDK sweep construction can produce `SmSurfOfExtrusion`, which is outside that affine surface-class certificate. This is an unnecessary preservation restriction for a rigidly placed derived result, not an executed numerical regression claim.

Preferred seam: a sealed placed dependency/value carrying a borrowed sealed result plus an authenticated proper-rigid absolute world-from-evaluation frame (or an explicit relative delta with unambiguous composition), retaining the same liveness lease and lineage `Placed`. Geometry adds a typed Placement operation/value, or keeps rigid occurrence metadata without a numerical operation; processing still binds the immutable expected frame and ticket. Validate runtime rigid tolerances, source/generation and operand identity before consuming the receipt. Do not loosen rational preflight or opcode18: identity opcode18 intentionally means conversion in the plane path. Alternative opcode17 needs a **sealed** rigid-copy result with managed liveness/lineage/copy-face table; raw `copy_transform` returning a handle is insufficient for canonical acceptance. Neither route should overwrite a borrowed Boolean result's frame or mutate shared definitions.

Required witnesses: nonidentity rigid placement after Boolean, nested/repeated occurrences of the same result, rigid class preservation including a non-affine-certified surface, stale/foreign frame rejection, original result still usable, survey-scale translation kept outside object coordinates. Nonuniform/reflected placements must continue through explicit affine handling.

## Safe implementation and qualification sequence

1. Add checked-copy face map consumption and adapter-owned lineage attribute/sidecar; qualify copy, split, coincident merge, geometry replacement and destructive Boolean coverage with all output faces accounted. Capture both operand roles and generated-plane roles. Keep incomplete operations unpublished.
2. Add exact constructor face-association output at actual creation sites and source-domain/parameter transport. Feed it through the existing authored request, sealed receipts and common operations; no second walker or evaluator.
3. Extend one shared versioned native/browser mesh protocol for per-corner normals/parameters and sealed face table. Bound lineage growth and wire lengths; validate malformed cardinality, foreign object and expired table cases. Keep process/worker lifecycle and release linearity intact.
4. Implement Rust source-parameter appearance evaluation, normal orientation and corner splitting. Emit the existing canonical ReadyPresentation inputs and use existing assembly/hash/site-local/instance funnel. Source/curve/texture obligations remain visible until actually evaluated.
5. Integrate retained layer exterior-shell filtering and final product publication only after placement/opening/layer/appearance obligations all close. Preserve exact contract and default behavior. Refusal keeps safety, but does not complete this goal.

Witness set must include actual authored fixture bytes via fixture catalog gates: annex_e tessellation-with-pixel/blob/image-texture, individual colors, advanced BRep, mapped transformation/multiple items; and real opening-cut layered walls. Explicitly derived invariants may wrap those bytes in nested nonidentity mappings, but must be labeled derived, not an original authoring-tool model. For indexed texture sources not admitted by retained constructors yet, first implement the genuine constructor/mapping support; an exact-only texture witness cannot qualify retained fidelity.

Native SDK tests must evaluate actual copies/Boolean/splits/affine, assert original topology-origin coverage and cut/interface roles, nonempty pixel/image attachments, UV seams and analytic normal directions. Include coincident differently styled inputs and reversed cutter orientation. Compare source semantics and independently known geometric/appearance invariants, not local face enumeration pins or nearest-triangle matching. Browser must run actual module worker from staged pinned assets through common issue/await/accept/final assembly, with cancellation/drop during dispatch, screenshots or sampled real texture output, immutable original receipts, and repeated occurrence isolation. Native success does not qualify browser or package artifacts. End-to-end base/branch performance, memory and output verdicts remain required separately.

This plan addresses P4's retained appearance seam. Full mapped/Boolean/opening/layer coverage, imported-format channels, final publication and all consumer qualification remain separate completion gates; no current source-only output is a final displayed product.
