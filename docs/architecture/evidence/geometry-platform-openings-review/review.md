## Concrete objections before port

**1. Private import: `program/openings/mod.rs:9`.** It imports `GeometryRouter` through `crate::router::voids::{GeometryRouter, VoidContext}`. The `GeometryRouter` name there is a private `use super::GeometryRouter`, not a crate-visible reexport. Rust privacy rules indicate an E0603 private-import failure for the sibling `program` module. Import `crate::GeometryRouter` or `crate::router::GeometryRouter` directly; keep the crate-visible `VoidContext` alias. This is a static finding, not an observed compiler diagnostic.

**2. Gate initialization moves earlier.** `router/voids/mod.rs::numerical_configuration` eagerly calls all four enabled accessors before attempting the first numerical route. The previous parametric/2D success did not reach the prism/coaxial enabled calls. These accessors initialize process-wide OnceLocks from environment, so this is an observable lazy-read change even though arithmetic expressions are preserved. A deterministic supported-extension-shaped example is: an earlier host succeeds parametrically, then a later host's actual selected source callback sets `IFC_LITE_PRISM_CUT=0` or `IFC_LITE_VOID_UNION=0` before its reached numerical work. The old first relevant gate read can see the new value; eager capture on the earlier host can already have fixed the previous value. There is no sufficiently strong documented prohibition to dismiss this as unsupported. Preserve each pure configuration read at its original reached numerical route. Such a source-free configuration lookup does not require introducing a decoder/router service into Execution. Mandatory correction must use the value reached at its original conditional boundary, not force an earlier unrelated gate read.

## Effect ownership and remaining terminal acceptance work

The ordered EffectSet is consumed once; it logs rect stats, host failure summary, attributed failures, consumed marker and cut-effect writes. The staged mixed child owns its own Execution and detached telemetry. Its ordinary refusal/panic discards only that child, replacing the old snapshot/restore guard; prior source effects and previously completed hosts are outside this rollback domain. Accepted child effects append once and telemetry commits once after the unchanged correction/topology gates. The root numerical catch forwards reached parent effects before resuming the same panic. No source/global drain or actual-work census/account reset was introduced. A detached telemetry log is not a Send/transport qualification.

This is NOT yet terminal-safe on parent. NumericalOutcome currently carries only `thread::Result<Mesh>` and publishes all effects/telemetry before inspecting panic outcome. A typed terminal must have its own Result path and an acceptance barrier. Keep reached nonprovisional diagnostic evidence, but do not publish a false consumed/cut/rect success or staged telemetry after cancellation. Dropping an unaccepted child's owned effects is not a rewind/refund of source visits, resource charges or earlier hosts.
