# Typed route telemetry: static review

Inspected the current uncommitted shared-root telemetry change at HEAD `0446a34f139ca587903b47de2571f65240c7fefd`. Exact inspected source hashes are in `/tmp/ifclite-typed-telemetry-review-hashes.json`. No edits, builds, tests or jobs were performed. No concrete blocker found in this bounded review.

The four existing production closure-recording sites are replaced by ParametricCut, PlanarCut, PrismDefer and PrismCut scalar facts. A repository source search found no remaining closure caller of telemetry_transaction::record. Publishing still occurs only after record releases the PENDING RefCell borrow, preventing sink reentrancy under that borrow. Event payloads contain only integer scalars; Vec<Event> therefore admits Send and Sync without an executable closure, router, TLS reference or thread guard. Transaction itself retains PhantomData<Rc<()>> and remains thread-bound. The new compile-time generic Send+Sync assertion checks the detached type when tests compile, not a public cross-thread scheduling contract.

Atomic behavior is preserved at the original sinks: ParametricCut adds one PARAM_FIRES with Relaxed; PlanarCut increments FIRES before FOOTPRINTS with Relaxed; PrismDefer increments the same indexed DEFERS entry with Relaxed; PrismCut increments FIRES, OPENINGS_ANALYTIC then OPENINGS_RESIDUAL with Relaxed. Existing take/reset operations are unchanged. Earlier usize-to-u64 conversion before storing PrismCut rather than inside a deferred closure is a pure unchanged cast of already captured scalar values. Deferral index bounds and delayed-publish panic timing are unchanged.

Feature gating matches at enum variants, match arms, enabled diagnostic module and crate-visible sink reexports: any of observability, csg_capture or debug_geometry enables prism aggregate events. Without all three, prism diag remains the existing no-op aggregate implementation, while opening-perf-trace records actual candidate/defer work directly, including its feature-only configuration. The actual-work tracer, CSG census, weld counters and resource budgets do not move into transaction effects. Parameter and planar events remain available in feature-off builds, as before. All publisher paths are crate-visible through the existing crate-visible voids/bool2d_path/prism_cut modules and the new crate-visible param_stats reexport; no private import inconsistency was found.

Nested transaction semantics remain the same: capture pushes a new buffer; detach pops it and disables guard rollback; child commit re-records its events into the currently active parent in original order, or executes sinks immediately if none exists. A rejected detached set drops only its owned vector. An unwinding capture drops its active top buffer; parent buffers survive. Committing an accepted child does not escape an unaccepted enclosing parent. The conversion removes boxed closure allocation, but no performance or full-allocation-bound claim is established here.

The new isolated subprocess test selects the correct telemetry_transaction::tests path, checks that one test ran, and uses real counter entry points plus typed planar events to exercise nested acceptance, child discard, same-payload panic propagation, unpublished parent state, committed totals, enclosing-parent rejection and restoration of immediate publication after unwind. Its imports, child module wiring and catch_unwind capture shape show no evident name/privacy/borrow error. The test intentionally does not fabricate geometry because it verifies the telemetry transaction contract itself. It has not been compiled or run in this review.

Coverage limitations: new test does not exercise feature-enabled PrismDefer/PrismCut sink values, and its Send+Sync assertion is not an executed cross-thread transfer/commit test.
