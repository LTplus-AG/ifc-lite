# IFCX imported-geometry ownership: concrete implementation brief

Read-only source inspection; no repository edits, builds, tests, jobs or numerical requalification. Inspected source identities and local corpus presence are in `/tmp/ifclite-ifcx-owned-program-integration-plan-hashes.json`. Existing IFCX/USD receipts remain historical evidence for their recorded predecessor sources, not qualification of this proposal.

## Actual consumed boundary

`useIfcLoader.ts::loadFile` detects `ifcx` at approximately974 and awaits `ingest/viewerModelIngest.ts::parseIfcxViewerModel`. That calls the actual `@ifc-lite/parser` reexport of `packages/ifcx/src/index.ts::parseIfcx`. The latter already returns a **Promise**, as do `parseFederatedIfcx` and `addIfcxOverlay`; they are not synchronous public APIs. `extractGeometry`, `extractPointClouds` and the internal federated finalizer are synchronous today.

The exact production replacement seam is phase5 in **both** `index.ts:171-172` and `:558-559`: composed nodes and the authoritative pathToId already exist, properties have been extracted, and current code runs mesh extraction then point-cloud extraction before hierarchy/relationships/quantities. The second call is shared by initial layered parse and incremental overlay recomposition. Replacing only the first parse call would leave supported composition consumers on the old numerical emitter.

The raw handoff must occur **before** `geometry-extractor.ts::getNodeTransform/flattenMatrix`. Local matrices are already narrowed into Float32Array there; `combineTransforms` also writes each composed matrix cell into f32. Entering only at `convertUsdMesh`, or passing current transformByFrame values, is too late to own original precision. Use the already-composed raw `UsdMesh` arrays and raw local `UsdTransform.transform` matrices, plus their node/path/lineage identities. TS Number is the original parsed double here; original JSON numeric lexical spelling is already gone and must not be claimed.

No STEP decoding belongs at this boundary. `GeometryDocument::add_mesh_definition` currently accepts a finished `Mesh` with f32 positions, and `add_occurrence` accepts an invertible affine row-major f64 placement. These are useful display storage, not a source-before-narrowing import API. They cannot replace the emitter by wrapping already transformed buffers. Valid projective/current singular-normal fallback cases also do not fit that document occurrence admission unchanged.

## Scope and the existing load-path exception

Normal primary/federated single-file IFCX additions use loadFile and its existing stale-session checks/finalizeModel. Keep those calls and target/registry ownership. Do not add a native IFCX JSON loader, alternate viewer entry, synthetic STEP serialization or another composition engine.

Actual current code has a pre-existing exception: `useIfcFederation.ts::loadFederatedIfcxFromBuffers` directly calls parseFederatedIfcx, converts meshes and publishes layered models/store data, rather than going through loadFile. Its overlay-add route calls that helper again. This helper also omits parsed point clouds from its geometryResult. These are facts, not behavior to silently call canonical or fix as an incidental numerical rewrite. Whole-format canonical-load coverage must explicitly bring prepared layered input/publication into the same load owner, preserving the layer panel/provenance/reset/selection/ID-range/retry semantics. It must not stringify and reparse a baked scene to reach loadFile.

A coherent common-owner design is an internal prepared-source form accepted by loadFile's existing load session: the existing layer parser/composer produces a branded prepared IFCX source/store payload, then loadFile owns geometry work, cancellation/stale checks, finalization and publication. useIfcFederation becomes the layer-input/preparation wrapper. Keep ordinary File callers source compatible. Decide whether the prepared input is a private overload or a load-session-owned prepared-source ticket; either way there is one publication owner, no second loader. Point-cloud omission in the old layered helper requires an explicit fidelity decision/test, not an invented preservation claim. Reusing the new Rust emitter in both current parser entries advances numerical ownership before that owner unification; it does not alone satisfy the SAME-loadFile goal.

## Exact channels that must survive

* **Composition/source authority:** Keep composeIfcx/composeFederated, layer strength/order, inheritance and null masks, tombstones, resolved child-edge order, path resolver, layerStack/pathIndex, attributeSources/contributingLayers/pathToLayers. Existing remote schema imports are declared metadata; the parser does not fetch them. Rust receives composed source facts, never reinterprets composition or fetches assets/schemas.
* **Metadata:** Keep entity/property/quantity/relationship/hierarchy/string tables and getters, synthetic pathToId/idToPath generation/order, source bytes, fileSize/entityCount/schemaVersion, and progress phase order. Synthetic IDs can change on recomposition; retain that existing identity/reset policy rather than treating these as STEP IDs. ProcessingResult's narrower fields are not a replacement for IfcxParseResult.
* **Mesh source:** Original points, faceVertexIndices, optional faceVertexCounts, provided normals versus missing normals; source path and nearest entity context. Output is per-occurrence expressId/optional ifcType, Float32 positions/normals, Uint32 indices, RGBA color, optional per-vertex UV and texture. There are no current mesh material-subset/PBR shader/face-varying-normal semantics to invent from the type declaration. Standard gltf::material opinions survive composition but the recorded PBR overlay changes no emitted mesh color.
* **Traversal/occurrences:** Existing seed selection includes disconnected cycle components; accumulated output is path-scoped, preserving shared type instances and multiple parents. Nearest entity context and inherited Type-definition state matter. Mesh output deduplicates by node path, entity ID, accumulated transform and resolved color, canonicalizing explicit identity to absent transform. Equal absent default-color versus explicit default-valued color still have different key tags. Point clouds do **not** have that mesh emitted set and must not inherit its dedup rule. Native InstanceRecord is not currently emitted by this importer; source sharing can be internal without changing the baked public output.
* **Presentation/assets:** Preserve closest-lineage diffuse+opacity resolution, visibility override behavior, default gray, type exclusion, and current image extension admission point. decodeIfcxAppearance and createIfcxImageDecoder own UV/image validation, aggregate allocation budget, once-per-image caching, straight-alpha top-down RGBA8, original encoded image bytes/mime and repeatS/repeatT. Preserve original image references and byte sharing once per imported scene; do not clone images per occurrence or re-encode them. Existing numeric/material limitations are not broad USD shader support.
* **Frames/georeference:** Current import assumes IFCX native Z-up and converts to viewer `(x,z,-y)` after world transform. Header/type API exposes no metersPerUnit/upAxis interpretation; do not add an implicit scale or georeference bake. The current IfcProjectedCRS/IfcMapConversion extension is separately extracted, validated and forwarded to datastore metadata, including conflict refusal. Viewer coordinateInfo comes from output bounds; normal IFCX meshes have no native RTC/local_to_world/instance metadata fields. Retain original local source and f64 frames internally without silently changing the presented frame.
* **Points:** Keep pcd::base64, points::array, points::base64 selection precedence, colors, count and final bbox. Current @pointcloud decoders return f32 source chunks; inline JSON coordinates narrow in decodePointsArray before IFCX placement. Full source-before-narrowing point ownership therefore needs a raw decoded-column/inline-source seam before that cast, not a claim that an already-decoded chunk recovers f64. Existing PCD/base64/JSON codec authority may remain the format adapter, while Rust owns numeric conversion/placement/bounds. No Rust PCD/pointcloud codec already exists in this tree to invoke blindly.

## Smallest coherent Rust program replacement

Implement one `ImportedGeometryProgram` in a new `rust/geometry/src/imported/` module, consumed through a thin processing scene owner and wasm bindings. It is a source-independent input variant, not an IfcType registry entry. Reuse the common request identity/resource/error conventions, without modifying the active STEP inner-program or retained SDK implementation.

Concrete ownership:

1. **ImportedModelStore** owns one immutable composed-graph revision and source-definition/asset tables. TS composition adapter retains semantic metadata tables; Rust's graph input owns ordered node/edge/path IDs and the geometry-relevant source facts. Do not clone the whole composed attribute graph/properties per product. Distinguish stable source node/definition IDs from traversal occurrence IDs and output synthetic entity IDs.
2. **ImportedGeometryProgram** owns two ordered passes, MeshTraversal then PointTraversal, occurrence/path stack, source definition references, inherited context/visibility/presentation, raw local matrices and current arithmetic-stage matrices, emitted mesh keys, pending source request and output slots. No borrowed JS typed-array view/decoder/callback/RefCell guard survives a poll. Walk iterative with the existing path semantics; work/resource refusals are terminal and reported, not empty imported success. Do not introduce a small arbitrary truncation cap to make the graph convenient.
3. **SourceAdmission** is authenticated by model/store/revision/request identity. It requests reached frame/header, then eligible mesh source, then image/presentation source at the original reached stage; the point pass requests its chosen codec payload. Own original f64 point/matrix/normal/UV coefficients before numerical work. Avoid eagerly decoding images or validating a hidden/unreached mesh, which would move exceptions and consume budgets before the old path. Existing entire-file JSON/composition admission stays in the original host.
4. **ReadyOperation** variants own `Mesh { definition, original_topology, source_normals, transform_chain, display_contract }` and `Points { definition, precision/encoding, colors, transform_chain, display_contract }`. They contain no raw source bundle or live host references. Concrete numerical work performs fan triangulation/position transform/normal work/point transform/bounds, not a callback that invokes old TS extractGeometry wholesale. A Ready can be executed after the source adapter/model buffers are released.
5. **Completion/assembly** validates exact issued identity before attaching arrays, appearance or output. Presentation retains the derived asset handle/pixels/wraps and color, not full model authority. Produce the existing importer MeshData/PointCloudExtraction shapes in their existing order; convertIfcxMeshes/buildIfcxDataStore/coordinateInfo publication continue consuming that result. Copy WASM getters once and free every owned handle with try/finally, including abandoned iteration, error and stale load. No JS view may outlive memory growth/free. Whole scene publication remains after complete importer success, with original overlay rollback preserved.

Preserve numeric compatibility as an explicit display contract while retaining f64 originals: cast local matrices to f32, multiply cells in the original row-major child*parent order with f64 accumulation and f32 result assignment per stage, apply per-point homogeneous divide and the exact existing threshold/error, then axis conversion and f32 positions. Fan triangulate with the same order. Provided normals use the same f32 inverse-transpose matrix, singular/nonfinite fallback and renormalization. Missing normals are computed from already narrowed displayed positions, accumulating through f32 **after every addition**, then normalizing. Do not replace that with f64 accumulation or generic Mesh::compute_normals and claim equality. Explicit precision improvements require separate geometric/scene evidence, not this ownership migration.

Mesh dedup key construction currently uses JS Number-to-string/join behavior. A Rust tuple key must not silently change negative-zero, explicit identity/default presentation or formatting/collision semantics. Preserve the adapter's exact identity-string formatting at an explicit source/identity admission boundary, or qualify a precise equivalent JS-number formatting implementation. This is identity serialization, not keeping a second numeric geometry engine.

Point operations retain their distinct current matrix chain and f32-before-transform input behavior where the codec itself defines f32. To claim original inline/float64 PCD source ownership, factor the existing codec's raw field/number decoding from f32 numeric emission and pass those original columns to Rust, which performs the compatible narrowing stage. Public codec helpers outside IFCX retain their own current contracts; they are not automatically ported by an IFCX-only program. Mesh every-vertex w rejection and point extractor first-point-only w validation are different existing behaviors; a safety correction must be explicit rather than silently introduced under compatibility.

* `packages/ifcx/src/imported-source.ts` and prepared Rust executor adapter package dependency/entry. Replace numerical bodies in geometry-extractor.ts and pointcloud-extractor.ts; delete orphan geometry-normals.ts and duplicate matrix/transform/triangulation loops in the same change after all consumers use Rust. Keep composition/presentation resolution authority in the existing format adapter, not a second Rust composer.
* Both phase5 call sites in index.ts must consume the same program; incremental overlay finalizer may need to become async and callers must **await inside its try** so failed Rust work still rolls back addedLayerId. Public parse functions are already async; their return shapes and source authority stay.
* Add the raw point codec handoff in @pointcloud only where needed to prevent premature narrowing; retain existing actual codec behavior, byte-order/colors/error selection. Do not claim source precision from the current decoded Float32Array seam.
* Viewer ingest/loadFile remains the load owner; separately bring the existing layered helper into it through prepared-source input, preserving all existing layer publication behavior. No parse-to-Rust-to-STEP detour and no new upload path.
* Generated wasm d.ts must come from the canonical build script. New published dependencies/API changes need matching guides, changeset/API snapshot and actual consumer tests. No unused export solely to expose a planned seam.

## Synchronous package compatibility is a real decision gate

@ifc-lite/ifcx is currently wasm-free and its exported sync extractors work without initialization. Passing a prepared Rust executor to the browser is a sound consumed adapter, but by itself does not preserve those no-setup standalone calls. Async parse functions can await backend preparation, yet changing extractGeometry to Promise or failing it until async init is a public API behavior change. The existing @geometry IfcLiteBridge requires async init and a full engine; importing it does not solve direct sync extraction or wasm-free package compatibility. The inspected package manifests do not establish a dependency cycle here; the concrete blocker is initialization/runtime behavior, not an invented cycle.

A mechanically coherent no-handwritten-fallback option is a **small generated synchronous WebAssembly artifact** compiled from the exact same imported Rust program/math, with embedded bytes and a minimal sync ABI instantiated synchronously/lazily on the first extractor call. The canonical full wasm build and this artifact share the Rust implementation; there is one algorithm and no TS numerical fallback. Browser/Node ESM consumers need no fetch, filesystem, top-level await or init call for sync extraction. Prepared browser execution may supply its already initialized Rust executor only if it implements the same program/contract. This is a proposed packaging implementation, not an available artifact: it needs a reproducible canonical generation step, committed/distributed asset policy, ABI/version pin, build/type/runtime wiring, CSP/target support and size/startup/memory measurements. It cannot be supplied by hand-editing wasm/pkg artifacts or embedding an unqualified stale binary.

If no such artifact/support policy is acceptable, the honest alternative is a versioned initialization/API decision with migration guidance. A supplied backend plus unchanged TS default numeric fallback is an intermediate browser-only experiment, **not** complete global Rust ownership and not an acceptable completed replacement. A no-WebAssembly host that presently runs the JS extractor is an additional compatibility limit: a mandatory Rust-WASM implementation cannot preserve that environment without a different generated Rust execution target or explicit support/API decision. This constraint must be decided before broad package activation, not hidden behind optional callbacks.

## Qualification using actual hosts and corpus

The existing importer comparator invokes parseIfcx, parseFederatedIfcx and addIfcxOverlay and captures tables/getters/strings/relationships/hierarchy/paths/composed attributes/edges, meshes/points/georef. Reuse its schema and exact typed-array/scalar-bit evidence on base/candidate; do not rerun STEP geometry as an IFCX substitute. Seven catalogued IFCX files from its receipt are locally present: Hello Wall + FireRating, Domestic Hot Water + PBR, georeferenced bridge, PCERT architecture, and Point Cloud. Read-only presence is not a new hash verification or successful execution. Fetch any absent additions through pnpm fixtures and skip with that instruction. Historical receipts observed zero UV/image/georef channels on these samples; equal absence cannot qualify them.

Meaningful additional real-host invariants:

* Actual public sync extractGeometry/extractPointClouds calls from a fresh Node ESM realm without init; actual async parse and built package dist Hello Wall verification; real browser worker/main-thread artifact loading/CSP, with no TS numeric fallback path.
* Existing source tests for disconnected cycles, multi-parent alias dedup, explicit identity, inherited shared types, different presentation and sheared/nonuniform-scale normals against independent perpendicularity; add mirrored/projective/far-origin/scalar-rounding and provided/missing-normal order cases. Use nonempty real source outputs and compare original f64 source facts separately from displayed typed buffers.
* Existing importer full/incremental layer equality, FireRating property, PBR opinions, null masks/tombstones, failed-overlay rollback including Rust/asset failure, and exact path/layer/data-table preservation.
* Actual texture extension roundtrip from real encoded/pixel source resources through current writer/parser: require nonzero UV/image/original-encoded bytes, attachment/wraps and byte identity. Georeference extension tests must observe actual returned metadata; the bridge filename alone is no witness.
* Points: actual PCD/base64/inline cases and source precision tags, nonempty RGB/count/bbox, nonidentity lineage, repeated parent paths and type/invisibility, point-only file valid with zero meshes. Do not apply mesh alias suppression or omit points in composed loads.
* Mount the actual load hook for primary and federated targets with registry selection/ID ranges, point-only and geometry-less overlay error, stale parse/execute/assembly rejection, metadata-only allowEmptyGeometry, error retry and deterministic WASM disposal. Existing ifcxStaleGuard, federatedIdOffset and ifcxBuffers tests supply host wiring patterns; mocked Rust geometry is not numerical qualification.

USD export is currently `IfcAPI.exportUsd -> rust/export::export_usd(content)` over STEP bytes. Its actual stage consumer/roundtrip receipts are useful, but this importer replacement does not create IFCX-to-USD or retained-surface USD support. A later scene-export entry should consume the same qualified definitions/occurrences/presentation, with no JSON reloader and explicit Z-up/metres/texture/metadata semantics. Native USD reference sharing is distinct from native USD instances.

Completion requires superseded TS math deleted, all importer entry consumers using the owned program, sync/package/runtime decision resolved, canonical layered-load ownership resolved, actual complete-scene and host/WASM tests, paired end-to-end timing/memory and default/exact/other-consumer checks. This brief provides the next concrete replacement; none of those gates is claimed complete today.
