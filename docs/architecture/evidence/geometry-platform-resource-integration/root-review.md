## Corrected: unrelated ambient terminal could override actual source ancestry

The core SourceStopHandle already traversed ancestry oldest-first. But resource::stop normalized through that handle and then returned TERMINAL's previous first record, which could be an unrelated worker's A. check_current checked worker CURRENT before source. source_scope's prior_stop ran after installing the source handle but before selecting the actual source account, so it could inject worker A into the source. Its surrounding with_source_stop post-run check occurred after CURRENT restored the unrelated worker account, creating an exit-time contamination path even for successful actual source work.

Corrections:

- with_source_stop now scopes/restores TERMINAL alongside SOURCE_STOP. It transfers no kernel, diagnostics, census, numerical or other TLS.
- source_scope selects the actual validated source account before checking/normalizing its status and checks again before restoring worker CURRENT. It no longer interprets foreign CURRENT as an actual-source prior fault.
- check_current observes an existing source-ancestor fault first. stop retains each account's own established first fault, then returns the source chain's authoritative fault within the source terminal domain. Outside such a domain, ordinary first-fault terminal behavior is unchanged.
- with_source_stop does not account-check after its operation has already restored foreign CURRENT. Consumers capture stop while inside their actual owner work; ProductState now retains it across the restoration.

The source epoch remains data attached to existing validated leases. No stopped/expired handle gains source/router admission; no new lease bypass is added. Existing same-source first-fault ancestry is retained, while unrelated worker terminal state restores on success/error/unwind.
