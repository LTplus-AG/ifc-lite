## Concrete resource-ownership gap

`RetainedProductExecution`, `PendingRetainedTransaction` (`session_retained.rs:53-81`) and `IssuedCommonConstruction` retain no execution account or persistent resource-terminal capability. `ProductState::validate_retained_resources` (`session.rs:243-249`) restores `Scopes` and calls `resource::check_current`, but those scopes contain only kernel budget, degenerates and pending diagnostics (`session_state.rs`). `ProductOwner::read_work` publishes a source resource context from the account that happens to be current during that new synchronous call. It does not retrieve the original issuance account.

Consequently, the following real public sequence can bypass an original account's cancellation, despite the delivery README saying the acceptor checks captured lexical resource stops:

1. Create the actual bound decoder/router/context and `RetainedProductExecution` inside a bounded `account.scope`.
2. Call `issue_next` inside that scope, then leave it. Complete the issued native construction normally.
3. Cancel the original account while the transaction is dormant.
4. Call `execution.accept(receipt, decoder, router)` outside that account scope, or under an unrelated fresh account.

The ticket, source, owner, frame and object checks still pass. The new resource-check work scope sees no original account, `self.terminal` has not observed its cancellation, and `accept_admission` likewise sees the new ambient domain. The original reply can therefore be consumed and the logical slot discharged. Cancellation before `IssuedCommonConstruction::execute` also has no original-account check in that issued work. This is a concrete missing boundary, separate from the acknowledged absence of full heap accounting. It does not affect the permanent ordinary exact path.

Correction: capture the actual selected execution account/terminal authority as owned data at admission and carry it through pending/issued work, reinstalling it only for short synchronous slices. Check it before actual numerical invocation and before the first accept take. An unrelated caller TLS account must not replace it. Preserve foreign-ticket rejection before any retirement authority and preserve intact work on refusal. If resource ownership is deferred, explicitly refuse accounted retained handoff instead of accepting it under an ambient replacement, and remove the claimed captured-stop guarantee. No TLS/RefCell/owner-work guard should be stored across execution. A resource-qualified process heap claim is still out of scope.

Required distinguishing fixture: issue a real construction under account A, leave scope, complete the actual SDK operation, cancel A, then accept outside A and under fresh B. Both must refuse before original reply consumption, leave the same pending reply intact, and discharge zero slots. A healthy-A control must succeed. Repeat cancellation before execute with an actual SDK invocation witness showing no command reached. Existing seven SDK-dependent fixtures contain no execution-account case and do not test this path. This fixture has not been executed during review.

## Authentication and ownership checks verified

`session_retained/entry.rs` requires a model-bound context and validates the decoder using the actual `SourceBundle` or explicitly trusted source inputs. It acquires the real paired `ProductOwner`, calls `decoder.decode_by_id(job.id)` inside that owner's synchronous work, and constructs the canonical job using that actual entity. Caller-supplied root attributes are discarded; the caller's ID/type must agree. Planning runs under the same retained reservation and decoder provenance is checked again afterwards. This is stronger than accepting a matching caller entity ID as source authority.

The called `SourceBundle::owns_decoder` checks private bundle Arc identity and unchanged cache provenance. Context lifecycle checks actual source epoch; `ProductOwner::validate` checks actual decoder/router instances, generations and reservation IDs. `validate_reply` checks the executor protocol's original outer request, contextual emitter, captured actual registry tokens, payload tag and nested program reply. No mutable external work packet can substitute the runtime's original engine reply in the native wrapper.

The new logical value is genuinely distinct from a mesh: original analytic source coefficients are captured before the sampled constructor path, lowered to an owned recipe, and associated with a fresh common program occurrence slot. Repeated STEP IDs create distinct child program identities. `ItemValue::Retained` cannot pass through exact `into_mesh`; ordinary ProductState execute/accept reject retained contracts. The original engine-produced nested reply stays held by processing until its sealed runtime discharge succeeds. The actual common product iterator then consumes those logical values rather than receiving a fabricated mesh.

For native acceptance, ticket Arc identity and stage Arc/state precede source-expiry cleanup. A foreign receiver cannot retire the supplied receipt's runtime. Captured context, original outer/common request and owner stamp are compared before consulting the engine reply. `RetainedRequest::same_admission` compares document, revision, definition, worker incarnation and immutable recipe Arc identity. The sealed realization's actual process/object liveness is checked; worker.release invalidates the object's tracked liveness. The private expected f64 forward/inverse frames are compared to the sealed completion. Ledger duplicates are checked by logical slot, and ledger capacity is reserved before changing the linear pending state.

Only after these checks does acceptance CAS DELIVERED to ACCEPTING and take the original reply. A protocol rejection restores the reply and delivery stage where cancellation has not superseded it. A racing cancellation cannot be overwritten by the final ACCEPTED CAS; retirement invalidates the entire captured worker/ledger. This is a commit-admission linearization point, not a promise that the worker remains live forever after successful acceptance.

## Lexical scopes, errors and cleanup

Source admission returns after `ProductOwner::work` closes its live work epoch, source-borrow publication, diagnostic scopes and triangle-order guard. The reservation persists, but no decoder borrow or TLS guard is transported in issued work. Native execute takes only its issued immutable request, the selected worker and numerical controls; the pending reply remains executor-held. This source currently has no browser await implementation; native lexical correctness does not qualify one.

Independent cancellation carries the captured RuntimeOwner plus atomic stage. It retires that actual process, without discovering a replacement from a numeric PID. Executor drop cancels pending work; completed receipt drop retires its captured owner. Foreign rejection returns ownership of the original receipt, so eventual caller-driven drop is distinct from the receiver itself retiring it. Issued work is linear: failed/wrong-worker execution consumes it and leaves its pending executor terminal/outstanding until cancellation/drop; it does not replay or switch to exact work. Dropping only the issued object is not currently an automatic executor cancellation API and should be documented/tested as such.

## Fixture weaknesses and limits

All twelve new behavioral fixtures are unrun; seven return early unless `IFCLITE_SMLIB_WORKER` is configured. Source parsing/guard receipts do not establish type correctness, numerical execution or this review's resource invariant.

The foreign-expired-receiver fixture currently uses a receiver with no pending transaction. It proves the no-pending rejection path, but should additionally use two independently pending real transactions to exercise mismatched nonempty Arc tickets, preserving both originals. The wrong-admission fixture mutates private expected state and uses a second real SDK result, which is useful; it does not cover every outer request/common identity/context generation/frame alteration. The source-root test proves edited caller attributes are ignored through actual source admission, not merely by inspecting strings. Add real source swap/cache-authority revocation and router/decoder generation changes during dormancy with receipt-return/no-foreign-retirement witnesses. Pending cancellation during actual runtime work, issued drop, error cleanup and source/account isolation also need execution evidence.

The construction checkpoint remains incomplete. Full mapped occurrence DAGs, ordered Boolean/opening operand continuations, common rigid occurrence transforms, browser consuming transactions and final late appearance/publication are missing. A returned `RetainedProductPlan` is inspection of logical traversal with explicit remaining placement/opening/layer/appearance/persistent-face requirements. It is not final product geometry or source-only display assembly. Default exact evaluation remains separate and permanent; refused retained constructors do not fall back to it. No cross-target equivalence, scene preservation, full resource coverage, performance, final compilation, or browser qualification is established by this report.
