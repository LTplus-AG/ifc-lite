## Actual correction

OwnedResourceContext owns an OptionalAccount, the SourceStopHandle captured
inside the actual reserved ProductOwner work, and a shared first-fault cell.
There is no source/model allocation or decoder/router execution capability in it.
Each with_scope installs exact captured CURRENT/SOURCE_STOP/TERMINAL and restores
ambient channels on normal/error/unwind paths, including explicit originalNone.
An opt-in owned stop observer retains stops from fresh nested actual core work
epochs before their normal TLS restoration. Ordinary account scope/source_scope
implementations and the default exact contract are unchanged. Without a new
owned scope the stop observer is empty and preserves original stop selection.

Retained constructor entry first validates SourceBundle/context provenance, then
uses the existing canonical with_source_resources adapter so an actual borrowed
source account takes precedence over unrelated worker TLS. It retains strict
paired owner reservation semantics; this does not authorize an escaping retained
child under a busy ancestor. After actual owner admission it checks preexisting
Compatibility terminals before a fresh work epoch could erase them. It captures
inside validated owner work, charges reached root work, and checks the captured
resource state after planning.

issue_next validates source/actual owner before installing capture, checks it
before every reached step, charges reached work, and checks immediately after
execute_admission and again before an issued operation escapes. A logical
operation accompanied by a stopped GeometryStep cannot become SDK work.
Issued work owns a clone of the resource-only context, validates source and actual
runtime identity before its resource scope, and checks/charges before SDK entry.
After an SDK result, source validation and captured resource checks precede
DELIVERED. Resource stop retires that captured runtime and returns the actual
ProgramStop as RetainedExecutionError::Stopped, without selecting exact work.

Acceptance checks the intact foreign-ticket/source/owner/frame/object boundary
before installing resource authority. It refuses a captured stop before growth
or the first reply take. Actual ledger header backing is preflighted under the
original account, with fallible growth even in unaccounted mode. Its admitted
backing remains charged beside the owner until destruction; rejection does not
refund storage that actually grew. A final captured stop check precedes the
DELIVERED-to-ACCEPTING transition and reply take. Explicit cancellation still
performs report/claim cleanup under the original lexical domain after validation.

This is deterministic reached-work and known-header accounting only. Source
coefficient collections, SDK/process heap, numerical scratch, bookkeeping and
presentation allocations remain incomplete/opaque. No heap/RSS/resource-qualified
product or final publication claim is introduced. No live TLS/RefCell/work guard
is retained in the execution or issued numerical packet.
