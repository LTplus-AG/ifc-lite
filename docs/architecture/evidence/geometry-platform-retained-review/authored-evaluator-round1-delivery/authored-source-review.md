## Concrete remaining identity/authority gaps

Current root `ProductionModel::invalidate_source()` and `OwnedMeshProductionContext::validate_source/validate_decoder()` have no relationship to this document. A source factory/model invalidation therefore cannot expire it. This is a real integration gap before owned production admission, not a demonstrated wrong rectangle result in the opt-in snapshot contract.

   Minimal distinguishing invariant: admit from a model-owned plan, prepare, explicitly invalidate that ProductionModel source, then publish an otherwise valid old completion. The current API has no model-bound check that could refuse it. Future model integration must reject before mesh/document publication, while an independently retained historical snapshot may remain valid only under an explicit historical-snapshot contract.

   Bind once per model/load to the existing SourceBundle and ProductionContext identity/lifecycle; validate at admission and publication. Do not build a second source index, infer authority from a digest, clone source bytes per product or attach the whole source owner to decoder-free numerical/display payloads. Existing raw-byte `plan_authored_geometry` is a pre-existing standalone analytic adapter and constructs a fresh index/hash on invocation; calling it per product would re-scan/re-hash the file. The model-owned planning entry should reuse the already authenticated factory/decoder and build/cache definitions once under the model revision, preserving duplicate/prewarm/trusted-input policy.

2. **Completion validation authenticates request bookkeeping, not numerical result origin.** `retained.rs:88-108` exposes a public completion constructor and mutable tessellation, and `:212-237` validates document/revision/definition/incarnation values and expected frames. It does not bind the packet to a worker-issued result or the independent BRep handle. A caller can construct a completion from a valid request and any nonempty structurally valid closed-looking tessellation using the expected frames, and publish it. This may be acceptable for a caller-trusted local geometry-document adapter; it cannot be described as authenticated worker-result provenance at an untrusted reply boundary.

   Minimal distinguishing invariant: retain a valid request/frame, substitute a different valid mesh, and observe that request/frame validation alone cannot detect substitution. Production integration needs an executor-held issued-result identity and exact expected packet/handle binding before accepting a transported completion. Preserve returned packet ownership on rejection. The consumer must obtain current worker liveness from the runtime owner rather than a stale caller-supplied nonzero integer. Runtime-controller cleanup/liveness changes are owned by the other reviewers; this review does not duplicate their implementation.

3. **The full curve/profile evaluator is not present behind the refusals.** `retained.rs:258-275` refuses multiple/inner loops, circles and every non-rectangle profile. The C++ recipe requires one outer loop and supports line polygons or an isolated full circle only. Simply widening these checks would admit data that the actual builder and provenance do not implement. Preserve all these refusals until their mechanisms and positive SDK witnesses exist.

## Specific correction boundary for the next integration round

Preserve the current standalone constructors as explicitly **host-trusted** adapters if that is the intended public contract. `RetainedCompletion::new` is needed across the geometry/runtime crate boundary and is not inherently a vulnerability in a caller-trusted library. Likewise mutable numerical buffers can be useful for explicit host assembly. The concrete problem is advertising their validation as runtime authentication or accepting them as authenticated ProductProgram replies without a separate executor-owned barrier. The delivery documents caller-supplied live incarnation, but its broad “identity validation” phrasing must stay limited to request bookkeeping; it currently provides no origin seal for result buffers.

A concrete model binding can remain in processing without coupling geometry to processing or retaining raw source in numerical payloads:

1. Add an opaque model-owned authored-plan/admission entry next to `authored_geometry/planning.rs` and `evaluator.rs`, consumed by the actual model-owned ProductProgram source command. It receives the existing authenticated `OwnedMeshProductionContext` and leased decoder, calls `context.validate_decoder()` before reached IFC extraction, and owns/caches the resulting plan once at the model revision. Do not grant this authority merely by wrapping a caller-created public `AuthoredGeometryPlan` whose fields can be changed. Keep the existing raw-byte public planner as explicitly standalone source analysis.
2. Extract a narrow lifecycle token from the existing model state: a copied load/source-epoch/context-revision stamp plus an opaque `Arc` of the small revision state. It must preserve the existing rule that dropping ProductionModel alone does not invalidate snapshots, while explicit `invalidate_source()` does. This token must contain neither SourceBundle, bytes nor appearance maps. The processing authored-document owner keeps it and validates it at source admission, request issue and completion acceptance. The existing SourceBundle remains solely in the model/source store; source-read commands validate the actual decoder against that owner. Revision/context identity is checked by the outer request owner, not inferred from digest or IFC entity IDs.
3. Keep the geometry document/request numerical types independent: they own source coefficients, local f64 frames and copied opaque stamps. A `Ready` packet does not need the whole OwnedMeshProductionContext. A model-bound processing `publish_source` performs source-token validation before calling the geometry document's host-trusted publication method. An explicit standalone historical document can retain its existing snapshot contract; the canonical path must not silently select that weaker contract.
4. Issue retained work through an executor-owned pending slot keyed by full request/session/sequence/definition/revision plus opaque runtime incarnation identity. On delivery, validate the actual runtime owner remains live and that the completion is exactly the one issued for that slot (including its worker-affine BRep realization). Keep the expected result in the executor-owned store or use a sealed completion receipt whose issuance is controlled by the runtime owner. Do not treat `RetainedCompletion::new` plus a caller integer as the seal. The outer work boundary already has a pattern for expected issued replies; use that barrier and return wrong packets intact before display assembly. Numerical Ready payloads carry the copied identity/receipt and owned arrays, not source/model authority.
5. On accepted completion, retain the runtime resource owner separately from shared occurrence definitions. Cancellation, undelivered result or owner death releases/invalidates the handle through that owner; the immutable source recipe remains available for an explicitly requested replay. No spontaneous replay or exact-engine switch is permitted.

Focused invariants for this correction are (a) actual bound plan admission, then explicit model invalidation, rejects old completion before publication; (b) source replacement or same bytes in a different load cannot manufacture matching authority; (c) a forged/substituted host-created completion cannot enter the authenticated reply slot, while an explicitly host-trusted standalone document can still accept its documented input; (d) dropping source/model context after numerical admission does not keep source bytes alive through the numerical packet, while the small lifecycle token still observes explicit invalidation; (e) caller mutation of a public plan does not acquire a canonical model binding. These are integration tests to add, not executed results.
