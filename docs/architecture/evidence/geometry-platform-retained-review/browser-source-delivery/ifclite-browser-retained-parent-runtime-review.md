## Concrete blockers at this pin

**P1: foreign publication validation can retire an unrelated live Worker.** In `processing/src/authored_geometry/bound_browser.rs`, `validate_browser_publication` checks the receiving document's lifecycle first. If that lifecycle expired, it calls `publication.work.realization.retire()` before authenticating that the publication was issued/published by this document. A Rust caller can keep valid publication B, invalidate model/document A, and pass `&publication_b` to `document_a.validate_browser_publication`. A then retires B's actual owner. `accept_browser` correctly authenticates its private ticket before lifecycle retirement; this later validator bypasses that ordering. The eventual mesh-handle lookup is too late.

Repair: authenticate an immutable publishing-document/publication identity before granting retirement or mutation authority. Do not depend solely on caller-editable definition/product/occurrence fields; PublishedBrowserSource currently exposes all of those plus work publicly. Seal the fields needed for ownership, preserve read-only getters for actual consumers, and check document identity before source-expiry retirement. Add a genuine browser/source test with two model lifecycles: expired A must reject B without retiring its Worker or changing either document, while B remains displayable. The parent states the owner is hardening this area after the pin; this report does not presume that repair exists.

**P2: the browser gate opens curved rational pipe consumption without a curved rational numerical witness.** `RetainedDriver.qualify()` sets one private #qualified after runSweepContract; both OrderedRegion and RationalDisk require that same flag in driver and Rust bridge. At this pin runSweepContract has only one format2 case, rational-straight-pipe: degree1 with two controls. regionWitnesses contains format1 line/circle/arc profile recipes, not a curved rational directrix pipe. A degree2 curved RationalDisk source therefore executes after a witness set that never exercised that curved pipe producer. Native qualify_rational_disks explicitly runs both straight and curved weighted rational cases, so the target qualification requirement is materially weaker in the browser.

Repair: before opening the rational gate, run an actual same-Worker curved rational pipe upload with independent positive volume/manifold and meaningful tessellation/shape invariants, plus deterministic cleanup; or keep that route explicitly refused behind a finer qualification state. No capability bit, caller flag or native receipt should substitute. Add bound browser execution of the actual curved rational source after qualification and refusal before qualification/replacement; do not count format1 circle extrusion as testing format2 curved pipe construction.

## Cancellation, startup and replacement

The InFlight guard is armed before the first await in polled Rust qualify/evaluate. Any error or dropped polled future retires its captured owner; success disarms only after actual owner/object validation and completion construction. The guard carries no borrowed TLS/decoder/RefCell state. A retired BrowserWorker cannot revive by a later successful Promise resolution: Rust owner.live stays false and JS driver checks #retired/current incarnation after awaits. On JavaScript retire, the object Map is cleared before transport retirement. Captured transport.retire compares exact frozen incarnation object, so stale cleanup cannot terminate a replacement.

Before dynamic import finishes, driver.retire sets #retired; the startup continuation checks it before allocating a Worker. Dropping BrowserWorker invokes owner retirement, so pending import cannot later create an orphan. A never-polled evaluate/qualify future has not called the driver or started numerical work; its borrowed BrowserWorker remains the legitimate owner. Dropping issued bound work releases its ticket strong reference; no private pending slot holds it alive. Do not describe that unpolled-future case as proof that all executor startup is cancelled: construction itself may already be importing assets and remains owned until executor retirement/drop.

A JavaScript Promise being ignored is also not Rust Future cancellation. wasm-bindgen's active Promise future can remain running, and active async mutable borrows constrain free/re-entry. Documentation correctly speaks about a dropped in-flight Rust future; an explicit public abort protocol is not implemented here and should not be implied.
