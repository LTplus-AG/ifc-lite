# Typed product work and executor ownership

The corrected typed synchronous boundary is qualified within the scope recorded
in [validation.json](validation.json), against the frozen
[source manifest](source-manifest.json). Earlier product receipts retain their
original source scope. Whole-platform cutover remains gated.

The [source overlay](source-overlay.json) retains all 226 exact qualified files
so this layer remains reproducible after subsequent working-tree edits. Apply its
archive over the pinned base in a separate clean checkout, then remove the listed
deleted source paths. Every archived file was checked against the frozen manifest.
Fixtures and built runtime artifacts remain separate inputs. New mapping-stage
edits are outside this receipt’s source scope.

The canonical producer now issues reached work tickets, executes existing
numerical builders under decoder/router reservations and validates numerical
replies before the existing presentation assembly. Tickets distinguish session,
sequence, strategy and type-map identity/class. Reply acceptance also checks
owner/configuration identity, payload variant, contextual dispatch tag and the
executor's recorded sparse registry-entry identities. Invalid replies return
their unconsumed packet. Duplicate execution is rejected before callbacks or
cache effects can repeat.

Pending thread-local curve caps, refused faces and legacy mapped CSG reports
are scoped independently of the caller. Original abandoned-primary and final
CSG drain points preserve processor grouping; full router diagnostics remain
under the exclusive executor owner. Optional scoped CSG census instrumentation
preserves the global aggregator and requires explicit context propagation to
worker threads. Registry-entry traces are ordered unique actual entries, not a
complete source log or a precision/authorship contract.

## Rejected initial qualification

The [initial boundary report](rejected-initial-boundary.json) records an actual
workspace failure: allocating shared owner state during every unused router
construction violated the existing zero-allocation invariant. The correction
must preserve that test by making reservation state lazy.

A separate baseline/branch probe proved another compatibility requirement. A
custom processor can synchronously produce a child product through the same
canonical producer and decoder/router, then resume its outer geometry. The
baseline produced the expected child and outer volumes; the first reserved
candidate rejected the child before construction. Lexical child admission must
preserve this extension while independent sibling sessions stay exclusive.
Trusted decoder cache clearing and unchanged unit reseeding inside callbacks
must likewise remain valid, while changes made to a waiting reply invalidate it.
These are required corrections, not exceptions to the no-loss objective.

The corrected implementation makes owner state lazy, commits reached callback
mutations only under live trusted ownership, and preserves synchronous canonical
children through all live ancestors. Matched source/router halves inherit lexical
authority; fresh halves reserve independently. Final diagnostic hooks preserve
the caller's restored triangle-order mode. Explicit joined-worker mutable-decoder
borrowing preserves the existing scoped-thread extension contract. Independent
resumable siblings and stale replies remain rejected.

## Remaining platform requirements

This boundary is private and synchronous. Full router diagnostic envelopes,
owned/versioned model context, finer source/mapping/opening commands, template
reservation/cancellation, remote reply epochs, complete retained-engine
integration and all-consumer/all-platform qualification remain open. Public
canonical nested calls must remain lexical; there is no asynchronous child
execution capability. The exact arithmetic kernel remains the default numerical
engine. The [work contract](../../geometry-platform-work-boundary.md) records
these implementation and preservation requirements.
