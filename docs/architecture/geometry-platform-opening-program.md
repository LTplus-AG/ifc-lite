# Geometry platform: opening operations

The canonical host-opening path now separates reached source classification
from numerical execution and consuming effect publication. This implementation
is **unqualified**: the combined source has not compiled or executed its geometry
tests. [Integration evidence](evidence/geometry-platform-openings-integration/integration.json)
records the delivered source, parent corrections and parse checks. Worker disk
admission refused heavy validation; syntax checks do not establish type safety
or preservation.

Classification retains requested opening occurrence IDs, repeated occurrences,
selected processor callbacks, quiet failure policy, frames and original reached
ordering. Numerical operations receive the placed host, admitted immutable cutter
context, quality and lazy numerical gate functions. They retain no decoder or
router. The current synchronous adapter borrows the cutter context only during
execution; a resumable driver must own that context and create the borrow
lexically, without retaining a borrowed operation across suspension.

Typed terminal outcomes propagate through classification, probes, geometric
routes, staged children, material parts and layer callers. A terminal outcome
must precede another fallback, source read or output publication. Successful
acceptance consumes the ordered effect log and detached telemetry. Failed
acceptance preserves reached root failure diagnostics and drops provisional cut,
consumed-host and success telemetry effects. A lexical failure guard drains the
actual root clipper on early exit; its normal finalizer drains the same buffer,
so the guard then has nothing to publish. Unaccepted speculative children retain
their own disposable logs.

New tests exercise lazy gate ordering, callback changes to unreached gates,
requested-ID attribution through a compatibility cache alias, real host cuts,
and cancellation after actual capped exact-kernel work. These assertions remain
unrun. Existing exact numerical algorithms remain the execution engine; no
alternative engine selection is introduced here.
