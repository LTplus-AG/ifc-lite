# Resource admission for accumulating geometry and ProductProgram

**Status: planned, not implemented.** This proposal complements the [common ProductProgram plan](geometry-platform-product-program.md). It specifies future resource accounting and typed terminal behavior; current model-context qualification does not prove these guarantees. Existing source, numerical and consumer behavior remains the compatibility baseline.

## Existing mechanisms and their actual scope

- `rust/core/src/limits.rs`: `MAX_MAPPED_ITEM_DEPTH = 32`, shared traversal contracts. Depth/path guards must remain unchanged on the compatibility path. They do not bound repeated occurrence expansion. A global visited set must never remove accumulating repeated geometry.
- `rust/geometry/src/router/mapping/merged.rs`: continuation frames own bulk-decoded `IntoIter<DecodedEntity>`, `SourceParts`, and returned mesh parts. Cache hit clones a cached mesh before `place`; child success merges each returned part; `finish` clones a single source into local/shared caches before placement. Shared publication excludes empty, exact-budget-tripped and truncated sources; local publication historically differs. Bounded execution must not accidentally change unlimited-path policy.
- `mapping/submeshes.rs`: ordered per-child return and transform, textured `plain` path, and accumulating output collection. `mapping/occurrence.rs` decides template eligibility/materialization and may publish materialized identity during admission; placeholder ensures shared source then appends metadata-only mesh. Count every placeholder/occurrence even when it has zero vertices. A bounded failed template must not leave a materialized marker falsely claiming a template exists.
- `router/frame_parts.rs`: `SourceParts::merge`/`FrameParts::merge` search prior frame buckets and copy into meshes. Charge frame comparisons as work as well as payload bytes. Different origins must retain current frame separation, order, bounds and RTC rules.
- `rust/geometry/src/mesh.rs::merge`: infallible `reserve` and extend for positions/normals/indices; `vertex_offset` narrows to u32 and adds unchecked indices. `merge_all` sums usize lengths unchecked. A bounded operation needs checked preflight before any buffer growth, offset cast or index addition; changing this legacy API globally is unnecessary for the first coherent bounded executor.
- `rust/geometry/src/construction/program.rs`: graph nodes/uses avoid repeated evaluation but `Evaluated::clone` copies mesh and diagnostics for remaining uses. Existing `MAX_DIAGNOSTIC_WORK = 65_536` bounds diagnostic copying only. Fresh builder evidence is deliberately retained before that copy charge. This is not a general memory reservation or mesh-copy bound.
- `rust/geometry/src/kernel/budget{,_state}.rs`: exact predicate escalation budgets, per operation and element, snapshot/restoration across polls. They preserve existing numerical fallback behavior. They are neither mesh-memory limits nor cancellation and must not be repurposed as admission currency. Keep kernel behavior unless caller explicitly chooses a separately specified fidelity policy.
- `rust/processing/src/appearance/{budget,transfer_budget,texture_budget}.rs`: checked aggregate point/corner/UV/item work, transfer work plus memory envelope, texture header preflight. Useful patterns: repeated maps charge repeated UV rows, image identities deduplicate actual decoded rasters, decoder+RGBA coexistence reserved before decode. Their fixed authoring limits are domain-specific, not suitable default global geometry limits.
- `apps/server/src/mem_policy.rs` and `admission{,_guard}.rs`: startup policy uses explicit memory budget or 70% of tighter readable cgroup/physical ceiling, byte-weighted upload admission, CPU/queue permits, RSS breaker, and resident-byte handoff. Reuse host policy/concurrency/RAII ownership; upload bytes remain a heuristic for geometry working set. Do not import server or Tokio dependencies into core. Browser must supply an explicit host budget; native `/proc` policy cannot be assumed there.
- `processor/request.rs` and `processor/mod.rs`: existing cancel flag is checked between chunks and returns partial results by public contract. New ProductProgram cancellation cannot silently reinterpret that API as all-or-nothing. Native jobs, browser batch/partition output, and appearance each retain additional output/template/raster/metadata allocations outside mapping; a mapping-only counter cannot qualify those consumers.

## Proposed policy and concrete ownership

Use `ExecutionPolicy::Compatibility` or `ExecutionPolicy::Bounded(ResourceLimits)` at the owned execution-model/session factory, not implicit process globals. Compatibility means no NEW mapping/product resource ceiling; all existing source guards, appearance limits and exact-kernel budgets remain. It does not mean literally unlimited process resources. Bounded limits are explicit nonzero or explicit-unlimited typed dimensions; zero is a real zero allowance, never a magic opt-out.

`ResourceLimits` has independent checked dimensions: cumulative work units, cumulative materialized/copy bytes, maximum live accounted bytes, output bytes/occurrences, retained cache bytes, diagnostic/evidence bytes, source/command slots, and in-flight command count. No arbitrary small default is introduced. Hosts select limits from measured deployment capacity and corpus qualification; receipts record effective policy and dimensions. A maximum single buffer/mesh vertex/index length also prevents wasm32/isize/u32 representation overflow irrespective of an unlimited policy.

The leased `ModelExecutionStore` owns a shared `ResourceLedger` and retained cache/template reservations. Each ProductProgram owns a child `ExecutionAccount`, cancellation view, ordered effects journal and terminal state. Its local deterministic work/copy/output allowance prevents another parallel product deciding whether this product crosses its intrinsic limit. A model/global live-memory gate controls concurrent resident reservations. Temporary lack of a global resident permit is backpressure (`WaitingForCapacity`), not a source fault; impossible-to-fit reservations or explicit queue/deadline policy cause a typed terminal refusal. Do not block while holding router/cache locks. Nested canonical calls share the parent's model residency pool and charge the owning request; they must not reset cumulative counters by creating fresh child sessions. Explicitly independent user models remain independently budgeted, so host-level aggregation is still required.

`Reservation` is an owned Send RAII handle, unique/non-Clone, tied to ledger/model/account identity and allocation class. Dropping releases live bytes/slots; transfer moves ownership into a reply/cache/output handle. Releasing live bytes never refunds cumulative work/copy/output charges. Arc payload sharing charges one retained allocation on its storage owner plus each reference/occurrence header, not the full payload per Arc clone. Deep cloning charges the full new payload every time. The ledger itself uses checked arithmetic and reserves its own bounded bookkeeping before admitting more handles; do not use one unbounded allocation record per vertex.

`Admission::prepare(Cost)` checks cancellation, all arithmetic, representation limits and quotas before allocating. It returns a permit covering work, peak requested storage and future publication class. `Cost` is computed from counts/capacities already available at the reached source/operation point. Unknown producer sizes require incremental chunk admission, a conservative proven upper bound, or an explicit unqualified extension boundary; estimating then allowing unbounded producer allocation is not a bound. Do not prewalk/decode later branches merely to estimate them: that would change lazy source/diagnostic order.

Bookkeeping reservation is not an allocator oracle. Name bytes as requested/accounted backing storage, with container/header and known simultaneous scratch allowances. Allocator metadata, rounding, fragmentation and library allocations are not exactly controlled by Vec capacity. For grow/reallocate, reserve the whole new requested allocation while old backing remains charged; after success release the old reservation and reconcile observable capacities. `try_reserve_exact` avoids geometric-growth requests but does not promise exact allocator consumption. A claim about actual allocator heap requires an instrumented/limiting allocator or bounded storage allocator covering every allocation; process RSS needs a separate OS isolation mechanism. Wasm memory can still abort on OOM outside these audited sites.

## Charge points and checked cost formulas

All usize/u64 products/sums use checked arithmetic before casts. For a mesh payload request: `4*(position_scalar_count + normal_scalar_count + index_count + uv_scalar_count)` plus owned mesh/part/occurrence headers, strings, attachments and other deep-owned vectors. Use actual lengths for copy work; backing capacities/requested capacities for live storage. A repeated source with k occurrences is charged k copies/merges/occurrences where materialized, even if source decode/evaluation is memoized once.

1. **Source frame / bulk decode:** reserve frame, item-list and diagnostic envelope space before `DecodedEntity::clone`, `resolve_ref_list` output, frame push and path-set growth. Decoder internals need incremental bounded decoding before this can claim source-allocation coverage; charging a fully decoded list afterward is too late. Preserve merged transform-before-cache and submesh representation-before-transform ordering.
2. **Cache hit:** acquire returned Arc under a short lock; release lock; calculate exact payload counts; charge clone/copy work and reserve destination before deep clone and bake. A cache hit is not free expansion. Cached geometry remains source-frame canonical; no uncharged post-cache cloning.
3. **Child merge:** before `SourceParts::merge`, reserve frame-bucket header and all target growth, charge comparisons, copied scalar/index operations and rebase/normal transforms. Check vertex offset + each index against u32; partial buffers cannot survive a refused merge as valid output. Keep first-compatible-frame and triangle order unchanged.
4. **Textured execution:** preflight decoded coordinates/PnIndex/index expansion/normal and UV seams before allocating their buffers; reserve source+destination coexistence during weld and UV splitting, including hash/index workspace. Reserve encoded raster, decoder scratch and RGBA coexistence from admitted headers; charge unique shared raster once but copied MeshTextureData pixel Vec per real copy. A URL string is not image resolution; GPU decode/upload is a separate consumer budget.
5. **Template/instance:** reserve canonical source payload, template cache entry, materialization marker and occurrence metadata before marking/publishing. Transfer cache reservation to the store only after complete validated source success at the original reached publication point. An instance saves geometry copies but still consumes one occurrence header, transform, style/metadata and wire/upload output. Missing/failed templates never receive a successful marker.
6. **Assembly:** preflight `OwnedJob` entity/metadata copies, normal rebuilding, weld/dedup, hash workspace, MeshData metadata/properties/string clones, layer/indexed-colour splits, fallback/type-map parts and texture conversion. Reserve original+replacement arrays while both exist. Charge splits by actual emitted corners/UVs, not original unique vertex count.
7. **Output/cache handoff:** a successful reply moves permits with payload; no clones of reservation ownership. Accept validates ticket, context/source epoch, runtime owner/emitter and fault status before assembly/publication. Finished product transfers output residency to consumer-owned lease. Native sinks/retained results, browser MeshCollection and JS getters, partition template buffers and appearance authored plans must retain/replace that lease through the actual handoff; dropping product state must not refund bytes while consumer copies remain resident. Existing public bare Vec return types cannot enforce external lifetimes; compatibility wrappers need documented boundary or a new owned result internally, without inventing hidden false process guarantees.
8. **Diagnostics/evidence:** bound fresh report count/bytes before copying/appending. Resource refusal reporting uses a fixed small terminal record requiring no expansion proportional to the refused request; reserve emergency diagnostic space at account creation. Preserve prior admitted source evidence once, ordered. Do not recursively multiply failed-occurrence diagnostics without charging. Existing construction fresh-evidence exception remains explicitly outside copy cap until migrated, never described as fully memory bounded.

## Typed terminal semantics and publication barriers

Introduce `ProgramStop::{ResourceRefused(ResourceFailure), Cancelled}` separately from `SourceFault`/ordinary geometry loss. `ResourceFailure` identifies dimension, operation/source/occurrence, requested/remaining counters and overflow/allocation-failure reason without owned unbounded source strings. Budget arithmetic overflow is refusal, not wrapping/unlimited. Cancellation remains sticky even if a later callback returns geometry. Poll boundaries and long audited loops check cancellation; it is cooperative, not a hard deadline.

`ProgramStep`/reply carry `Result<ReadyValue, ProgramStop>`; source operations can separately carry their historical recoverable source outcomes. First terminal stop poisons the attempt and prevents issue/accept/finish-success, retries, fallback geometry and cache/template publication derived from aborted work. Work/accept exactly-once validation prevents duplicate charges or double release. A duplicate request is rejected before allocation/producer invocation. Terminal report owns prior diagnostics and no publishable partial scene.

Existing swallowing points to bypass or refactor in the bounded lane:
- merged `AfterChild` Err -> `skipped` and continuation;
- submesh `plain` Err -> unsupported record;
- `element/session_work.rs`: plain `unwrap_or_default`, primary Err -> Retry, voided `.ok()`, type-map `.ok()?`;
- boolean/source fallback handlers, constructor graph generic geometry errors, host-opening retries and batch panic/error conversion.
A separate sticky account fault checked immediately on return from all compatibility callbacks is the minimum adapter when a `GeometryProcessor` cannot return typed ProgramStop. It prevents a terminal stop swallowed inside that synchronous call from producing success; it does not interrupt the call or bound its uninstrumented allocations. The program's own code must propagate typed stop directly. Never identify terminal stops by matching error strings.

Cache/effect atomicity has two scopes. A source entry is publishable only if that source completed without terminal stop and owns its cache reservation. A later refusal of another product branch must not retroactively erase previously reached, independently valid cache effects or reorder callbacks; current work semantics preserve effects at their reached execution point. Aborted/dependent incomplete entries and provisional materialization marks must roll back by RAII. If the host requires whole-product atomic cache visibility, implement a transaction overlay as a NEW declared policy and qualify diagnostic/cache reentry semantics; do not quietly defer existing effects until accept. Model-store immutable content-addressed completed cache entries can safely outlive a failed consumer provided their accounting remains owned.

Streaming is likewise not retractable. Strict product refusal produces an error, never a success with clipped geometry. Whole-model all-or-nothing delivery requires a staging/commit sink or protocol with explicit terminal failed status; already delivered prior independent product batches cannot be recalled. Current chunk cancellation's documented partial-return behavior remains compatible. Public new owned execution errors must preserve ResourceRefused/Cancelled through browser JsError/native/appearance error conversion, not silently empty success. Arbitrary custom extension side effects cannot be rolled back; bounded support must state which extensions are accounted and cancellation-cooperative.

## Concrete coherent implementation sequence

A. Shared policy/account/RAII permit and typed stop in core-neutral geometry execution support; explicit Compatibility default. Test checked arithmetic, exactly-once movement and sticky failure. No kernel replacement or change to existing numerical fallback policy.
B. ProductProgram mapping continuation with two audited consumers and occurrence/source caches, bounded decoder/item-list admission, accounted merge/texture/output helpers and provisional-template rollback. Preserve source request order, diagnostic checkpoints and path membership rules. Common work requests own permits through dormancy; no borrowed guards/locks cross replies. Integrate construction DAG take/clone and diagnostic evidence reservations as another consumer, not a separate drifting budget.
C. Processing acceptance/assembly and all native/browser/appearance adapters propagate typed stop and own output lifetimes. Instrument metadata/style/texture conversion and template/partition materialization, then expose bounded caller policy. Host server admission reuses deployment budget selection while reserving model resident permits in addition to upload bytes; browser records explicit supplied policy. Avoid claiming end-to-end bounded output before these adapters land.
D. Qualify accounted coverage and peak RSS separately. Kernel scratch/exact BigRational, decoder caches, profile tessellation, raster dependencies and custom processors remain explicit exclusions until allocated under a proven envelope/instrumented allocator. If any required producer cannot be bounded, refuse it in strict supported-mode admission with explicit capability reason before invoking it, or label that whole run resource-unqualified; never execute it and claim a hard bound. A future process supervisor can impose OS memory limits only with actual platform primitives; native pipe-transfer byte limits are not process RAM limits.

## Meaningful regression and qualification matrix

- Real shared mapped fixture with repeated operands at several depths: sufficient allowance gives identical ordered meshes, UV-position pairing, origins/local bounds/instance transforms, metadata and diagnostics vs compatibility. No global visited dedup and no low arbitrary default.
- An accumulating diamond DAG and duplicate role edges: one cached evaluation, every repeated copy/occurrence charged. Vary resident budget independently from cumulative copy/work. Refuse BEFORE clone/merge using an audited allocation/event probe, not state-set/readback. Large zero-geometry placeholders also exhaust occurrence allowance.
- Cache hit vs miss, local vs shared caches, frame-part splits, flat vs nested maps, both transform-admission orders: same geometry under admitted policy, terminal copy refusal before bake; no degraded source or poisoned marker later used as template. Complete independent prior cache entry remains valid and charged after later branch fails.
- UV seam expansion with nonidentity PnIndex and embedded raster header/coexistent buffer sizing: enough allowance exact scene parity; just-insufficient budget typed terminal, no white/untextured retry or fallback success.
- Merge near u32/usize/isize limits: pure preflight arithmetic tests exercise impossible lengths without allocating giant models; actual small geometry boundary test proves preflight governs real merge and ordered output.
- Cancellation before admission, awaiting reply, inside audited loop, immediately after callback, before accept, before cache commit and finish: one Cancelled terminal, intact rejected reply, no stale cache mark, no fallback callback, owner/reservation release. Scoped callback panic restores TLS/owners and drops reservations; retained outputs/cache entries keep residency.
- Interleaved/dormant/cross-thread sessions and lexical nested children: one shared model live ledger, no reset on resume/fresh nested session, no alias permits/double refunds. Shared pool exhaustion waits without cache locks, resumes when consumer drops output; explicit oversize stops without deadlock. Work quotas deterministic per product; scheduling-dependent live admission documented separately.
- SourceFault from malformed geometry retains exact current recovery/counters; identical text in an ordinary error cannot trigger ProgramStop. An extension intentionally catches an internal resource error still cannot cause bounded success (sticky fault), while an uninstrumented large allocation remains an explicit unsupported coverage case.
- Native streaming and browser/appearance integration: typed error visible to real caller; no partial current-product success, no valid final commit after Cancelled, no earlier stream retraction claim. Measure allocation high-water instrumentation and end-to-end native/WASM actual scene parity on the acquired texture/mapped/georef/opening corpus; heavy repeated-source model for resident/cumulative accounting, actual allocator/RSS separately reported.

Lifecycle token/context revision, runtime owner generation and authenticated source/index identity remain separate. Resource reservations bind to the execution account and actual accepted payload, not to a claim that ProductionContextId authenticates bytes. This design does not close that source-adapter prerequisite.
