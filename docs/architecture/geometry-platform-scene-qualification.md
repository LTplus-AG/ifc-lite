# Complete consumer-scene comparison plan

This is a qualification design grounded in the current tree and committed base API, not a completed comparison or a claim of universal fidelity. The initial audit changed no Rust source or build artifacts. The subsequent shared consumer harness lives in `tools/smlib-evaluation/scene-comparison`; its receipts qualify only the exercised consumer channels and fixtures.

## What the existing receipt proves

`rust/processing/examples/perf_probe/measurement.rs` calls `process_geometry`, then computes `perf_probe/fingerprint.rs::mesh_fingerprint` outside timing. Its ordered FNV includes express/item/material IDs, geometry class, position/normal/index buffers, RGBA, origin, local bounds and local-to-world. It explicitly excludes type names, textual metadata, material names, properties, UVs, textures and instancing. It does not fingerprint the returned frame, georeferencing, diagnostics, text/symbolic output, or streaming events. Equal existing hashes are useful numerical evidence, insufficient for a complete scene claim.

`MeshData` serialization is also insufficient: `instance`, `local_bounds` and `local_to_world` are `#[serde(skip)]`; symbolic NaN sentinels serialize as null. A JSON dump with sorted keys would lose information.

## One reusable consumer harness

Build a standalone qualification executable from ONE shared harness source against the pinned base and candidate libraries in their isolated targets. It consumes public APIs only; it changes no numerical implementation, injects no alternate processors, and does not copy production meshing logic. Keep its source digest, dependency lock, compiler/target/profile/features, exact base revision, candidate source manifest, source model digest, request settings, environment and worker count in each receipt. Direct rustc linkage to existing matching rlibs is possible (as the nested producer probes demonstrate); a small isolated consuming crate is easier for repeatable profiles. Harness compilation is not permission to rebuild either numerical tree differently.

The harness has a typed collector, one canonical structured writer and one offline comparator. It emits content-addressed records and a manifest with field names, capabilities, record counts and per-channel digests. On mismatch, compare actual field records and report first differing field/ordinal/float bits; retain raw records for inspection. Hashes accelerate comparison; they do not replace structured equality. A strong digest such as SHA-256 avoids relying exclusively on FNV collisions. This is pairwise base/candidate comparison, not new golden byte pins or a declaration that this harness encoding is a product wire contract.

Use the existing common `ProcessingRequest`/`ProcessingSink` and `process` APIs where both builds expose them. Both the committed base and current tree have `ProcessingResult` mesh/frame/instance metadata and the current `MeshData` field set. Their public canonical `produce_element_meshes` entry also remains available. Inspect the exact pinned base before compiling; do not assume another historical version has those APIs.

If an API differs, keep a tiny explicit adapter for that build that only invokes the equivalent entry and reads fields. Record support as Present/Unavailable with the actual API reason. Never substitute empty vectors, default frames, default colors or guessed metadata for an unavailable field. Common supported fields must compare; unavailable fields remain a qualification gap. Candidate-only construction reports are a separate additive channel, not a fabricated baseline equivalent. Keep both adapter sources and their diff in receipts.

### Execute these consumer modes

1. Full native STEP pass with properties and presentation layers enabled, default opening filtering, Medium quality, retained meshes, instancing disabled. This is the broad numerical/presentation baseline and current perf mode.
2. Streaming retained pass, same semantics, small fixed initial/throughput chunks, and again with `fast_first`; capture all sink events and returned result independently. Run with instancing off and on. Explicitly record disabled features and compare matching request modes only.
3. Symbolic extraction using `extract_symbolic_data_with_provenance_in_frame` and the ACTUAL returned `ProcessingResult.frame`; include its source provenance. STEP `ProcessingResult` has no text collection. A mesh-only harness cannot qualify annotations.
4. A targeted public canonical-element lane with identical real source/context setup for richer per-element hash and refusal evidence (see below). This supplements the end-to-end collector; it does not replace it.
5. Separate actual IFCX importer and USD/export consumer lanes. These use the same external comparison schema but their real host APIs, not `process_geometry` on JSON. They cannot be claimed from STEP-only evidence.

Start with one-thread and repeated independent-process base runs to establish reproducibility. Then repeat matching base/candidate native worker-pool configurations. Do not change request semantics, suppress diagnostics or disable features only on one side to obtain equality. Use real process completion/error status and bounded execution; a skipped, failed or partial run is never equivalent to a complete empty scene.

## Exhaustive collected fields

### Presented mesh records

Source: `rust/processing/src/types/mesh.rs::MeshData`. Record EVERY public field, with explicit option presence and sequence lengths:

- `express_id`, `ifc_type`, `global_id`, `name`, `presentation_layer`;
- `positions`, `normals`, `indices`, `color`;
- `material_name`, `geometry_item_id`, `material_id`, `properties`;
- `uvs`; texture presence plus `texture_id`, optional `rgba` bytes, `width`, `height`, optional verbatim `url`, `repeat_s`, `repeat_t`;
- `geometry_class`, `origin`, `local_bounds`, `local_to_world`;
- optional `instance` and ALL `InstanceMeta` fields from `rust/geometry/src/mesh.rs`: `transform`, `local_transform`, `canonical_transform`, `rep_identity`, `instanceable`.

UVs must remain attached to their actual vertex ordinals. Do not separately sort positions, normals, UVs or triangle indices. URL equality proves preservation of the reference, not successful image resolution. For external image consumers additionally compare resolved asset bytes/dimensions and the exact archive/path resolution result; a missing image is a recorded failure, not empty texture success. Sharing the same Arc allocation is not a scene contract, but its pixel content and dedup texture ID are.

Do not infer full material-definition fidelity from RGBA/`material_name`. The presented `ProcessingResult` exposes those fields and textures, not an exhaustive PBR/source material graph. If full property/material/source preservation is claimed, collect the actual `data_model::extract_data_model` output (`rust/processing/src/data_model/*`, including material associations) and the relevant real export/import payload as additional channels. Keep source facts distinct from presentation outcomes.

### Frame and model records

Source: `rust/processing/src/processor/mod.rs::ProcessingResult`, `mesh_frame.rs`, `types/response.rs`, `georeferencing.rs`.

Record `mesh_coordinate_space`; explicit `MeshFrame` variant and ALL payload (`SiteLocal.placement[16]`, `ModelRtc.anchor[3]`, or `RawIfc`); optional `site_transform` and `building_transform`; complete `ModelMetadata` including schema/entity/geometry-entity counts, `coordinate_info.origin_shift`, `is_geo_referenced`, optional `length_unit_scale`, `length_unit_refused`, and complete optional `Georeferencing`.

The latter includes CRS/datum/projection strings, eastings/northings/height, x-axis components, scale, axis factors, rotation, transform matrix, CRS description/map zone/unit/unit scale/source. Preserve snake_case names used by this existing Rust contract. Record frame bits before any world reconstruction. A secondary world reconstruction check may use the public frame methods; it must not replace exact frame and payload comparison or rebase away a regression.

### Instances and templates

Source: `types/mesh.rs::InstanceRecord` and `RawInstanceOccurrence`, plus the `MeshData.instance` attachment.

Record every final `InstanceRecord` field: occurrence `express_id`, `ifc_type`, `global_id`, `name`, `presentation_layer`, `color`, `template_express_id`, `rep_identity` (all 128 bits), `transform[16]`, `geometry_item_id`. Templates are the actual retained mesh records referenced by `template_express_id`, not a second guessed mesh set. Assert every reference resolves, identities/multiplicity are preserved and no unexpected orphan/template disappearance occurs.

The canonical-element supplement records every `RawInstanceOccurrence` field, including pre-RTC `world_transform`, metadata, color and item identity. This catches losses hidden by final template collation. Compare instanced and flat base/candidate lanes separately; additionally reconstruct presented occurrences using actual public template/frame contract to check scene equality. Do not materialize everything through custom replacement arithmetic just to make the instancing lane look like flat output. A render-equivalent secondary comparison cannot silently excuse changed template/provenance fields.

### Text and all symbolic primitives

Sources: `symbolic/primitives.rs`, `symbolic/provenance.rs`, `symbolic/output_cap_types.rs`, public entry in `symbolic/mod.rs`.

Capture complete `SymbolicDataWithProvenance`, preserving each fill's aligned `fill_items()` sidecar. Include all `grid_axes`, `polylines`, `circles`, `texts`, `fills` and optional `truncated` fields, not only text strings. For `SymbolicText`, explicitly include `express_id`, `ifc_type`, `x`, `y`, `dir_x`, `dir_y`, `height`, decoded `content`, `alignment`, `world_y`, `color`, `target_px`, `representation`. For fills preserve hole offsets, hatch parameters including optional-by-NaN secondary angle and frame elevation; for other primitives include every public field from their definitions. Source provenance and truncation/refusal reasons must remain visible. Do not decode IFC string escapes a second time.

### Streaming contract

Source: `processor/sink.rs`, `processor/request.rs`. Capture ordered `on_bootstrap`, `on_frame` (including `baked_basis`), `on_batch` (full actual emitted mesh records plus processed/total counts), and `on_color_update` (actual ID/color update sequence). Compare event chronology, batch boundaries and multiplicity for matching requests. Also replay real color updates into a separate consumer view and compare final presented colors. Both the original batch color and applied update are evidence; replacing both with final returned meshes masks deferred-style regressions.

Bootstrap spatial entities/trees/pruned edges are recursively captured, retaining order and exact enum reasons. These are useful metadata outputs even when absent from `ProcessingResult.metadata`. A result-only comparison misses their disappearance.

### Diagnostics, source refusal and work accounting

Source: `types/response.rs::ProcessingStats`, `geometry/src/router/diagnostics.rs`, `diagnostics_recording.rs`, `diagnostics.rs`, `construction/reports.rs`, `csg/census.rs`.

Compare semantic full-pass stats: total meshes/vertices/triangles, total CSG failures/products affected, degenerate drops, refused input elements, refused prepass records, and complete optional `geometry_diagnostics`. Preserve schema version, classification, reason counts, silent no-ops, rect-fast outcomes, worst hosts, oversized-reference drops and unsupported-item counts/types. Compare actual reasons/IDs, not only aggregate totals.

Elapsed times are nondeterministic performance evidence: record them in a separate measurement channel, exclude them from the scene equality digest. `from_cache`, point-cache hits/misses and related work counters are also retained in an execution-evidence channel, because equal scenes can legitimately use different memoization; do not quietly discard them or call all statistics byte-identical. Explain any change in cache/dispatch work rather than treating it as geometry loss by default. Aggregate counters are not a proof of per-product attribution.

The canonical-element supplement records `ProducedElementMeshes` meshes, occurrences, `geometry_hash`, `geometry_aabb`, `geometry_volume`, `geometry_closure`, ordered typed `csg_failures`, and `degenerate_triangles_dropped`. When router diagnostics are explicitly collected, drain once at the owning pass's natural boundary; do not drain beforehand and change the producer's result. Include actual host-opening classifications and per-host before/after triangles, opening kinds, cutter counts and bounds where the public consumer exposes them. Input decoder refusals are source evidence, not fabricated per-element attribution.

The process-global CSG census has only `(op,a_tris,b_tris)` and no product identity. Its multiset with multiplicity can qualify workload conservation in an isolated run, not causal attribution or successful cuts; parallel record order is scheduling-dependent. Optional scoped sink propagation is explicit and should not be assumed to reach arbitrary Rayon children. Reset/drain the global census in a fresh harness process with no unrelated work; do not double-drain or enable extra numerical work to collect it.

Candidate owned graph `ConstructionReports` exposes `curve_capped`, ordered unique `face_refused` types and cumulative `decoder_refused_record_ids`; execution failures carry root/item IDs, error, fresh diagnostics and reports. These describe eager source admission and numerical execution with their documented separate chronology. They are not the canonical producer's occurrence-ordered event stream and must not be compared as though they were. Keep graph-only evidence in its own lane; compare equivalent actual terminal failures where baseline public APIs expose them, otherwise mark capability gap.

## Ordering and floating-point policy

The primary compatibility comparison retains the actual order of every vector, duplicate, vertex, index, occurrence and event. Canonicalize only genuinely unordered maps (such as properties when not already BTreeMap): sort typed keys and retain values exactly. Do not sort away missing duplicate geometry, reorder triangles, normalize normals, recompute UVs, renumber IFC IDs or elect different templates in the primary lane.

Use a typed canonical value writer/serde Serializer that records f32 and f64 as fixed-width IEEE-bit values, plus type/field tags, lengths and option presence. Include signed zero, NaN payloads and infinities exactly in this same-target/same-toolchain preservation lane; also flag non-finite geometry independently. Do not let JSON turn symbolic NaN sentinels into indistinguishable null/absent values. Explicitly append serde-skipped fields. Strings compare exact UTF-8 bytes; no case folding, whitespace normalization or Unicode re-normalization. u128 identities must not pass through JavaScript numbers. RGBA and UV bit fidelity is as important as coordinate bits.

A secondary canonical scene multiset, indexed by full semantic identity and content with occurrence multiplicity, helps diagnose harmless scheduling order changes. It is supplemental: report ordered mismatch separately and identify whether consumer order is contractual. Repeat base against itself first; if a channel is inherently nondeterministic, disclose it and compare its documented invariant without weakening deterministic channels. Cross-target trig differences need the existing determinism qualification policy, not an arbitrary tolerance that hides this branch's same-target drift.

## Completion criterion

Produce base/candidate structured receipts for every available matrix cell, with actual feature witnesses and exact capability manifests. Investigate every mismatch; accept only explicitly justified differences with retained field-level evidence and independent invariants. Missing real texture/annotation/IFCX corpus remains a named unqualified scope. A complete STEP scene comparison, plus separate canonical/hash/diagnostic and IFCX/USD lanes, is the coherent path to a defensible no-loss claim. Passing a larger mesh hash alone cannot support that claim.

## Native format boundary and reusing the browser adapter

The current native `processing::process` path scans STEP records and uses `EntityDecoder`; its `schema_detection`/`core::SchemaFamily` recognition of an IFC5 label is NOT an IFCX JSON composition loader. The actual existing IFCX consumer is `packages/ifcx/src/index.ts::parseIfcx` (JSON header validation, composition and extraction), reached by `apps/viewer/src/hooks/useIfcLoader.ts::loadFile` through `ingest/viewerModelIngest.ts::parseIfcxViewerModel`. `IfcxParseResult` includes full data tables/path mappings/point clouds as well as meshes. Native STEP qualification preserves that native consumer; it neither establishes new native IFCX import support nor qualifies the existing browser IFCX consumer. Browser IFCX preservation must be exercised through its current real load path and importer.

An eventual shared Rust owned-IR seam should consume definitions supplied BY that existing import adapter, rather than reparsing the same file in a second loader. At the geometry extraction boundary, the authoritative already-composed IFCX nodes have USD-style mesh and transform attributes (`packages/ifcx/src/types.ts::UsdMesh/UsdTransform`, `geometry-extractor.ts`, composition/traversal/path resolver). The adapter may package owned mesh coordinates/topology, authored normals/UVs, resolved appearance/texture references, full transform stack, up-axis/units, stable source path and property/classification references into an explicit imported-mesh definition plus occurrence/presentation records. Shared Rust lower/evaluate must retain source/occurrence distinctions and use an explicit frame contract; imported tessellation is an appropriate source definition, not a finished canonical product mesh disguised as a plan.

Two qualifications are necessary. First, the current extractor already emits Float32 arrays, applies transforms and converts Z-up to viewer Y-up. Passing those final buffers into Rust can preserve existing rendered behavior, but cannot recover original precision, authored topology or source-local pose. Label that boundary honestly as imported evaluated geometry. For actual source-owned definitions, add the handoff before its narrowing/transform bake, using the already-composed raw USD attributes and lineage from the same parser; retain the current host's composition/tombstone/inheritance/asset-resolution authority, and replace the superseded numeric emitter rather than running two pipelines. Second, the Rust constructor registry currently reads STEP schema entities; this source-independent imported definition requires an explicit IR input variant/adapter contract, not fake STEP entity IDs or rerunning a STEP processor on IFCX arrays.

Keep `loadFile(file,target)` the canonical browser/federation path. Pass the same imported entity/path maps, relationships, properties, georeferencing and point clouds through existing ingest/store publication; use Rust only for the owned geometry operation/placement contract once qualified. Do not silently drop importer-only data because native `ProcessingResult` has fewer channels. Preserve full pose, per-occurrence appearance and layered property/material provenance through the existing adapter, and compare pre-handoff source facts plus post-handoff presented results. USD export must then consume the same qualified scene definitions/presentation rather than acquiring a parallel parser or alternate loading route. This is a proposed next coherent implementation boundary, not functionality claimed by the present Rust refactor.

The common Rust consumer probe records current source/model/library digests and structured exact-value evidence outside performance timing. Its README states unsupported boundaries and commands. The IFCX/USD sibling lane exercises the actual host importer/exporter separately; native STEP scene equality cannot stand in for those results.
