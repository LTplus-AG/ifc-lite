# Test and evaluation strategy

ifc-lite rule: *ground truth an agent cannot fabricate*. Every layer has an **oracle** — something external to the code under test that says what's right.

## 1. Oracles by layer

| Layer | Oracle | Mechanism | Where |
|---|---|---|---|
| Parser / validator | buildingSMART IDS corpus (334 cases: pass/fail verdicts, invalid files) | Existing `corpus.test.ts`; keep 307/307 | `packages/ids/src/__corpus__` |
| Validator semantics | ifctester parity set | Existing parity script | `__corpus__/ifctester-parity-6117` |
| Audit | Corpus `invalid-` cases + official audit CLI on exported docs | `AUDIT_UNDETECTED` must stay empty; CI oracle job | P-01 |
| Writer | Round-trip on corpus + property-based generator | `parse∘write = id`; oracle verdict equality | IDS-014 |
| Ops / reducer | Algebraic laws | apply∘inverse = id; compound = sequence of primitives; history replay = final state | IDS-019 |
| Gate | Schema tables + generated hallucination set | 100% reject fake names, 100% accept corpus names | IDS-021…023 |
| Lint | Labelled lint corpus + per-rule fixtures | Precision ≥ 95%, recall tracked | IDS-054 |
| Preview / explain | Validator itself | Parity: preview verdicts ≡ validate; trace verdict ≡ validate | IDS-057, IDS-059 |
| Infer | Labelled selections on real models | Accuracy ≥ 90% (accepted candidates reproduce the human-written spec's verdicts) | IDS-062 |
| bSDD mapping | Recorded bSDD responses | Mapping table tests per data type | IDS-071 |
| Diff/merge | Mutation corpus (apply random ops to corpus docs, diff must recover them) | Exact recovery of applied changes | IDS-104 |
| Testgen | Our validator + corpus | Generated fixtures produce expected verdicts | IDS-111 |
| Agent | E1–E5 sets, executable oracle (E2) | Scores + ship gates | P-08 |
| UI | Real models from ≥2 authoring tools; screenshots/recordings | PR evidence per AGENTS.md | each UI PR |
| Performance | `tests/benchmark` baseline with real models | p95 targets NFR-01/02 | IDS-068 |

## 2. Test pyramid per package
- **ids / ids-authoring / ids-model-loop / ids-testgen:**
  - unit tests;
  - property tests (fast-check);
  - corpus tests (skip when fixtures are absent, per `pnpm fixtures` rules);
  - no snapshot tests of source text (AGENTS.md "never assert on source text").
- **ids-agent:**
  - unit tests on tools (pure);
  - recorded-response replay for the loop;
  - no live calls in CI.
- **viewer:**
  - store-slice tests;
  - component tests where logic lives;
  - tour tests;
  - a11y checks (jsx-a11y ratchet);
  - a few end-to-end flows with Playwright (Chromium preinstalled) on a small real model.

## 3. AI eval details
- **E2 construction:** for each corpus spec with paired IFC, write a natural-language description (generated by an LLM, then human-reviewed and edited). The task is "write an IDS for this description". The score is the fraction of paired IFC elements where our verdict on the agent's IDS equals the corpus verdict. Fail cases are included, so a spec that's too lax is caught.
- **Splits:** train (prompt tuning allowed), validation (go/no-go), test (headline, scored every release, never tuned on).
- **Cost control:** Batch API for live runs (50% price); prompt caching; sampled nightly (20%), full per release.
- **Regression gate:** a PR that changes prompts, tools or model config must attach an eval report. CI checks that the report hash matches the change and that no metric drops beyond tolerance.
- **Human eval for prose** (Explain/Translate): a 5-point rubric, 2 raters, monthly.

## 4. Real-model evidence set
A private fixture set (not committed if licensing forbids; fetched via `pnpm fixtures`):
- IFC4 and IFC2X3 exports from at least three different authoring tools.
- Sizes: 5k, 100k and 1M+ elements; a federated set of 3+ models.
- Used for perf benchmarks, preview/infer demos and screenshots in PRs.

## 5. Definition of Done (every backlog item)
- [ ] Tests per the pyramid. Oracle-backed where a row above applies.
- [ ] House rules: no `as any`, `@ts-ignore` or silent catch; modules ≤ 400 lines; MPL header.
- [ ] Docs updated in the same PR; snippets typecheck; generated regions refreshed.
- [ ] Changeset + API-surface snapshot if a published package changed.
- [ ] Evidence attached for user-visible behaviour (real model / oracle / screenshot).
- [ ] i18n catalogue entries for new strings; analytics scrub-compliant.
- [ ] Superseded code deleted in the same PR.
