### Learnings and gotchas

- **All `@ifc-lite/data` schema lookups are async.** The gate loads the tables once per process (`createGateContext`) and builds synchronous, case-folded indexes, so `checkOps` itself is synchronous.
- **The entity tables contain EXPRESS defined types** (`IfcLabel`, …). The gate subtracts `IFC_DATA_TYPES` so an entity facet on `IfcLabel` is refused.
- **There are no `Qto_*` rows for IFC2X3 or IFC4** (IDS-009 pending). The gate accepts `Qto_` names it cannot verify in those versions, mirroring the audit's `canVerifyReservedSet`. Once IDS-009 lands, the hallucination test should add Qto fakes for those versions.
- **User-defined predefined types.** A predefinedType outside the enumeration is an ObjectType match in IDS, and the corpus uses such values (six partOf cases: SLABRADOR, WARREN, …). The audit does not check partOf predefined types. The gate refuses these values unless they are declared with `meta.custom.declareUserDefinedType`. Without that rule, an invented enum member would pass as "user-defined" on every entity that allows USERDEFINED.
- **Template data-type names are not accepted.** The audit only tolerates IDS template names such as `IFCPROPERTYSINGLEVALUE` after `findDataType` succeeds, which it never does, so the gate does not accept them either.
- **The translation service only negates sentences that start with "Must".** Property and attribute requirements come out identical for required, optional and prohibited. `describeFacet` therefore prefixes the localised optionality label when the service did not change the sentence.
- **Doubled quotes in the translation service.** It renders constraints wrapped in quotes inside templates that add quotes again (`Property ""Pset_DoorCommon"."FireRating""`). This is an upstream wording bug; flag it for the IDS-027 renderer in `@ifc-lite/ids`.
- **Property-test generator coverage.** The first generator version almost never produced a reorder of a non-first facet: corpus sections usually hold one facet. A broken `facet.move` inverse stayed green until `facet.add` was weighted up and moves within the same spec were forced. Check new generators for this kind of blind spot.
- **Vitest 5 s timeout.** The full suite runs files in parallel, which pushes the property test past the 5 s default. Long tests set their own timeout.
- **Worktree-isolated shell sessions** refuse compound commands that `cd` and then run git. Run git from the worktree root.

### Spec deviations (from `03-architecture/02-document-model-and-ops.md`)

`02-document-model-and-ops.md` lives on the campaign branch and needs the same edits there (open decision 1).

1. **No zod.** The workspace has no zod dependency, so the op contract is authored as JSON Schema (`src/ops/schema*.ts`). One small interpreter both validates ops and exports the schema; the single source of truth is preserved.
2. **Four fidelity ops** (`spec.restore`, `spec.patch`, `facet.restore`, `facet.patch`). They are what inverses are made of. They carry raw IDS content and node ids, so undo restores import leftovers (`cardinalityRaw`, `ifcVersionRaw`, `rawRelation`, absent `minOccurs`) exactly. They pass the gate like any op.
3. **`ValueInput` adds `{ kind: 'raw', constraint }`** to `ConstraintDraft`, for verbatim constraints (imports, inverses, compound expansions).
4. **Optional id fields in payloads.** `facet.add`, `facet.replace`, `facet.setField`, `value.set` and `value.addEnumValue` take optional `constraintIds` / `constraintId`. When an id is not given, the reducer derives it deterministically from the opId (`deriveId`, a UUIDv8), so `apply` stays pure.
5. **New ops `meta.custom.declareUserDefinedType` and `meta.custom.removeUserDefinedType`,** and `StudioMeta.custom.userDefinedTypes`. They are the explicit escape hatch for user-defined predefined types (see gotchas).
6. **`NodeIndex` mirrors the document shape** (parallel arrays) instead of storing `NodePath`s. `locateNode` derives the location. Spec and requirement `id` fields carry the node UUIDs.
7. **`bulk.applyTemplate` takes the template inline** (`{ template, params }`) rather than a `templateId`, which keeps the reducer pure without a registry. `{{id:local}}` placeholders derive ids.
8. **Gate API is `checkOps(ops, doc, ctx) → { ok, issues[] }`.**
   - Each issue carries `{ ok: false, code, path, message, candidates, opIndex, opId, facetId, field, value, versions }`.
   - Undo and redo replay exact inverses and do not re-run the gate.
   - `facet.remove` and similar ops do not re-ground the rest of the document.
9. **Gate codes beyond the table:** `GATE-OP-001/002`, `GATE-CUST-002…004`, `GATE-STR-001…008` and `GATE-VAL-001…008`, as listed in the package README.
10. **Provenance is stored on history entries** (`HistoryEntry.source`), not written into `meta.provenance` by the reducer. Writing it from the reducer would break apply∘inverse = id.
11. **Not implemented** (out of this session's scope): `spec.split`, `spec.merge`, `value.convertKind`, `bulk.expandAbstract`, `bulk.fromBsddClass`, `bulk.fromInference`, `bulk.fromMapping`, `bulk.setVersion`, the other `meta.*` ops, and the gate's `GATE-BSDD-001` check.

### Open decisions

1. Add the deviations above to `02-document-model-and-ops.md` on the campaign branch, with the op table and the gate code list.
2. **Re-identification needs the previous content.** The sidecar stores node ids and a fingerprint, not the previous IDS content. Re-identification after an external edit therefore needs the previous document, for example from the local library. Should `studio.json` also carry a content snapshot, so that `.idsz` bundles edited elsewhere can be re-identified on their own?
3. **Gate strictness on imported documents.** `spec.setIfcVersions` re-grounds every facet of the spec, so an import with legacy invalid names blocks a version change until those names are fixed. That is intended (the result must be grounded), but the UI should offer the fixes.
4. **Entity hierarchy-proximity boost for candidates is not implemented.** Ranking uses OSA Damerau-Levenshtein, token Jaccard, and the applicable-pset boost. Tune it with the P-08 E-sets.
