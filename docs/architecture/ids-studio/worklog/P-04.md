**Decisions taken**
- *Incremental scope by identity.* The reducer shares structure, so a spec whose `IDSSpecification` and `SpecNodes` objects (and `meta.custom`) are unchanged is served from cache; the reducer's `touched` set is accepted as an extra hint. Document rules (duplicates, overlaps, identifiers, document info) re-run every pass. Suppressions are applied after the cache.
- *Suppressions* use the existing `Suppression` meta, keyed by node id; they cover the node and every descendant, `rule` may be `IDSL-AREA-*`, and a blank reason is ignored. **No op writes suppressions yet** (see open questions).
- *Quick fixes* are op batches with ids derived by `deriveId` from code/node/variant (deterministic output). Every rule passes its fixes through `checkOps` (`gated`), so an offered fix always passes the P-02 gate. Fixture contract: fix passes gate, clears the finding, adds no audit error.
- *Per-finding demotion.* A finding may carry a lower severity than its rule (used by REGEX-003); a caller's severity override wins.
- *Deviations from the catalogue severities*, each recorded on the rule page: ENT-002 is info and means "removed in IFC4X3" (IfcWallStandardCase is still in our IFC4X3 table, so the catalogue example does not hold; the gate already refuses names missing from a version); PDT-001 is split: PDT-001 (error) only when the enumeration has no USERDEFINED, new PDT-003 (info) for undeclared user-defined values (coordinator finding 2, corpus `entity/pass-a_predefined_type_may_specify_a_user_defined_*`); REGEX-003 is warning, and info for `(?:…)` / `\/` because buildingSMART pass- cases use them; PART-001 covers the "unusual but valid" relation cases, since the audit already rejects schema-invalid owner/member combinations.
- *New rule ENT-005* (entity name not upper case, warning, fix upper-cases through `value.set`) per coordinator finding 1 (P-01 audit rule `E_IFC_ENTITY_CASE`).
- *No rule depends on a list flag for attributes* (coordinator finding 3).
- *`@ifc-lite/ids` exports `IFC2X3_MAPPED_ALIASES`* (minor changeset) so VER-001 accepts IFC2X3 mapping-table names from the validator's own table instead of a copy.
- *Solver* is three-valued: exact for finite sets (via `matchConstraint`, numbers compared numerically) and numeric intervals; patterns can only be proven to overlap by a sampled witness, never declared disjoint (`'unknown'`). SPEC-002/003/006 restrict to single-valued subjects (entity class, one attribute, one property); classification and material can be multi-valued, so disjoint values there are not contradictions.
