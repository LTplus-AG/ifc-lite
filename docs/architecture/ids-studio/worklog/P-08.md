**Decisions taken**
- **Scorer location.** The scorer is `scripts/ai-eval/ids/*.mjs`, run with `node:test`. It sits next to the existing `scripts/ai-eval` harness, as 06-ai-agent.md §9 says (`scripts/ai-eval/ids/*`).
  - It loads `@ifc-lite/ids`, `@ifc-lite/parser` and `@ifc-lite/data` from their `dist/` by path (`packages.mjs`), because the root package has no workspace deps.
  - A missing `dist/` throws with the build command instead of skipping.
  - CI coverage: `scripts/ai-eval/ids/*.test.mjs` was added to the node-tests `scripts/` glob catch-all in `test.yml`. That job downloads the build output first, and `check-test-wiring` enforces the glob.
- **Data location.** Datasets live in `tests/ai-eval/ids/{e2,e4,e5}/`. That tree is outside `tests/ai-eval/manifest.json`'s scope. The existing manifest gate still passes, and our tests reuse its `privacyFindings` scan over every dataset text.
- **Record shapes.**
  - E2 `ifcVersion` is an array, e.g. `["IFC2X3","IFC4"]`.
  - E4 stores the expected *document*, not an op diff. The op vocabulary (P-02) is not on this branch. The runner can derive the diff once ops exist.
  - E5 behaviours are `reject`, `unresolved` and `ignore-injection`. `unresolvedCategory` uses the method's statement classes from 06-ai-agent.md §6: geometry, rules-engine, manual, ambiguous.
- **E2 verdict rule.** A candidate is `fail` if any specification fails, otherwise `pass`. A candidate that does not parse, or has no specifications, is unscorable and never agrees.
- **Agreement is per case, not per element.** The corpus gives one verdict per file, not per element, so the per-element agreement wording in the strategy doc cannot be computed from it. Per-spec applicable/passed/failed counts are still reported.
- **E2 descriptions mark the required/optional distinction explicitly.** A description says "optional check" when applicability has `minOccurs="0"`. Otherwise "required" is the default, and descriptions say "at least one" only where the case depends on it.

**Finding for P-01 (audit)**
- Our audit reports **errors on 18 conforming corpus IDS files** (`pass-`/`fail-` cases). They fall into three families:
  - user-defined predefined types: `E_IFC_PREDEF_TYPE_INVALID`, 12 cases;
  - the IFC2X3 air-terminal type mapping: `E_IFC_ENTITY_UNKNOWN`, 8 cases. Two of them also get `E_XSD_STRUCTURE` because they are specs with no requirements;
  - a classification on `IfcMaterial`: `E_IFC_PARTOF_ENTITY`, 1 case.
- They are pinned as a shrink-only `AUDIT_FALSE_POSITIVES` set in `e2-scorer.test.mjs`.
- While the set is non-empty, the "audit pass = 100%" ship gate cannot hold on E2, even for a perfect agent. Either fix the audit, or scope the gate to cases outside this set.
