#### IDS-124: what the preview models, and the readings taken

Upstream state was read on 2026-10-08 from the buildingSMART/IDS repository
(`ver/1.1.x`, draft PR #380 fetched read-only) and the issue pages. The
backlog's "candidate features" were mapped to upstream sources:

| Backlog feature | Upstream | Modelled as | Conservative reading |
|---|---|---|---|
| (not in backlog; the only change merged on `ver/1.1.x`) | #188, #251, PR #382 | `uri` on property/classification/material in applicability | Informational, never checked against a model |
| translations | #154 (only concrete proposal: `instructions` on all facets) | `instructions` on applicability facets | No translation XML is invented; names/descriptions in other languages stay in the sidecar (ADR-011). Requirement instructions stay on `IDSRequirement` |
| extended partOf | #379, draft PR #380 | attribute/property/classification/material nested in partOf, evaluated on the related element | Exactly one related entity (#380's `xs:choice` no longer enforces it; #379 says "at least one"). `IfcRelSpaceBoundary` (#247) and inverse partOf (#200) are undecided upstream and not modelled |
| identifiers | #339 (resolved as documentation, PR #369: "should be unique") | preview audit warning `W_IDS11_IDENTIFIER_DUPLICATE` | "should" means warning, never error |
| tolerance | #418 (milestone 1.1, discuss & decide) | `toleranceRule: 'ids11-418'` stamped on value constraints by the preview parser | Inclusive bounds `v ∓ (abs(v)·1e-6 + 1e-6)`, each rounded half-to-even to 15 decimals (the reference implementation's rounding as reproduced in a #418 comment); fixed, not configurable; ranges never use tolerance |

Other decisions:
- One flag shape everywhere: `preview: { ids11: true }` on `parseIDS`,
  `writeIdsXml` (new third argument, `IdsXmlWriteOptions`; `IdsXmlFormat` stays
  layout-only), `validateIDS` and `auditIDSDocument`. ADR-011 calls it
  `ids11Preview`; the nested object leaves room for later versions.
- Without the flag, the writer and validator throw
  `IDS11PreviewRequiredError` on a document that uses a 1.1 feature, instead
  of silently dropping it (ADR-011: no 1.1 leakage, and no silent 1.0 skip).
- Preview output uses schema location
  `http://standards.buildingsmart.org/IDS/1.1/ids.xsd` plus an XML comment.
  **Assumption:** buildingSMART has not published that URL; it follows the 1.0
  pattern and the `version="1.1.0"` of the upstream `ver/1.1.x` XSD.
- The preview parser does not read `uri` on requirement facets. That is an
  IDS 1.0 feature the default parser ignores today; reading it only under the
  preview would make a preview parse of a 1.0 file write different bytes.
- The structural audit's XSD shape tables moved to `structural/shapes.ts`
  (index.ts 566 → 411 lines, allowlist lowered). `translation/service.ts` was
  2 lines over its budget (inherited from IDS-011); it is under it now.

Evidence: across all 334 corpus files the writer output is byte-identical with
the flag off, on, and after a preview parse; with the preview, all 307
pass/fail verdicts hold and the audit's non-info findings are unchanged on all
334 files (`src/preview/ids11-corpus.test.ts`). Nested partOf on
`AC20-FZK-Haus.ifc`: 7 spaces, 6 on "Erdgeschoss", 1 on "Dachgeschoss"
(`src/preview/ids11-model.test.ts`).
