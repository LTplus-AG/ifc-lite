# Integration Guide: Generated IFC Code in the Monorepo

This guide explains where the code generated by `@ifc-lite/codegen` lives, who
consumes it, and how to regenerate it. The integration into `@ifc-lite/parser`
is done; this page describes the current layout, not a migration.

## What the generator emits

For one EXPRESS schema, `node dist/cli.js <schema.exp> -o <dir>` writes these
files into `<dir>`:

1. **entities.ts** - entity interfaces with full inheritance
2. **types.ts** - defined-type aliases
3. **enums.ts** - enum definitions
4. **selects.ts** - SELECT union types
5. **schema-registry.ts** - runtime metadata (`SCHEMA_REGISTRY`,
   `getEntityMetadata`, `getAllAttributesForEntity`,
   `getInheritanceChainForEntity`, `isKnownEntity`, `CONCRETE_RELATIONSHIP_TYPES`)
6. **type-ids.ts** - numeric type-id lookup tables
7. **serializers.ts** - STEP serializer bound to the bundle's `SCHEMA_REGISTRY`
8. **index.ts** - barrel export
9. **test-compile.ts** - compile smoke test, excluded from the published build

Add `--rust` to also write Rust type tables (see the
[README](./README.md#generate-from-the-official-ifc-schema)).

> **Runtime dependency:** the generated `serializers.ts` is a thin re-export of
> the schema-agnostic STEP serializer in `@ifc-lite/data` (it only binds the
> bundle's `SCHEMA_REGISTRY`). Any project that consumes a generated bundle must
> therefore have `@ifc-lite/data` installed. This keeps the serialization logic
> in one place so the per-schema copies can never drift.

## Where the generated code lives

| Committed output | Source schema | Consumed as |
| --- | --- | --- |
| `packages/codegen/generated/ifc4/` | `schemas/IFC4_ADD2_TC1.exp` | `@ifc-lite/codegen/ifc4` |
| `packages/codegen/generated/ifc4x3/` | `schemas/IFC4X3.exp` | `@ifc-lite/codegen/ifc4x3` |
| `packages/codegen/generated/ifc2x3/` | `schemas/IFC2X3_TC1.exp` | `@ifc-lite/codegen/ifc2x3` |
| `packages/parser/src/generated/` | `schemas/IFC4_ADD2_TC1.exp` | `@ifc-lite/parser` (IFC4 registry, types, serializers) |
| `packages/parser/src/generated/ifc4x3/schema-registry.ts` | `schemas/IFC4X3.exp` | per-version registry in `@ifc-lite/parser` |
| `packages/parser/src/generated/ifc2x3/schema-registry.ts` | `schemas/IFC2X3_TC1.exp` | per-version registry in `@ifc-lite/parser` |
| `rust/core/src/generated/{schema,type_ids}.rs` | `schemas/IFC4X3.exp` plus IFC4 and IFC2X3 supplements | `ifc_lite_core` |

`@ifc-lite/export` and `@ifc-lite/ids` import the `@ifc-lite/codegen/*`
bundles at runtime. `@ifc-lite/parser` picks the registry that matches a
model's schema with `getSchemaRegistryForVersion`
(`packages/parser/src/generated/schema-registry-by-version.ts`).

## Copy Generated Files to Parser

`packages/parser/src/generated` is a committed copy, not a symlink. After
regenerating IFC4, copy the files over:

```bash
cp packages/codegen/generated/ifc4/*.ts packages/parser/src/generated/
```

The `ifc4x3/` and `ifc2x3/` subfolders of the parser copy hold only
`schema-registry.ts`. They deliberately carry no `entities.ts`, `types.ts`,
`enums.ts` or `selects.ts`, because three copies of those interfaces in one
package would redeclare the same TypeScript type names. Copy only the
registry:

```bash
cp packages/codegen/generated/ifc4x3/schema-registry.ts packages/parser/src/generated/ifc4x3/
cp packages/codegen/generated/ifc2x3/schema-registry.ts packages/parser/src/generated/ifc2x3/
```

## Regenerating

Never hand-edit a generated file; change the generator and regenerate.

```bash
pnpm --filter @ifc-lite/codegen build
pnpm --filter @ifc-lite/codegen generate:ifc4
pnpm --filter @ifc-lite/codegen generate:ifc4x3
pnpm --filter @ifc-lite/codegen generate:ifc2x3
```

Then copy the parser files as above.

`pnpm check:codegen-sync` (`scripts/check-codegen-sync.mjs`, run in CI by
`.github/workflows/test.yml`) regenerates every target above into a temporary
directory and byte-compares it with the committed files. A missing file, an
extra file or a content mismatch fails the check, so a generated file that was
patched by hand, or a parser copy that was not refreshed, cannot land.
