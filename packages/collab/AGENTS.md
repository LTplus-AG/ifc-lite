# Agent notes: packages/collab (+ packages/collab-server)

Supplements the root [AGENTS.md](../../AGENTS.md) Collaboration server section. Collab-specific footguns:

- **IFCX is the canonical wire.** This package emits it via `snapshotToIfcx` + `serializeIfcx` (`src/snapshot/to-ifcx.ts`) and seeds a `Y.Doc` via `seedFromIfcx` (`src/snapshot/from-ifcx.ts`); the recipient's `parseIfcxViewerModel` lives in `apps/viewer` (`src/hooks/ingest/viewerModelIngest.ts`), not here. Any CRDT/IFCX shape change must preserve the seed, snapshot, re-seed round-trip (`test/round-trip.test.ts`).
- **`mergeUpdateFrames` must use `Y.mergeUpdates`, never byte-concatenate frames** (`collab-server/src/persistence.ts`). `Y.applyUpdate` decodes only the first update in a naive concatenation and silently drops the rest, losing every edit after frame 1 on room reload (the #1501 data-loss class).
- **Persistence filenames use `encodeURIComponent(roomId)`**, not the old sanitizer that mapped unsafe chars to `_` (which collided distinct rooms onto one log). `legacyLogPath` migrates pre-encoding logs on load/append and deletes them on compact. Any persistence-format change needs the same migrate-or-poison discipline or existing rooms lose history.
- **Transaction origins are load-bearing** (`src/doc/schema.ts`): local edits use `LOCAL_ORIGIN`, seeding `SEED_ORIGIN`, undo `UNDO_ORIGIN`; the server applies disk state with origin `load-from-disk` so `onDocUpdate` skips re-persist/re-broadcast. `UndoManager` tracks only `[LOCAL_ORIGIN]`. Writing to the doc without the right origin breaks undo or echoes loaded state back out.
- **No placement-specific code path.** There is no `placementBaseline` in-tree (that delta-render logic is viewer-side); in the CRDT a placement is just a plain namespaced IFCX attribute (`setAttribute(doc, path, 'usd::xformOp::translate', value)`). Do not special-case it here.
- **E2E-encrypted rooms cannot be snapshotted server-side.** With `src/security/e2e.ts` (AES-GCM-256) the server routes ciphertext only; `snapshot-worker.ts` server-side IFCX export silently does not apply without key escrow.
- **collab and collab-server are one unit.** Test both with `pnpm test:collab` (runs vitest in both packages), not just `turbo test`; run the reference server with `pnpm collab:server`. Server env: `COLLAB_PORT` / `COLLAB_HOST` / `COLLAB_DATA_DIR` (default `./.collab-data`) / `COLLAB_MAX_ROOMS`. A CRDT schema change usually needs test updates in both packages.
- **Preserve the file-level IFCX header round-trip.** `header` / `imports` / `schemas` are stashed into the doc meta map on seed and re-emitted on snapshot (`from-ifcx.ts` stashes, `to-ifcx.ts` re-emits); drop them and snapshots lose their header.
- **New public entry points go in the `exports` map.** `@ifc-lite/collab` publishes subpaths (`./snapshot`, `./providers/indexeddb`, `./providers/websocket`, `./awareness`, `./snapshot/worker`); add to `package.json` `exports` or consumers cannot import it even though tsc emits the file.
