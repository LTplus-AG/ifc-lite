# @ifc-lite/geo

## 0.1.0

### Minor Changes

- [#10385](https://github.com/LTplus-AG/ifc-lite/pull/10385) [`e15f582`](https://github.com/LTplus-AG/ifc-lite/commit/e15f5824cb0747471e0f2dc15c16ef47972fcb89) Thanks [@louistrue](https://github.com/louistrue)! - New package `@ifc-lite/geo` (first release 0.1.0): the CRS engine the viewer places models on a map with, now usable from Node. `resolveCrs({ epsg, name, wkt })` returns a transformer that converts points to and from WGS84 (projected coordinates in metres, with the CRS's own unit reported as `linearUnit`), reads grid convergence and point scale factor, and says how its datum shift is done (`datumShift`); `egm96Undulation` gives the EGM96 geoid height. The package makes no network request and writes no log by itself: the epsg.io lookup and the cdn.proj.org datum grids are loaders the host installs with `configureCrsLoaders` (one configuration per process) or gives to an engine of its own with `createCrsEngine`, and diagnostics go to a handler installed with `configureCrsDiagnostics`. `@ifc-lite/geo/wkt` reads what a CRS WKT states without resolving it. The viewer installs both loaders and a console handler, and behaves as before except as follows.
  
  Behaviour change in the viewer: an `IfcWellKnownText` WKT2 map-projection parameter written without a unit (`PARAMETER["central_meridian",9]`) is now read in decimal degrees, as ISO 19162:2019 9.3.4 and PROJ read it. It used to be taken as radians, so a central meridian of 9 put an ETRS89 / UTM 32N site near Munich at 158.2° E, about 10,900 km away. A WKT whose projection lacks a parameter it needs after reading (a central meridian or scale factor for transverse Mercator) is refused instead of placed on the wrong meridian (also when the IFC CRS name names an EPSG code; a WKT that cannot be read at all still falls back to the name), the precision-grid badge shows a failed grid download as failed instead of loading indefinitely, and a WGS84 position outside the extent a WKT declares no longer converts back to map coordinates either. proj4 is updated to 2.23.0 with `wkt-parser` 1.9.0, which reads WKT1-style parameter names in WKT2 itself, so the local `wkt-parser` patch is gone.
