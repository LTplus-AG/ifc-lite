# @ifc-lite/geodata-ch

## 0.2.0

### Minor Changes

- [#10391](https://github.com/LTplus-AG/ifc-lite/pull/10391) [`f78f7e0`](https://github.com/LTplus-AG/ifc-lite/commit/f78f7e0b7a346981030ad5a1d7b7c951fb0e1c27) Thanks [@louistrue](https://github.com/louistrue)! - New package `@ifc-lite/geodata-ch`: a typed, headless client for Swiss federal geodata as site context in LV95 (EPSG:2056). It covers address search and parcels by EGRID or point. Terrain comes as swissALTI3D elevation grids read from the Cloud Optimized GeoTIFF tiles by range request, with the tile mosaic and overviews handled and heights in LN02 (EPSG:5728). It also offers swissBUILDINGS3D 3.0 tile discovery, swissTLM3D and register features in a box, polygon or multipolygon (cell splitting past the 200-feature cap), ÖREB extract URLs, and WMTS/WMS layer descriptors. Each result carries the dataset's required attribution. `fetch` is injectable, and the client has a cache hook, per-host rate limiting, a per-request timeout (`timeoutMs`, default 30 s, typed `HttpTimeoutError`) and retries with backoff that honour `Retry-After` as seconds or an HTTP-date.
  
  Inputs and results are explicit about what they are. Every entry point that takes coordinates throws on values outside LV95 and says when the arguments look swapped, instead of returning an empty result. `features()` returns what it collected when `maxRequests` runs out, with `requestLimitReached`, `unqueriedCells` and an overall `truncated` flag, and falls back to a bounding-box query with client-side clipping (`bboxFallbackCells`) for polygons too long for a GET URL. `ElevationGrid.hasData` is `false` for a box wholly outside coverage. The approximate LV95↔WGS84 helpers are internal (about 3 m error at the periphery, not 1 m). The SWISSIMAGE attribution text is documented as layer-level, with the product page authoritative. The provider-neutral contracts are country-neutral; only Switzerland is implemented.
