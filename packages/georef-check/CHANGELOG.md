# @ifc-lite/georef-check

## 0.3.0

### Minor Changes

- [#10537](https://github.com/LTplus-AG/ifc-lite/pull/10537) [`0ae24d5`](https://github.com/LTplus-AG/ifc-lite/commit/0ae24d5d962c5604ea957942a21b64a956aab4bf) Thanks [@louistrue](https://github.com/louistrue)! - The georeferencing doctor: check and fix a model's georeferencing from the CLI, MCP and SDK.
  
  - SDK: `bim.georef.check({ allowNetwork? })` diagnoses with `@ifc-lite/georef-check`, using `@ifc-lite/data`'s EPSG catalogue and `@ifc-lite/geo` transformers resolved for the CRSs the diagnosis needs (names through `@ifc-lite/geo` first, then the catalogue). Offline by default; checks a missing capability prevented are listed in `skipped` with what would enable them. `bim.georef.planFixes(report, { choose?, values?, acceptApproximateDatum? })` gives every suggested fix a status (`ready`, `needs-value`, `review`, `manual`, `alternative`, `conflict`); `bim.georef.fix(plan)` applies only the `ready` ones, never a fix the checker marks uncertain. `bim.georef.setSite({ RefLatitude, RefLongitude, RefElevation })` writes IfcSite's position (IfcCompoundPlaneAngleMeasure to the millionth of a second), as one undo step; the doctor derives it from the map conversion only when that is plausible and the datum shift is not an approximation the user has not accepted.
  - CLI: `ifc-lite georef check <file>` (human or `--json`; exit 1 on findings at or above `--fail-on`, default `error`; `--allow-network`) and `ifc-lite georef fix <file> --out F` (= `check --fix`; `--apply ID`, `--value PATH=V`, `--dry-run`, `--accept-approximate-datum`), which shows each change, writes a new file, verifies it reads back and checks it again.
  - MCP: `georeferencing_check` (report and plan as JSON) and `georeferencing_fix`; `georeferencing_write` gains action `site`.
  - georef-check: site latitude/longitude fixes are `apply.via: 'georef.site'`.
  
  The doctor refuses input/output aliases and verifies site fields before saving. Invalid user values stay unresolved; derived site values wait for a recheck if their conversion changes. Site writes retain ownership of their positional edits, and session reads match the exported first-valid-site selection.

## 0.2.0

### Minor Changes

- [#10386](https://github.com/LTplus-AG/ifc-lite/pull/10386) [`42254b8`](https://github.com/LTplus-AG/ifc-lite/commit/42254b8676dda36be70b678924744b97f91c9ee8) Thanks [@louistrue](https://github.com/louistrue)! - New package `@ifc-lite/georef-check` says what is wrong with a model's georeferencing and how to fix it. `diagnoseGeoreference(facts, { reprojector?, crsCatalog? })` is a pure function that returns the Levels of Georeferencing found (LoGeoRef 10 to 50, per the published definition) with stricter notions kept as separate `indicators`, and a list of findings. Each finding has a stable code, a severity, a one-sentence explanation, the numbers it is based on, and structured fixes: each change names a real entity instance and EXPRESS attribute, and each fix says how it can be applied (one `bim.georef.update`, one grouped `bim.georef.set` with the values only the user can supply marked, or manual with the reason). It covers the map position applied twice (by the site placement or by the geometry), Scale and unit slips, a UTM zone number in front of the Easting, LV03 numbers in an LV95 model, positions outside the CRS's area, authoring-tool default site locations, site latitude/longitude that contradicts the map conversion (naming which side is suspect), a CRS with no map conversion, a missing or unresolvable CRS, a missing MapUnit or vertical datum, invalid rotations, sources that disagree, and IFC2X3 without the ePSet convention. `collectGeorefFacts(store)` reads the facts from a parsed `IfcDataStore` without meshing, measuring IfcCartesianPoint and point-list coordinates separately and reading each point list through a bounded prefix. The injected `Reprojector` takes metres and returns `[longitude, latitude]`; `crsRequirements(facts)` lists the CRSs to resolve before diagnosing, so an asynchronous resolver can feed it.
  
  `@ifc-lite/parser` adds `extractGeoreferenceCandidates` and `extractGeoreferenceCandidatesOnDemand`. They return every georeferencing source in a file (IFC4 entities, `ePSet_MapConversion`, the IfcSite reference point, every IfcMapConversion with its own TargetCRS) instead of only the one that wins. `extractGeoreferencing` and `extractGeoreferencingOnDemand` are unchanged.
