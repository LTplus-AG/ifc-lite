## 0. Definition of done and stop line

- **Ledger:** every one of the 622 IDs is closed in `~/rust-review/ledger.md` as one of:
  - `fixed` (with the PR);
  - `fixed-by:<ID>`;
  - `rejected` (false positive, with evidence);
  - `wontfix` (a decision, recorded in the relevant AGENTS.md);
  - `deferred` (only for WPs that D8 makes optional).
- **Gates:** every gate in §6 is on `main`.
- **Docs:** single-home claims in docs and comments are true or deleted.
- **Stop line (D8):** the campaign is *complete* when Phases S, B and F, plus C1–C4, C6, C7 and C9, are closed. C5, C8, C10–C13 and Phase L are *optional*. They continue only while the measured progress numbers (§1.5) keep improving, and the maintainer may close the charter at the stop line with the remainder `deferred`.

## 1. Operating model

### 1.1 Issues and charter
- **Charter issue.** One umbrella charter issue, "Rust maintainability sweep (review 2026-10-15)", states what is swept (these 622 IDs) and what ends it (§0). AGENTS.md "A sweep needs a charter" requires it.
- **Issue labelling.** The issue-queue gate does not adjudicate our PRs: `louistrue` is in `exemptLogins` (`scripts/issue-queue.config.json:115`). `unqueued` is a PR-level label, not something issues inherit. Instead, the maintainer labels each WP issue `ready` at the start of the wave that contains it, as one labelling batch per wave. No PR carries `unqueued`.
- **One defect class per issue.** Each WP below is exactly one defect class; v2 splits every mixed WP from v1. The issue body lists the finding IDs and links the review file.
- **PR size.** Above ~1,500 changed lines, stack PRs against the same issue.
- **Claiming.** Assign `louistrue`, post a claim comment naming the session, and add a `claimed:session-<id>` label before any code is written. Assign every PR to `louistrue` and link it to the thread.

### 1.2 PR classes: never mix them

Each PR declares one class:

| Class | Meaning | Required evidence |
|---|---|---|
| **R** (refactor) | Behaviour-preserving | (a) `perf_probe --iters 1 --fingerprint` byte-identical to base over the named corpus: `AC20-FZK-Haus`, `ISSUE_129`, `duplex`, `IfcOpenHouse_IFC4`, the four in-tree parity fixtures, and Holter when the host has it. (b) The `geometry_correctness_harness` insta snapshots (`rust/geometry/tests/snapshots/`) are unchanged. (c) `mesh_determinism` is green. (d) The format oracle(s) from T3 are unchanged for any output the PR can reach. (e) For changes to instancing or colour, which the fingerprint excludes: the manifest's material/style hashes, the export `instanced_*` tests and the server parity tests. (f) A neutral perf verdict (`scripts/perf/probe.sh`, base vs branch, interleaved) in perf-sensitive paths. |
| **X** (behaviour change) | Fixes a bug or changes output | The regression test first, citing the finding ID; this is where `verify-first` IDs are verified (§2). The per-fixture fingerprint delta, listing which files moved and why. Insta snapshots re-accepted (`cargo insta review`) in the same PR. The format oracle(s) re-pinned *only for the format files that moved*. The parity `quick` job green, or a new `tools/ifcopenshell_reference/allowlist.json` row with an investigation note; the reference itself is IfcOpenShell's output and is never regenerated by us. `mesh_determinism` re-pinned (both x86/arm64 and wasm32 manifests) **only if** the synthetic fixture's output changes, which colour-policy fixes such as PROCESSING-4 do. Real-model before/after for user-visible changes. A perf verdict in perf-sensitive paths. |
| **G** (gate) | Adds a check or ratchet | It fails at the parent commit of a known instance and passes at the fix. Script gates under `scripts/` are *invoked* from a workflow (AGENTS.md). |

**Reconcile-then-delete.**
- Copies that have drifted are first made to agree in an X PR that pins the agreed behaviour.
- The deletion of the copies is then an R PR that must be byte-identical.
- A policy change (e.g. D3 fail-closed) is never combined with a consolidation.

**Merging:** the merge queue serialises. Each X PR re-runs its oracles after its final rebase. Each R PR in geometry re-runs the fingerprint after rebasing over any merged X PR. There is no global "one X PR open" rule: snapshots are per fixture and goldens per format, so conflicts are local. Dispatch `determinism.yml` (45 min) once per wave, and on any PR touching `rust/geometry/src/{kernel,csg}/`.

### 1.3 Every PR
- **Rust checks.** Run `cargo clippy --workspace --all-targets -- -D warnings` and `cargo test --workspace`. When a public Rust API changes, also build and test in-dir: `rust/python` (`tests/test_bindings.py`, `tests/test_alignment_axes.py`) and `rust/csg-thread-bench`.
- **Semver.** A PR that removes or changes a `pub` item in a published crate appends its account to `rust-major-offset.json` (`latestBreak`), measured with `cargo-semver-checks` against crates.io. The published crates are listed in `scripts/lib/crates-io.mjs` (core, clash, geometry, processing, landxml, export, ffi, wasm). The **coordinator** bumps `majorOffset` once per unpublished window; PRs only append (D7).
- **wasm surface.** Any change to `@ifc-lite/wasm` bindings requires:
  - the regenerated `.d.ts` committed;
  - `pnpm api-surface:update`;
  - a `pnpm changeset`;
  - `pnpm test:wasm-contract` extended for new or changed entry points (D12 limits how much of this the campaign does).
- **TS twins.** For the STEP log writer and attribute mutations, clash, the schema converter and the GUID helpers: behaviour fixes land in Rust and TS in the same PR with a parity vector (`rust/export/tests/fixtures/*.json`), plus a TS changeset (D5).
- **Docs.** Update docs in the same PR. When code moves, grep the repo, including `docs/architecture/{mesh-determinism,pure-rust-csg-kernel,plato-codegen}.md` and `rust/AGENTS.md`. Every design note includes a "docs touched" line.
- **House rules.**
  - The module-size ratchet applies: split, don't allowlist.
  - Supersede means delete.
  - Never run a repo-wide `cargo fmt`.
  - A new file gets the MPL header.
- **No new published crates (D1, D2).** The only new crate is the dev-only testkit (F1b), as a path-only **dev-dependency**, which cargo strips at publish. A new crate would need:
  - a crates.io bootstrap and Trusted Publisher;
  - entries in `CRATES`, `[workspace.dependencies]` and `scripts/sync-versions.js`;
  - edits to the per-crate path filters in `ifcopenshell-parity.yml`, `python-wheels.yml:19-33` and `test.yml:469-471`.
- **Rollback.**
  - R PRs revert cleanly.
  - X PRs are reverted as PRs, pins included, never by restoring a pin file.
  - Consumer migrations are one PR per (foundation × crate), each independently revertible; there is never a cross-crate "delete all copies" PR.
  - Each foundation design note states its **stop line**: which migrations are optional, and what is safe to delete if migration stalls at crate N, so it never leaves a third copy.

### 1.4 Lanes, models, ledger
- **Coordinator: main session.** It owns:
  - the ledger, including the hot-file ownership table per wave;
  - the per-wave `ready` batch;
  - the `majorOffset` bump;
  - verification and merging.
- **Lanes are background agents in their own worktrees** under `/home/louistrue/wt/`. At most 6 run at once.
- **Fable** writes the design note before any code for: F2a, F3b, F3e, F4, C1a, C2, C4, C6 and C9a. Each note covers API, migration order, drift-reconciliation list, stop line and docs touched. Fable also reviews those PRs.
- **Opus** handles fixes, foundations and consolidations.
- **Sonnet** handles consumer migrations, CI shepherding, re-pins, ledger bookkeeping, rebases and review-bot fixups.
- **Machinery cap.** At most one lane at a time works on machinery (gates and oracles). No gate or oracle PR enters a wave unless the fix PRs it protects are in the same wave or the next.
- **Adversarial review is required before every merge.** An independent reviewer agent attacks the diff: Fable for foundation and consolidation PRs, Opus otherwise, and never the lane that wrote the PR. It tries to break the fix by checking:
  - the regression test fails at base and passes at head;
  - edge cases and NaN/malformed input;
  - drift left behind in other copies (DRY);
  - the evidence actually matches the claimed class.
  
  The reviewer posts its verdict on the PR. A PR is admin-merged only when CI is green, the verdict is `approve`, and every reviewer finding has been addressed or explicitly refuted with evidence.

### 1.5 Progress measurement
At each wave boundary, the coordinator records in the ledger:
- dispositions closed / open per WP;
- the jscpd clone count (358 at baseline);
- the number of rows in `module_size_allowlist.txt` (461);
- the number of `pub fn … Result<_, String>` signatures (G5 baseline);
- the number of function-length-ratchet allowlist rows (G4 baseline).

No new tooling is needed: these come from jscpd and grep.

## 9. Decisions for the maintainer

| ID | Question | Recommendation |
|---|---|---|
| D1 | Where does the math home live? | `ifc_lite_geometry::math` module, not a new crate. Every consumer already depends on geometry. Clash stays zero-dependency with Plato as its single definition. |
| D2 | Where does the server's data model come from? | `ifc_lite_processing::data_model`. Delete the server's fourth pipeline and its two TS-fed generators. No new crate: export's model code already depends on processing. |
| D3 | Malformed points, placements and units: fail closed, or default to 0? | Fail closed: refuse the item, record a diagnostic, and add a refused-element counter in `ProcessingResult` (the viewer can then say "N elements refused"). Done as an X PR (reconcile) followed by an R PR (collapse). Visible effect: some malformed files lose elements that render at the origin today. |
| D4 | How are issues admitted to the queue? | The maintainer labels the charter and each WP issue `ready` per wave. The queue gate is exempt for our account, and `unqueued` is a PR label. |
| D5 | Do TS twins change in the same PR? | Yes, with a parity vector and a TS changeset. |
| D6 | Generated-code slimming (C10)? | Ship it as one recorded Rust major once C4/C6 are in. Do not couple it to F5. |
| D7 | Rust crate publishing during the campaign? | (a) Accept roughly one Rust major per release window, recorded in `rust-major-offset.json`; this is current practice. Alternatives: (b) pause crate publishing until the foundations land; (c) keep `#[deprecated]` shims, which contradicts supersede-means-delete. |
| D8 | Stop line and budget? | Complete = S, B, F, C1–C4, C6, C7, C9. Optional = C5, C8, C10–C13, L. Re-evaluate at each wave boundary against the §1.5 numbers. |
| D9 | Fold the ~240 integration-test binaries? | Only when a test file is touched for another reason. Never as a sweep. |
| D10 | Move terrain CDT (`geometry/src/{cdt.rs,cdt/,terrain_cdt.rs}`) into landxml? | Move it. Its only consumer is landxml, and it is 1.5k+ lines of published geometry API. Otherwise record it as `wontfix`. |
| D11 | NaN policy in sorts? | Reject NaN at the boundary where input admission exists (consistent with D3). Elsewhere use `total_cmp` with NaN last. State it per site in S2. |
| D12 | May the campaign ship `@ifc-lite/wasm` majors? | Keep the browser's batch entry points stable (shared internals only). Allow removal of the dead exports (EDGE-WASM-30) as one wasm major inside C10. |
