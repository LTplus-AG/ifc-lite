### TL;DR of the decisions

1. **`RepresentationWalk` is a decoder-only structural walk in a new `pub mod ifc_lite_geometry::representation`.** It meshes nothing and owns no cache. It visits `Representation(6) → IfcProductDefinitionShape.Representations(2) → Items(3)`, plus `IfcMappedItem → MappingSource → MappedRepresentation.Items`, in DFS pre-order. It reports to a `WalkVisitor` that the caller supplies.
   - **Selection** is a typed `Select` policy. `Select::Meshed` (today's `meshed_representations`) is the single definition of "what renders".
   - **Nesting** is a typed `NestedMaps` policy, so each of today's four nesting rules is a parameter rather than a fork.
   - **Mapped transforms** are exposed as `MappedLevel::local_transform` (Target·Origin, **unscaled**, built on F3b's `placement`), the same convention as the F3b memo.
   - The router, C4's processing walks and C5's symbolic walk are all visitors.
2. **One item pipeline: `ItemMesher::mesh(item, ItemFrame)`.** `process_representation_item` is `mesh(item, ItemFrame::Direct)`, and every mapped-source walk calls `mesh(item, ItemFrame::MappedSource)`. The frame selects today's per-path stages exactly:
   - Direct items get content dedup, the instance stamp, and `rtc_applied` kept.
   - Mapped-source items get the rebase moved into `origin` (`keep_rebase_in_origin`) and no dedup.

   This is how "mapped walks routed through `process_representation_item`" lands as **R**. Whether source items should *also* use the content-dedup cache is a perf question, so it goes to C2-perf with a verdict (D34).
3. **F1a lands as C2-1:** the `mesh_check` module, which holds `EdgeLedger`, the closure verdicts and the signed volume. It is the first PR of the C2 stack and is written by the C2 lane. It **moves** the closure predicates that `kernel/nary_union.rs` and `csg/topology_diagnostic.rs` import today from `router/voids/prism_cut/closure_checks.rs`, a layering inversion. In the same PR, all eight production edge-pairing walks become ledger queries, so the home never sits next to its copies. Every gate keeps its own vertex key and rule; C2 changes no gate.
4. **Voids become three ordered, statically dispatched lists:** whole-host strategies, then the exact tail, then post passes. The order is today's and is **frozen**; reordering is an X PR (D33). `apply_void_context_inner` (781 lines) and `try_cut_wall_local_frame` (183) cease to exist. Dispatch is an enum `match`, with no `Box<dyn>` and no allocation per host.
5. **The `GeometryRouter` split is `RouterConfig` (pub, value type, consumed by C4) + `RouterCaches` + `RouterDiagnostics` + `ProcessorRegistry`.** `router/mod.rs` and `router/processing.rs` are split below 400 lines. The `with_*` constructor ladder stays as thin delegates, and C10 deletes it (ROUTER-40).
6. **C2 is additive at the `pub` level** (D35): `representation`, `RouterConfig`/`from_config`, and `mesh_check` behind `test-support`. Nothing is appended to `latestBreak`; a lane that finds it must remove a `pub` item defers that removal to C10.
7. **17 PRs: 11 R and 6 X.** Every R PR is byte-identical on the corpus and moves the ratchets *down*. In total C2 removes 13 of the 16 router function-length rows and 10 of the 12 router module-size rows. The six X PRs are split out explicitly (§3.5).

### 1. Target architecture

#### 1.1 `RepresentationWalk` (`rust/geometry/src/representation/`, new `pub mod`; each file < 400 lines)

```rust
// representation/mod.rs

pub struct ProductShape { pub id: u32, representations: Vec<DecodedEntity> }
/// Ok(None) iff attribute 6 is `$` or absent. Err carries today's exact message text

// representation/walk.rs
pub struct MappedLevel { pub item: u32, pub map: u32 /* IfcRepresentationMap */, pub mapped_rep: DecodedEntity }
impl MappedLevel {
    /// MappingTarget · MappingOrigin, unscaled (file units), via placement::Axis2Placement and
    /// the one CTO reader (operator.rs). Callers scale: router `scale_transform`, symbolic `unit_scale`.
    pub fn local_transform(&self, item: &DecodedEntity, d: &mut EntityDecoder) -> Result<Matrix4<f64>, PlacementError>;

#[derive(Clone, Copy)]
pub enum NestedMaps {
    Expand { max_depth: usize }, // recursion today: processing.rs:466, mapped_item.rs:80 (MAX_MAPPED_ITEM_DEPTH)
    Refuse,                      // instancing.rs:86: a nested map makes the source non-shareable
    Leaf,                        // yield the IfcMappedItem itself as an item (direct walks that delegate)
    FirstChain { max_depth: usize }, // rtc_offset/mapped_vote.rs: first mapped item per level, never branches

pub enum Flow { Continue, SkipChildren, Stop }
pub enum WalkRefusal { Dangling, Cyclic, TooDeep, NotARepresentationMap, Malformed }
pub struct WalkCtx<'a> { pub element: Option<&'a DecodedEntity>, pub shape_rep: &'a DecodedEntity, pub path: &'a [MappedLevel] }
pub trait WalkVisitor {
    fn shape_rep(&mut self, _rep: &DecodedEntity) -> Flow { Flow::Continue }
    fn item(&mut self, item: &DecodedEntity, at: &WalkCtx<'_>, d: &mut EntityDecoder) -> Flow;
    fn enter_map(&mut self, _l: &MappedLevel, _at: &WalkCtx<'_>, _d: &mut EntityDecoder) -> Flow { Flow::Continue }
    fn leave_map(&mut self, _l: &MappedLevel) {}
    fn refused(&mut self, _at: u32, _why: WalkRefusal, _ctx: &WalkCtx<'_>) {}
}
pub struct RepresentationWalk { pub select: Select, pub nested: NestedMaps }
impl RepresentationWalk {
    pub fn product<V: WalkVisitor>(&self, element: &DecodedEntity, d: &mut EntityDecoder, v: &mut V) -> Result<(), ShapeError>;
    /// Entry at an IfcRepresentationMap (type geometry, textured.rs; shared sources, instancing.rs).
    pub fn map<V: WalkVisitor>(&self, map: &DecodedEntity, d: &mut EntityDecoder, v: &mut V) -> Result<(), ShapeError>;

```

- **Shape of the walk.** It is iterative, using an explicit stack of `(MappedLevel, item cursor)`. It visits in pre-order and in list order, which is exactly the order today's recursion produces. The visited set is **path-scoped**: inserted on `enter_map` and removed on `leave_map`, as `mapped_item.rs:86-93` does today. Depth is capped by `NestedMaps::*::max_depth`, which is `ifc_lite_core::MAX_MAPPED_ITEM_DEPTH` for every geometry caller. The walk has fan-out, so the AGENTS.md bounding-walk rule calls for a cap plus a set; F3b's chain walk has fan-out 1, which is why it has no cap.
  - **No work budget in C2.** The mesh path bounds DAG re-expansion through its source cache: the visitor answers `SkipChildren` on a hit. A walker without a cache, such as C4's colour walk or C5's symbolic walk, chooses a budget in its own X PR. That is policy, recorded in §5.
- **Errors.** Structural errors (`ShapeError`) carry today's message strings. The probes call `.ok()` at the call site, so lossy behaviour stays visible policy, not a second walk. Per-item refusals go to `WalkVisitor::refused`. The router maps them to `record_unsupported_item` plus the drop log, exactly where it does today.
- **Caches.** The walk owns none.
  - Core's decoder owns the entity cache and the placement memo (F3b).
  - `RouterCaches` owns mapped-source meshes, item dedup, brep signatures, the content-signature memo, the instancing plan and materialised set, indexed-colour ids, and the material-layer index.
  - The per-host void context owns its classified cutters. In C2-perf it also owns the `OpeningGeometry` memo.
- **Mapped items and instancing.** `MappedLevel::map` (the `IfcRepresentationMap` id) is the key for the instancing source and the shared source cache. `ItemMesher` builds `InstanceMeta` from the path through one builder, `InstanceMeta::instanceable(rep_identity, local)` plus `GeometryRouter::scaled_row_major(&Matrix4)` (ROUTER-13). The don't-bake walk is `RepresentationWalk { nested: Refuse }`, so on a nested map it bails and does not cache, as today.
- **RTC frames.** `ItemFrame` is derived from `WalkCtx`:
  - `path.is_empty()` → `Direct { offset }`;
  - `process_raw_item_for_element` → `ElementRaw { offset }` (the element-frame inverse, processing.rs:787-834);
  - otherwise → `MappedSource`.

  `Direct` keeps `rtc_applied` and `publish_object_frame_bounds`. `MappedSource` moves the f64 rebase into `origin`, because `M(p − rtc) ≠ M·p − rtc` once M rotates (the B6f lesson). The rule therefore exists once, in `ItemMesher`, and no walk can skip it (ROUTER-27's class).
- **Placement.** `element_world_placement(element, strict) -> Result<(Matrix4<f64>, bool)>` (ROUTER-15), already scaled, sits on F3b's `placement::resolve_object_placement` and the router's `scale_transform`. It is the one resolver behind `apply_placement`, `apply_submesh_placement`, `resolve_scaled_placement(_strict)` and `element_frame_rtc`. The two `pub` methods keep their signatures.

- **Why one map of `(fwd, rev)` reproduces every walk.** A directed ± tally of `(a,b)` is `fwd − rev`. ### 4. Perf

**Contract per C2 PR.** The router and void path is the hottest geometry code, so R PRs must be neutral and must not chase wins:
1. `scripts/perf/instructions.sh` base vs branch: AC20-FZK-Haus (the CI `native-instructions` job) and ISSUE_129 (`--set large`, local; the 47-opening slab), plus duplex. The PR posts the per-phase table, and every phase must be ≤ base × 1.0005. There is no trading between phases (the F4/F3b contract).
2. `scripts/perf/probe.sh`, interleaved A/B, with a neutral verdict.
3. The CI perf ratchet is green, with no ceiling raised.

**Rules that keep it neutral:**
- **Static dispatch everywhere.** The `WalkVisitor` is generic (monomorphised), and the strategies are enum-dispatched.
- **No new allocation per host or per opening.** `Cutter` *replaces* `OpeningType` and is not built beside it. `ExactTail` holds today's locals. The walk's stack is a `SmallVec<[_; 4]>`.
- **`EdgeLedger` writes one map entry per undirected edge** where today's directed walks write two, so C2-1 should *lower* Ir. A gain is welcome, but no PR is reclassified to chase one.
- **No hoisting or memoising in C2,** even where it is obviously correct. That is C2-perf's work, so each win is attributable.

### 8. Risks, and the three most likely ways the plan fails

1. **Hidden side-effect reordering in the void-path decomposition (C2-7, C2-3).** The fingerprint does not see diagnostics, and the void path is mostly diagnostics plus shared mutable state:
   - `host_mutated` and `batch_consumed`;
   - bounds recomputed against the mutated host;
   - the clipper failure drain;
   - cut-effect records;
   - `HostDiagSnapshot` restores in the frame-snap retry.

   An "obviously equal" extraction can drop or duplicate a record, or read bounds one step early. *Mitigation:* evidence (g) on every voids PR; C2-7 is a mechanical extraction with no re-ordering; no logic is simplified in the same PR; the `unused_assignments` allow goes only once the borrow checker confirms it is dead.
2. **Perf erosion from abstraction on the hottest path.** Visitor indirection, an extra `Vec` per walk level, `Cutter` built beside `OpeningType`, or a missed inline across the new module boundaries could each cost a fraction of a percent, and 11 R PRs compound. *Mitigation:* the 0.05 %-per-phase contract on every PR (ISSUE_129 included, since it is where voids dominate), static dispatch only, and `#[inline]` on the per-item hot calls. Any PR over budget is fixed before merge, never offset later by C2-perf.
3. **File contention and stack churn with F3b, F2a and C4.** Several things touch the same files:
   - F3b R2a deletes the delegates `probe.rs` uses;
   - F3b X3a edits `textured.rs`;
   - #7752 and #7792 touch `router/{mod,processing,mapped_item}.rs`;
   - C4 wants the walk early.

   A 17-PR stack rebased over all of that stalls, or ships an R PR whose fingerprint was taken on a stale base. *Mitigation:*
   - hot-file ownership (D39);
   - C2-2 and C2-3 start only after F3b R1/X3a, #7752 and #7792 merge;
   - every R PR re-runs the fingerprint after its final rebase (§1.2);
   - two lanes on disjoint file sets;
   - C2-11, the broadest file move, lands last.

Other risks:
- X1 moves the 2D outputs and export goldens more than expected. Contain it: X1 is adopt-as-X with a per-drift test, and if the deltas are large it splits into X1a (depth) and X1b (selection).
- The `csg_topology_gate` feature already has 3 reds on main, so evidence (h) compares failing *sets*, not pass/fail.
- `RouterCaches` visibility is undecided until C4's note. C2 keeps it `pub(crate)` so the decision stays open.
