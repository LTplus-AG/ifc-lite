## C6 design note (coordinator b61983f5)

Work package C6 (#7783, charter #7670): one IFC data model, `ifc_lite_processing::data_model` (D2). It produces typed pset/qset/material/classification/document/relationship/spatial rows. Export's CSV/JSON/JSON-LD/IFCX/USD/BOS writers and the Python binding consume it, and so does the server's Parquet writer. The server's data_model extractors, both TS-fed generators and the per-site schema-family classifiers are deleted.

- **The planned F3b S1:** `data_model/spatial_elevation.rs` (F3b note row 16).

### TL;DR of the decisions

1. **One model, normalised.** `data_model` is a set of definition tables plus link tables, in file order, which is the shape the server already has. Export's `EntityRow` (one row per product, with psets merged and type inheritance applied) becomes a **projection** over those tables (`data_model::rows`). It is not a second model. Export's public types stay at their current paths through re-exports, so C6 adds no semver break.
2. **One typed decoder, two named encoders.** Every property, quantity and attribute value is decoded once into `DataValue`. It is rendered by exactly two encoders, and each one is a pinned external contract:
   - `render::flat` serves CSV/JSON/JSON-LD/IFCX/USD/BOS/Python (the export goldens).
   - `render::columnar` serves the server Parquet tables, the wire the viewer decodes, which must deep-equal the TS columnar parser (`apps/viewer/src/lib/lists/server-type-parity.test.ts`).
   - `fmt_num` ≡ `fmt_number` becomes one function.
   - There is no third encoder (D41).
3. **The server's decoder is canonical** for *what* is read: all property kinds (single, enumerated, list, bounded, table, reference, complex) under the #7718 per-model complex budget, keep-last ids, every relationship subtype, and materials, classifications and documents. Export today reads `IfcPropertySingleValue` only (`model_props.rs:170-179`, "P-next"). It gains the other kinds in one X PR (C6-7) **before** its decoder is deleted (reconcile-then-delete).
4. **Iteration model.**
   - Export stays **streaming**: one row per callback, the decoder cache capped at `PSET_CACHE_CAP = 1<<18` (`model.rs:151`), and a type-set memo per distinct type.
   - The server stays **materialised**, because Parquet needs whole columns. It keeps the #7718 per-model row budget, `max(16 × input, 16 MiB)`, charged before rows exist (`materials.rs:285-319`).
   - The complex-property budget is a constructor argument of the decoder, so no path can decode complex properties without it.
5. **Generated tables are replaced by core's EXPRESS registry.**
   - `generated/attr_indices.rs` (6,245 lines, IFC4_ADD2_TC1 only) is replaced by `RootSlots`, resolved by attribute **name** through `SchemaVersion::attribute_names`.
   - `generated/relationship_slots.rs` (375 lines, a union across schemas) is replaced by `RelSlots`, resolved by the `Relating*`/`Related*` names plus an aggregate flag.
   - Both generators and the attr-index-usage lint are deleted. One generator remains: EXPRESS → core.
   - F3e's typed slots supersede `data_model::slots` when they land. If F3e stalls, C6 does not wait (§4).
6. **One `SchemaFamily {Ifc2x3, Ifc4, Ifc4x3, Ifc5}` in core.** `from_label` returns `Option`, and every caller states its own default: IFC4 for re-export, fail-closed for reads by attribute name. It replaces `canon`, `step_log::attrs::schema_family`, `schema_detect::{detect_schema, attribute_schema}`, `targets_ifc2x3`, the step_map_transform allowlist, and processing's `schema_of_identifier`.
7. **Plan size:** 17 PRs, 8 R, 8 X and 1 G. The stop line is C6-0 … C6-10. After C6-4 or after C6-6, a stall leaves no third copy (§6).

#### 1.1 Home and dependency direction

`rust/processing/src/data_model/` is a new `pub mod`, and every file stays under 400 lines.

**Who depends on it.** `processing → core, geometry` is unchanged. `export → processing` already exists (`rust/export/Cargo.toml:14`), and so does `server → processing` (`apps/server/Cargo.toml:47`). #### 1.3 Iteration model and memory

| Path | Model | Memory bound |
|---|---|---|
| Export CSV/JSON/JSON-LD/IFCX/USD/BOS, Python | `rows::stream`: one uncached scan (`DataModelScan`), then one row per product callback, then type-product rows (#957 Route B, `model.rs:413-461`) | `O(links)` for the scan, plus one row, plus a decoder cache trimmed at 2^18. The type-set memo grows with the number of distinct types (`model.rs:180`). The complex listing is charged to **one** `ComplexPropertyBudget::for_input(content.len())` per model (`core/src/limits/complex_property.rs:128`). The writers that `collect` (`build_export_model`, `model.rs:48`) keep doing so. |
| Server Parquet | `extract`: the scan, then rayon-parallel table extraction (the same `rayon::join` tree as `mod.rs:140-195`), then the materialised `DataModel` | Row budget `max(16×input, 16 MiB)`, charged per row before it is built (materials only, as #7718). Complex budget as above. Over budget, `refused` makes the whole model refused, then a 400 (`parquet_data_model.rs:59-61`). |

Extending the row budget to every table is optional (C6-opt-a, X). C6 does not change which tables are charged.

### 4. Replacing the generated tables, and what happens if F3e stalls

**`RootSlots`** replaces `attr_indices.rs`.
- **Lookup.** `RootSlots::for_type(SchemaVersion::Ifc4, type_name)` finds the six names `GlobalId`, `Name`, `Description`, `ObjectType`, `Tag` and `PredefinedType` in `SchemaVersion::attribute_names` (`schema_registry.rs:58`). It is memoised per type in an `FxHashMap` owned by the extraction. Types unknown to the registry keep `UNKNOWN_TYPE_FALLBACK` (`metadata.rs:19`).
- **Proof, in the same PR and before deletion.** A test iterates all 776 rows of the generated table and asserts `RootSlots == row`. If the TS registry (IFC4_ADD2_TC1) and core's IFC4 EXPRESS edition disagree on any row, the test fails. The lane then lists the rows: an edition difference is decided by the maintainer (§10); it is never silently absorbed.
- **Not changed here:** the per-file-schema version of this (the bug half of SERVER-28) is C6-opt-b.

**`RelSlots`** replaces `relationship_slots.rs`.
- **Gate.** A type is a relationship iff `is_subtype_of(type, "IfcRelationship")` and it is not abstract.
- **Slots.** `relating` is the first attribute whose name starts with `Relating`, and `related` is the first that starts with `Related`. List-ness is read from the registry's aggregate flag.
- **Schema.** The file's schema (`SchemaVersion::from_file_schema`) comes first. If that schema does not declare the type, the lookup falls back over 4X3 → 4 → 2X3. That reproduces today's union semantics.
- **Proof, in the same PR.** A test asserts that for every one of the 54 rows, every bundled schema declaring the type agrees with the row, and that the gate set equals the 54 types plus the allowlisted `IFCRELASSOCIATES`.
- **TS side.** The parity lint's relationships pair is replaced by a committed vector, `rust/processing/tests/fixtures/relationship_slots_vectors.json`. The Rust test writes it and a TS test asserts `getRelationshipSlotPlan` against it (D5).

**What C6 needs from F3e** is the minimal contract in §5. **If F3e stalls**, C6-4 does not wait:
- `data_model::slots` is built on `SchemaVersion::attribute_names`, which exists today.
- The aggregate flag is added to core's existing EXPRESS-generated `schema_registry` by the same `@ifc-lite/codegen` generator. That is not a new generator.
- F3e later re-homes `data_model::slots` onto its typed slots in one R PR inside C6's files.
- No server-side or TS-fed table survives in either case.

### 5. The minimal contract C6 needs from F3a, F3c and F3e

**F3a (units, #7775).** C6 is not blocked: it calls today's `resolve_unit_scales` and `ProjectUnits::resolve` from one site, `data_model::units`. F3a must provide:
1. One IFCPROJECT locator that returns **all** project ids in file order, so multi-project material scales work (`material_units.rs:21-60`); the first id is the model's project.
2. A `ProjectUnits` resolve that returns length scale, plane-angle scale and per-measure units. For the data path it must keep #7752's `LengthUnit.scale` (main's value: +inf for an overflowing factor, never refused).
3. Numerical equality with `resolve_unit_scales` and `resolve_length_unit(..).scale` on the corpus, so the swap at `data_model::units` is one R PR.
4. No change to the "rows are in file units" contract.

**F3c (typed values, #7776).**
1. A typed-value representation (`AttributeValue::Typed { tag, value }` or equivalent) that a genuine 2-element string list cannot be mistaken for.
2. `as_logical() -> Option<Logical>`, with `.U.` and `.X.` both `Unknown` (the server treats `X` as unknown, `property_value.rs:252-257`).
3. Overflow reals stay `±inf` (D19), or carry raw text if F3c decides so. `DataValue::Real` renders identically either way, and any rendering change is a separate X PR (D45).
4. F3c lands its core change **additively**: the `List([String, v])` shape stays readable until the C6 sites move. Those sites are `property_value.rs:164,243`, `model_props.rs:46-53` and `appearance/{authored,page_material,tests}.rs`. **C6 lanes own those sites**; F3c does not edit them. C6-15 (PROCESSING-APP-1) lands after F3c.

**F3e (typed slots, #7780).**
1. A per-`(SchemaVersion, entity)` name → slot index lookup: ASCII-case-insensitive, amortised O(1), covering every IFC2X3/4/4X1/4X2/4X3 entity.
2. Per attribute, `aggregate: bool` (LIST/SET vs single).
3. An explicit `None` for unknown schemas and entities, so the caller picks the policy.
4. F3e adopts `data_model::slots` (§4) rather than adding a parallel lookup.

### 10. The three most likely failure modes

1. **Export becomes the complex-property amplifier again.**
   - Risk: C6-7 brings complex, table and list decoding into CSV, JSON and Python. If any export entry point builds the decoder without the per-model `ComplexPropertyBudget` and the per-id memo, the k^8 fan-out that S3 closed (82 MB in 1.7 s at k = 6) returns through a path the server tests never exercise.
   - Guard: the decoder has no budget-less constructor. Export tests read the shared vector `packages/parser/test/fixtures/complex-property-budget-7675.json`. C6-7's adversarial review runs that vector through `export_csv` and `entity_data`.
2. **A "byte-identical" move is not byte-identical.**
   - Risk: hidden order dependence breaks it:
     - the `FxHashMap::into_values` spatial node order (`spatial.rs:334`);
     - a `par_iter` changed to `par_bridge`;
     - the `BTreeSet` that orders `TYPEHASPROPERTYSETS`;
     - cached `decode_at` vs `decode_at_uncached` on duplicate ids;
     - the raw `rel_type` spelling being normalised "for free".
   - The route golden today has only 2 fixtures, so it would miss most of these.
   - Guard: C6-0 widens the oracle before anything moves. The C6-6 PRs move code verbatim, and clean-ups ride C6-5 or C6-8 with their own evidence.
3. **Registry-derived slots differ from the TS-generated tables outside the corpus.**
   - Risk:
     - an IFC4 EXPRESS edition difference (ADD2_TC1 vs core's IFC4);
     - a type present only in IFC2X3 appearing in an IFC4 file;
     - a `Relating*` naming irregularity.
   - Any of these gives a wrong `PredefinedType` or dropped relationship rows, and server ≠ browser, with no corpus file showing it.
   - Guard: the exhaustive per-row, per-schema equality tests run **inside C6-4, while the generated tables still exist**. A mismatch stops the PR for a maintainer call. It is never re-pinned.
