## F4 design note (coordinator b61983f5)

Work package F4 (#7778, charter #7670): one STEP grammar in core. This note is based on `origin/main` at `4f3197201f`, with **#7752 (S6a) treated as already merged**. F4 does not start until #7752 lands. It builds on #7752's `admit_step_real`, `parse_step_real`, `Token::UnrepresentableReal`, `EntityDecoder::{with_strict_reals, decode_by_id_lossless, refuse_record, polyloop_refusal}` and changes none of them.

Findings closed: CORE-1, CORE-6, CORE-8, CORE-9, CORE-10, CORE-16, CORE-28, CORE-30, CORE-32, CORE-35, EXPORT-STEP-15, PROCESSING-15, PROC-AL-14.

### TL;DR of the decisions

1. **No new grammar module.** Core already has the right homes: `parser::lexical` (trivia and framing), `step_encoding` (the string-literal end rule and decoding), `parser::numeric_literal` (numbers) and `parser::scanner_attributes` (`StepListItems`). F4 adds exactly **one** file, `parser/record.rs` (`StepRecord`). Everything else is a deletion or a re-route.
2. **One grammar option, not a matrix.** `Strictness::{Tolerant, Strict}` on `split_top_level_args`:
   - **Strict** is for STEP *writers*: the list must close, and every slot must be one well-formed value.
   - **Tolerant** is for everything else.

   Real admission (strict vs lossless reals) stays a **decoder** option (#7752), not a grammar option. The grammar always yields the typed overflow token.
3. **The tokenizer stays nom for structure.** Its number branch becomes a hand-written combinator over `step_numeric_literal_len`, `fast_float2` and `admit_step_real`. `lexical-core` is dropped, so `fast-float2` is the one float parser in core.
4. **Canonical numeric grammar:** the existing `step_numeric_literal_len`, which is the twin of TS `isCompleteStepNumericLiteral`.
   - Accepted: `.5`, `1E5`, `+1`, `1.` and `-0.`.
   - REAL vs INTEGER: a literal is REAL iff it has a `.` or an exponent.
   - Overflow follows D13 (see the numbers row in §3).
5. **Binary literals are a token of their own.** The tokenizer gets `Token::Binary` and the decoder gets `AttributeValue::Binary(String)`, which holds the raw hex with no decoding. Byte decoding has one home, `step_encoding::decode_step_binary`, and a non-zero unused-bits indicator is refused.
6. **Strict slot validation reuses the tokenizer's value grammar** (`parser::is_step_value(slot)` = nom `token` consumes the whole slot). A second value grammar is not written.
7. **Perf contract:** no phase of the native instruction ratchet may get worse than base + 0.05%. "Phase" means `entity-scan`, `lookup`, `preprocess`, `geometry` and `total`, measured on FZK-Haus (CI) and ISSUE_129 (local). Every PR that touches a hot path posts a callgrind table.

#### 1.2 Record and token types

```rust
/// `#id = KEYWORD ( ... ) ;`: the head is read with core trivia; the
/// argument list is read lazily. Head-only and O(head): cheap enough for
/// per-record keyword reads.
pub struct StepRecord<'a> { pub id: u32, pub keyword: &'a str, bytes: &'a [u8], args: usize }
impl<'a> StepRecord<'a> {
    pub fn parse(record: &'a [u8]) -> Option<Self>;  // None: complex `=(` instance, no `(`, non-UTF-8 keyword, unterminated head comment
    pub fn attrs(&self) -> StepListItems<'a>;
    pub fn attr(&self, i: usize) -> Option<&'a [u8]>;
    pub fn is_present(&self, i: usize) -> bool;       // replaces nth_attribute_is_present's body
    pub fn ref_at(&self, i: usize) -> Option<u32>;    // attribute i is exactly one `#n`
    pub fn first_ref_at(&self, i: usize) -> Option<u32>; // `#n`, or the first item of a ref list (the face/shell readers)
    pub fn ref_list_at(&self, i: usize, out: &mut Vec<u32>) -> Option<()>; // EVERY item one ref, else None (D3)
    pub fn real_at(&self, i: usize) -> Option<f64>;   // parse_step_real; overflow -> None
    pub fn point_at(&self, i: usize) -> Option<(f64, f64, f64)>; // today's parse_point_coordinates
    pub fn string_at(&self, i: usize) -> Option<Cow<'a, str>>;   // decode_step_literal; `$`/`*` -> None
    pub fn enum_at(&self, i: usize) -> Option<&'a [u8]>;          // `.T.` -> b"T"
}
pub enum Strictness { Tolerant, Strict }
```

- `Token` gains `Binary`. `UnrepresentableReal` comes from #7752.
- `AttributeValue` gains `Binary`.
- No `RefPolicy` enum. There is one rule: `ref_list_at` refuses a list with any non-ref item, oversized id or nested value. Geometry is the only caller (shells, faces, bounds and loops), and that is D3. A consumer that wants skip-on-bad iterates `attrs()` and calls `parse_ref` per item.

#### 1.4 Zero-copy constraints

- Every grammar function returns slices of its input.
- Allocation happens only where the caller asks for it:
  - `split_top_level_args` makes one `Vec<&[u8]>`;
  - `ref_list_at` writes into the caller's buffer;
  - `decode_step_literal` and `string_at` return `Cow`, borrowed unless the literal contains `''` or `\`.
- No `Vec<char>`, no ASCII projection, and no `String` per slot anywhere (EXPORT-STEP-15).
- `Token` stays borrowed. `Binary` and `UnrepresentableReal` carry `&'a [u8]`.

#### 1.5 Hot-path performance contract and how it is proven

The parse phases (`entity-scan`, `lookup`, `preprocess`) and the fast geometry accessors are the hottest code in the product.

**Rules:**
- the scanner keeps its `memchr` and cached-slash walk unchanged; only its two quote loops are folded into `literal_end_framed`, which is `#[inline]`;
- `step_numeric_literal_len` stays a forward scan with no allocation;
- the tokenizer's number branch does a single pass, where today it runs nom `recognize` and then `lexical_core` over the same bytes. This is expected to *lower* lookup Ir;
- `StepListItems` gets the byte-class jump before any polyloop or face-bound accessor moves onto it;
- `get_polyloop_coords_cached_into` keeps its point-cache policy and counters.

**Proof, per PR that touches core or a fast accessor:**
1. `scripts/perf/instructions.sh` (callgrind, `perf_probe --single-thread`, phase markers), base vs branch:
   - on `AC20-FZK-Haus` (the CI `native-instructions` family);
   - on `ISSUE_129` (the `native-instructions-large` family, run locally);
   - on one BREP-heavy fixture (Holter when the host has it, otherwise `duplex`).

   The PR body posts the per-phase table. The gate is every phase ≤ base × 1.0005, which is the ratchet's own tolerance.
2. `scripts/perf/probe.sh` interleaved wall-clock A/B, with a neutral verdict (PLAN §1.2 R(f)).
3. The CI perf-ratchet check is green.

A regression in any phase blocks the PR. There is no "net neutral" trade between phases.

### 4. G7: fuzz target design

**Tooling: cargo-fuzz, not proptest.**
- It is coverage-guided over raw bytes, which is exactly the threat model.
- The infrastructure already exists: `rust/core/fuzz` (standalone workspace), `fuzz.yml`, and the stable corpus-replay pattern of `rust/{geometry,landxml}/tests/fuzz_regressions.rs`.
- proptest would add a core dev-dependency for no extra power.

**Targets** (all in `rust/core/fuzz/fuzz_targets/`):

1. **`grammar_differential`** (the G7 target). Input bytes are used as-is and also wrapped as `#1=IFCX(<data>);`.
   - **Totality:** none of these may panic or hang:
     - `parse_entity`;
     - `StepRecord::parse` and every accessor;
     - `StepListItems`, `split_top_level_args` (both strictness levels) and `is_step_value`;
     - `parse_step_numeric`, `parse_step_real` and `read_step_number`;
     - `decode_step_literal` and `decode_step_binary`;
     - `close_step_record`;
     - `header::declared_schemas`.
   - **Agreement:** whenever `parse_entity` accepts the record, `StepListItems` yields `tokens.len()` items, and each item `i` agrees with its token as follows:

     | Token `i` | Must hold for item `i` |
     |---|---|
     | `Float` / `Integer` | `read_step_number(item)` gives the same variant and bit-identical value, spanning the whole item |
     | `UnrepresentableReal` | `parse_step_numeric(item)` is `None` |
     | `EntityRef(n)` | `parse_ref(item) == Some(n)` |
     | `String` | `decode_step_literal(item)` equals `from_token`'s string |
     | `Binary` | `item` is the same raw bytes |
     | `Null` | the item is `$` |
     | `Derived` | the item is `*` |
     | `List` | `StepListItems::of_list` recurses with the same rules |

     Also: `is_step_value(item)` holds for every item, and `split_top_level_args(.., Strict)` is `Some`.
   - **Fast vs decoded:** the input is fed as a one-record file to an `EntityDecoder`. When `decode_by_id` succeeds:
     - `get_cartesian_point_fast` must equal the decoded coordinates (both `None`, or bit-equal);
     - `get_polyloop_point_ids_fast` and `get_entity_ref_list_fast` must equal the decoded ref list, or be `None`.
2. **`scan_file`** (CORE-30): `EntityScanner` plus `build_entity_index`, then decode every span. It must be total, and every span must lie inside the input.
3. **`decode_string`** (CORE-28): `decode_ifc_string` and `decode_step_literal` must be total, with libFuzzer's `-timeout` catching any return of the quadratic path.

**Shared oracle without a copy.** The assertion functions live once in `rust/core/tests/support/grammar_oracle.rs`. The fuzz targets include them with `#[path = "../../tests/support/grammar_oracle.rs"] mod oracle;`, so there is no byte-for-byte mirror and no `pub` API.

**Seeds** (committed, synthetic, under ~100 KB):
- every input string from `rust/core/tests/fixtures/{step_numeric_vectors,step-page-directive,step-stray-apostrophe,ifc_string_vectors,type_paren_trivia_vectors}.json` and `rust/export/tests/fixtures/step_refuse_vectors.json`;
- the finding repros:
  - `#7=IFCCARTESIANPOINT((.5,0.,0.));`
  - `#5=IFCCARTESIANPOINT(/* (9.) */(1.,2.,3.));`
  - `#1=IFCWALL/* x */(…);`
  - `"0FF"`
  - `DATA ;`
  - 1 MB of `\X2\`.

A local-only script, `rust/core/fuzz/seed-from-models.sh`, extracts up to 8 distinct-shape records per keyword (≤ 4 KiB each) from the named corpus (AC20-FZK-Haus, ISSUE_129, duplex, IfcOpenHouse_IFC4, the two annex_e texture files, `issues/856_wall_decode_failed.ifc`) into an **uncommitted** corpus directory. Fixtures are not in git and their licences vary, so the committed seeds stay synthetic.

**CI vs local:**
- **Required (per PR):** `rust/core/tests/fuzz_regressions.rs` replays the committed corpus on stable through the same oracle, in the existing `rust-tests` lane.
  - G-class evidence: it fails at main for the `.5` seed (tokenizer vs `parse_step_numeric`, CORE-6) and for the comment-point seed (fast vs decoded, CORE-1), and passes after F4-1 and F4-3 respectively.
  - G7 lands right after F4-1 with the numeric/string oracle. F4-3 adds the fast-accessor half together with its seed.
- **Scheduled (weekly) and `workflow_dispatch`, non-blocking:** `fuzz.yml` matrix gains `grammar_differential`, `scan_file` and `decode_string` (`-max_total_time=60`).
- **Local, before merging any F4 core PR:** `cargo fuzz run grammar_differential -- -max_total_time=600` on the seed and model corpus; the PR body quotes the exec count.

### Needs the maintainer's decision

1. **`AttributeValue::Binary` vs keeping binary as `String`.** Recommendation: `Binary`. This fixes CORE-32 and the STEP writer re-emitting a binary as `'…'`. The cost is a core major (inside #11) and `get_string()` returning `None` on `IfcBlobTexture.RasterCode` and `IfcPixelTexture.Pixel`.
2. **The D13 data-path representation.** #7752 maps the overflow token to `AttributeValue::Float(±inf)` for lossless decoders. Export `step_log` keeps the raw text. F4 keeps both as they are. If D13's "keeps the raw text" is meant to cover `AttributeValue` too, that is a typed variant and belongs to F3c, not F4.
3. **A non-zero unused-bits indicator in binary textures:** refuse and count (recommended, D3), or implement bit-shifted decoding.
4. **Whether the TS-only drifts join F4 or go to a follow-up issue.** These are `parseStepValue` returning `Infinity`, `readRefList` reading refs out of comments, `parseStepList`, and the viewer splitter. Recommendation: a follow-up issue.
