# Prospective O-S1 input and retained-scene correctness diagnostic

This is a new, opt-in **correctness diagnostic**, not a performance cohort.
`benchmark.yml`'s `independent_input=true` route performs exactly two fresh,
first-file canonical viewer UI loads of the existing public O-S1 fixture.
BASE is `7dfc29870b0aa6a593c163592fcb84a92e5dfa19`; CAND is
`9fc86cb8ead77486b0bcd29726b775c27085524b`, #6780's final source.
No paired-ref inputs, replacement fixtures, retries, renderer options or
production subject changes are admitted. The original four-family comparator,
legacy collector and historical c619/2feb refusals remain unchanged.

The source/build producer checks the new 28-path contract, complete tracked
source manifests, actual subject heads and clean checkouts. All canonical
delivery/decoder/preparation/Scene/placement paths retain their respective
historical audited bytes; the lockfile changed since that audit and is pinned
for this pair. The actual installed browser ESM Zustand vanilla implementation
is also pinned (5.0.15; synchronous state commit/listener delivery), not inferred
from a CJS test dependency alone. Both final consumer graphs receive frozen installs, fresh root
typecheck including test-source audits, and forced viewer builds with their
own source-built WASM. Historical runtime/bundles are not reused. The actual
renderer entry is `packages/renderer/src/index.ts`; the preliminary external
screen's nonexistent `renderer.ts` row is superseded by this valid pin.

The complete viewer assets, default served WASM hash/path, every tracked
harness input (including witness function sources and the source contract),
Chrome executable/hash/version/backend, fixed graphics profile, exact public
fixture and cleanup receipts are frozen before the controls. Subject and
harness files, served assets and fixture are rechecked before/after each UI
load and in final cleanup. Unknown or changed source contracts refuse.

After ordinary app setup and the existing passive readiness observer, but
**before** `ViewerBenchmarkPage.loadFile`, the same witness is installed in
both arms. It discovers the committed current canvas/renderer without waiting
for renderer initialization, requesting a frame or invoking a second loader.
The actual file input still calls `useIfcLoader.loadFile(file, primary)`.

The synchronous store subscription observes pending original IFNS buffers
before React's canonical drain. The native Scene wrapper retains actual
decoded argument references and preserves receiver, arguments, return and
exceptions, including after observer refusal. It does not hash or clone
geometry on the hot path. Fixed caps are 10,000 deliveries/calls and 256 MiB
of retained original-buffer references. Retention prolongs these buffers'
lifetimes; both-arm instrumentation overhead is **unmeasured**. This does not
support normal timing or physical-memory benefit claims.

After unchanged metadata/geometry producer milestones, settled store/Scene,
allocated canvas and a positive fresh CPU-frame witness, measured milestones
are frozen. No GPU-completion or pixel identity is inferred. The posttimer
capture retains the original complete produced-output digest formula, including
hidden produced flat meshes. It derives expected retained flat-piece bags from
the actual current viewport input and expected instance bags from observed
canonical decoded ingress, never from the retained Scene it verifies.
Merged contributors, duplicate pieces and occurrences retain multiplicity.
The sole expected-input placement oracle is the audited zero-primary-placement
contract; retained output bytes are never normalized through that oracle.
Raw IFNS hashes/metadata are auxiliary provenance. Complete decoded logical
instance identities are partition independent; no unknown wire field is scrubbed.

Model IDs and Scene/device objects authorize association and freshness only;
cross-arm identity uses verified single-primary deterministic channels. The
capture requires actual metadata/property access, a complete model, no load
error/pending shards/finalization/queues/fragments, retained CPU data and a stable
final store/current-props/Scene/device revision. The existing diagnostics also
retain legacy lifecycle fields (including stale opening/idle/interactiveReady
values); this observer does not rewrite them or claim those flags are correct.

Unknown mesh/wire/visibility shape, authored text, UV/texture, point clouds,
transparent/empty/malformed instance admission, topology splitting, placement,
state mutation, missing delivery and all work/memory bounds remain refusals.
Successful input equality requires **both** complete produced output and actual
viewport/decoded-input equality, plus unchanged independent readiness/resource/
runtime/error/asset/source/cleanup gates. Failure remains terminal. Allocation
evidence is persisted before appearance capture, so a full-identity refusal
does not erase the narrower source-preparation copy observation.

Before browser teardown the existing screenshot and scalar snapshot are
retained, late load/GPU faults are checked, and owned wrappers/subscription are
disposed. A failed disposal refuses admission. Original file-size copy, possible
late admitted cache copies, instrumented duration and sampled own RSS remain
distinct observations; sampled RSS is not a physical peak.

### Prospective v3 canonical empty-delivery accounting

`independent-viewer-input-v3-empty-accounting-instrumented` preserves v2 and
run 37183505460 as their original refusals. That run did not export the failing
packet, so this correction does not retrospectively identify or accept it.
The pinned partitioned routing helper always calls the canonical encoder; an
empty collated input produces a **32-byte v1 IFNS envelope**, with zero template,
occurrence and pool counts and reserved word zero. The canonical worker forwards
that nonzero-length packet, and the actual streaming effect decodes and invokes
Scene once per pending entry. Empty Scene preparation creates no output templates.

The observer supports only that exact envelope and exact empty decoded shape.
Every original delivery and accepted native call remains recorded once. Empty
calls have **no template-buffer pointer**: correspondence is explicitly the
source-audited no-output delivery/native-call multiplicity within the current
primary model and renderer/device, not an invented individual pointer association.
Nonempty pointer linkage, complete logical decoded bags, independent retained flat
pieces/instances and original produced digest stay mandatory. Each empty native
call must preserve its return and retained census; mutation, dropped/extra calls,
unknown tails/versions, unreferenced templates or corrupt packets remain refusals.
Raw shard/no-output provenance is retained separately from partition-independent
logical geometry identity.

A bounded post-timer diagnostic now records the first four and first undrained
raw delivery's admitted/current length, header, class and full SHA256 (up to a
fixed 64 MiB cumulative diagnostic bound), even after sticky refusal. Cap/hash
failures are explicit. Diagnostic records cannot grant eligibility or identify a
specific failed native call without its actual source linkage. No original GPU
receivers, return values, exceptions, shader/launch flags or model options change.

Local qualification uses the unchanged source-built WASM after exact artifact,
1,413 Rust/toolchain/build-input equality and freshness fences. The existing
partitioned API with **zero model bytes and zero jobs** produced the actual empty
packet, SHA256 `b4f6ca3b3509b77a9adc79a49a5f478b1f9449db87660d7f414d00f4119e7a07`.
No Rust API, source or production behavior was changed. Real decoder/preparation/
Scene and the mounted canonical delayed-init effect cover empty/nonempty mixing.
GPU byte/bind-group adapters and seeded metadata remain explicitly limited;
these controls are not a real model load, GPU frame or full-property proof.

The initial selection had **50 controls: 49 pass, one assertion failure, zero
skips**. That assertion incorrectly assumed a nonempty template allocated three
GPU buffers (actual four). The approved test-only correction asserts actual live
count and allocation-list equality before/after each empty ingestion instead.
The affected canonical file then passed **13 controls, zero skips**; the other
37 unchanged controls retain their original passes. Original failure and source

Actual canonical metadata/geometry producer milestones, settled scene/queues,
current ownership, fresh CPU-frame and fatal-error/resource/source/cleanup gates
remain unchanged. The earlier raw optional lifecycle values `opening`, `idle` and
`interactiveReady=false` remain recorded; source review found they are initialized
